Les environnements d’analyse traditionnels répartissent les données entre des comptes de stockage, des bases de données et des systèmes de fichiers distincts. ## Comprendre OneLake
Effectué
100 XP
5 minutes
OneLake est la base de la plateforme d’analytique de Microsoft Fabric. Il fournit une couche de stockage unique et unifiée où toutes vos données se trouvent. Comprendre OneLake est essentiel, car il modifie la façon dont vous pensez au stockage des données. Au lieu de copier des données entre des systèmes ou de gérer plusieurs comptes de stockage, vous travaillez avec un emplacement centralisé partagé entre toutes les charges de travail Fabric.

OneLake couvre l’ensemble du tenant
OneLake est un lac de données destiné à l’ensemble des locataires intégré à chaque environnement Fabric. Lorsque votre organisation active Fabric, OneLake est automatiquement disponible. Aucune installation ou configuration séparée n’est requise.

Avec OneLake, vous obtenez une seule copie de vos données. Toutes les charges de travail Fabric lisent et écrivent dans le même emplacement de stockage. Cette approche élimine le problème traditionnel des silos de données où chaque équipe ou outil conserve sa propre copie.

Les environnements d’analytique traditionnels créent souvent des copies de données pour différentes équipes ou charges de travail. Avec OneLake, toutes les charges de travail lisent depuis les mêmes fichiers sous-jacents. Lorsque les données changent, tout le monde voit immédiatement la version mise à jour. Cette source unique de vérité réduit les incohérences de données et les coûts de stockage.

Découvrir des données avec le catalogue OneLake
Le catalogue OneLake vous permet de découvrir et de parcourir les ressources de données dans l'ensemble de votre tenant Fabric. Considérez-le comme un inventaire pouvant faire l’objet d’une recherche de toutes les données dans OneLake.

Vous pouvez rechercher des ressources par nom, parcourir par espace de travail ou domaine, et afficher les métadonnées telles que les descriptions, les propriétaires et la traçabilité. Le catalogue permet de trouver des données pertinentes même si vous ne savez pas exactement où elles sont stockées.

Le catalogue fournit également des fonctionnalités de gouvernance et de sécurité. OneLake s’intègre à Microsoft Purview pour la gouvernance des données. Vous pouvez classifier des données, appliquer des étiquettes de confidentialité et suivre la traçabilité des données. Les contrôles d’accès déterminent qui peut lire ou modifier des données, en fournissant des contrôles de niveau entreprise pour protéger vos données.

Types de données dans OneLake
OneLake stocke les données dans des formats ouverts, ce qui signifie que vos données ne sont pas verrouillées dans un format propriétaire. OneLake utilise Delta Lake comme format de table par défaut, qui stocke les données dans les fichiers Parquet ouverts. Tout outil qui comprend Delta Lake ou Parquet peut y accéder, ce qui vous offre une flexibilité quant à l’utilisation de vos données. Les fichiers dans OneLake peuvent être n’importe quel format.

Les données dans OneLake peuvent inclure :

Tables hébergées dans des lakehouses, des entrepôts de données ou des eventhouses
Fichiers dans différents formats (Parquet, CSV, JSON, etc.)
Raccourcis qui référencent les données sans les copier physiquement
Modèles sémantiques pour l’analytique Power BI
Les raccourcis vous permettent de référencer des données dans des emplacements externes tels qu’Azure Data Lake Storage, Amazon S3 ou un autre emplacement OneLake. Les données demeurent à leur emplacement d’origine, tout en étant exploitables comme si elles appartenaient à votre lakehouse. Les raccourcis sont utiles lorsqu’une autre équipe gère les données sources ou lorsque les stratégies de gouvernance nécessitent que les données restent dans un emplacement spécifique.

Comment les données arrivent dans OneLake
Les données peuvent arriver dans OneLake via plusieurs méthodes d’ingestion :

Mise en miroir : réplique en continu des données à partir de bases de données externes telles que SQL Server, Azure SQL Database, Azure Cosmos DB ou Snowflake. Lorsque les données sources changent, OneLake reflète automatiquement ces modifications.
Pipelines : Orchestrer le déplacement et la transformation des données à l’aide des fonctionnalités de Data Factory. Ils copient des données de différentes sources, appliquent des transformations et les chargent dans OneLake.
Dataflows : Utilisez Power Query pour vous connecter à des sources, transformer des données et les charger dans OneLake. Ils sont familiers avec Excel et les utilisateurs Power BI qui ont travaillé avec Power Query.
Streaming : gère les données en temps réel via des flux d’événements. Les flux de données proviennent en continu de sources telles que les appareils IoT, les journaux d’application ou les événements clickstream.
Chargement direct : chargez des fichiers directement dans le stockage OneLake via l’interface Fabric.
Comment OneLake prend en charge votre flux de travail IA
OneLake joue un rôle fondamental dans l’activation de l’IA dans Fabric. Pour fournir des insights pertinents, les agents Copilot et Fabric IQ doivent rechercher et comprendre vos données.

Lorsque vous demandez à Copilot une question telle que « Quelles étaient les tendances des ventes du trimestre dernier ? », elle recherche le catalogue OneLake pour localiser les données pertinentes. Le même catalogue que vous utilisez pour parcourir et découvrir des ressources alimente l’assistance basée sur l’IA.

Lorsque les données sont dispersées ou mal documentées, même l’IA rencontre des difficultés pour le trouver. Copilot peut retourner des résultats plus précis aux consommateurs lorsque vos données ont des noms clairs, des descriptions et des métadonnées. Les assistants IA peuvent vous aider plus efficacement lorsque les données sont détectables et bien cataloguées.


## Parcourir et se connecter aux données dans OneLake
https://learn.microsoft.com/fr-fr/training/modules/discover-data-onelake/3-browse-connect-onelake 
Effectué
100 XP
5 minutes
Imaginez que vous travaillez dans une organisation de vente au détail où les données résident sur plusieurs espaces de travail. L’équipe d’ingénierie des données administre les données nettoyées dans son lakehouse, d’autres services exploitent des entrepôts contenant des mesures métier, tandis que les analystes ont élaboré des modèles sémantiques. Vous devez rechercher et vous connecter à ces données pour transformer des tables pour l’analyse, créer des modèles sémantiques ou créer des rapports.

Le catalogue OneLake vous aide à trouver des éléments de données au sein de votre organisation. Une fois que vous avez trouvé les données dont vous avez besoin, connectez-vous à celle-ci pour créer vos solutions analytiques.

Rechercher des données dans le catalogue OneLake
Le catalogue OneLake est une expérience de découverte centralisée pour tous les éléments de données de votre locataire Microsoft Fabric. Vous pouvez rechercher des éléments par nom ou par étiquette, ce qui facilite la localisation d’éléments spécifiques même dans les grandes organisations.

Capture d’écran du catalogue OneLake avec les différentes catégories pour découvrir les éléments.

Le catalogue respecte les autorisations d’accès, ce qui sécurise les données sensibles tout en activant la découverte des ressources disponibles. Cette visibilité basée sur les autorisations signifie que différents membres de l’équipe voient différents catalogues en fonction de leurs rôles.

Le catalogue OneLake affiche les métadonnées de chaque élément pour vous aider à comprendre ce que contient l’élément et s’il est approuvé pour une utilisation en production avant de commencer à l’utiliser. Les champs de métadonnées sont les suivants :

Nom, type, propriétaire
Dernière heure d’actualisation
Emplacement de l’espace de travail
Libellés de sensibilité
État de l’approbation (certifié/promu)
Votre organisation définit des étiquettes de confidentialité pour garantir une gouvernance appropriée sur les données. Ces étiquettes vous aident à identifier des données hautement sensibles et à prendre des décisions éclairées lors de l’octroi de l’accès.

L’approbation aide d’autres utilisateurs à trouver du contenu approuvé. Il existe trois niveaux d’approbation :

Promu : l’élément est prêt pour le partage. Tout utilisateur disposant d’autorisations d’écriture peut promouvoir un élément.
Certifié : L’élément répond aux normes de qualité de votre organisation. Seuls les réviseurs autorisés peuvent certifier des éléments.
Données de référence : l’élément est une source de vérité faisant autorité pour les données organisationnelles principales, telles que les listes de clients ou les codes de produit. Seuls les réviseurs autorisés peuvent appliquer cette étiquette.
Tous les éléments Fabric et Power BI, à l’exception des tableaux de bord, peuvent être promus ou certifiés. L’étiquette de données maîtres s’applique uniquement aux éléments de données, tels que les lakehouses et les modèles sémantiques.

En utilisant le catalogue pour découvrir les données existantes, vous réduisez la duplication et la confusion tout en encourageant la collaboration au sein de votre organisation.

Se connecter aux données
Une fois les tables de lakehouse ou d’entrepôt de données identifiées dans le catalogue, vous pouvez établir une connexion avec votre espace de travail afin de transformer et de préparer les données en vue de leur analyse.

Les raccourcis vous permettent de référencer des données à partir d’autres espaces de travail sans les copier ou les déplacer. Les modifications apportées dans la source sont immédiatement visibles via le raccourci. Cette approche élimine la duplication des données tout en vous permettant d’ajouter une logique métier et des transformations.

Les raccourcis prennent également en charge la collaboration entre espaces de travail. Par exemple, une équipe d'ingénieurs en données peut gérer des tables de transactions nettoyées dans leur entrepôt de données. Vous pouvez créer un raccourci vers ces tables à partir de votre lac de données analytique, puis les transformer en jeux de données prêts à l’emploi pour l'entreprise avec des colonnes calculées, des agrégations et des modèles dimensionnels. L’utilisation de raccourcis pour la séparation prend également en charge l’architecture en médaillon, permettant de structurer les données en différentes couches : brutes, enrichies et préparées.

 Conseil

Avant de créer un raccourci, vérifiez les données à l’aide du point de terminaison d’analytique SQL. Chaque lakehouse inclut un point de terminaison d’analytique SQL qui fournit un accès T-SQL en lecture seule aux tables. Vous pouvez interroger le point de terminaison pour afficher un aperçu des données, vérifier le schéma et vérifier qu’il contient ce dont vous avez besoin. Le point de terminaison utilise une syntaxe T-SQL familière de SQL Server ou d’Azure SQL Database.

Copilot peut vous aider à écrire des requêtes T-SQL lorsque vous travaillez avec le point de terminaison d’analytique SQL. Cette intégration IA est la façon dont les agents et Copilot interrogent les données Lakehouse, selon les mêmes modèles que ceux utilisés pour explorer et transformer les données.

Pour créer un raccourci dans votre lakehouse :

Ouvrez votre lakehouse dans l’espace de travail Fabric.
Sélectionnez Nouveau raccourci dans la barre d’outils.
Choisissez OneLake comme source de raccourci.
Parcourez l’espace de travail ainsi que le lakehouse contenant les données que vous souhaitez consulter.
Sélectionnez les tables ou dossiers à inclure dans le raccourci.
Confirmez la création du raccourci.
Le raccourci s’affiche dans votre lakehouse et peut être interrogé comme toute autre table. Vous pouvez exploiter ce raccourci au moyen de carnets de notes, de requêtes SQL ou de flux de données afin de créer des tables de faits et de dimensions, d’ajouter des colonnes calculées ou d’agréger des données à des fins analytiques.

Capture d’écran illustrant la boîte de dialogue de création de raccourci dans Microsoft Fabric, avec les options de sélection de l’espace de travail et du lakehouse.

Les raccourcis peuvent ne pas convenir à vos besoins lorsque vous avez besoin d’un instantané stable des données à un point spécifique dans le temps, lorsque la latence du réseau a un impact sur les performances des requêtes ou lorsque la conformité nécessite des copies physiquement distinctes.

Utiliser des modèles sémantiques
Lorsque vous trouvez des modèles sémantiques dans le catalogue, vous pouvez les explorer et les connecter à des fins de création de rapports. Les modèles sémantiques contiennent des relations prédéfinies, des calculs et des métriques métier qui facilitent la création de rapports.

Pour déterminer si un modèle sémantique répond à vos besoins, sélectionnez-le dans le catalogue OneLake, puis sélectionnez Ouvrir. La page des détails du modèle sémantique s’ouvre, affichant :

Onglet Vue d’ensemble : affiche la description, le propriétaire, l’état d’actualisation, l’approbation et les étiquettes de confidentialité
Section Tables : affiche le schéma de table et de colonne sous-jacent. Vous pouvez sélectionner l’icône binoculaire en regard de n’importe quelle table ou colonne pour explorer des exemples de données
Onglet Lignage : Visualise les dépendances en amont et en aval
Onglet Moniteur : affiche l’historique et l’activité d’actualisation
Capture d’écran montrant la page détails d’un modèle sémantique dans le catalogue OneLake avec l’onglet Vue d’ensemble, la section Tables et le bouton Ouvrir.

Une fois que vous avez confirmé que le modèle sémantique contient les données dont vous avez besoin, vous pouvez créer du contenu à partir de celui-ci à l’aide du bouton de liste déroulante Explorer ces données , qui offre plusieurs options :

Explorer ces données : ouvre un outil léger pour l’analyse ad hoc rapide avec des visualisations de matrice
Création automatique d’un rapport : génère automatiquement un rapport de synthèse avec des insights et visualisations clés
Créer un rapport vide : ouvre le canevas d’édition de rapport pour créer un rapport personnalisé
Créer à partir d’un modèle : utilise un modèle de rapport existant comme point de départ (le cas échéant)
Créer un rapport paginé : crée un rapport mis en forme adapté à l’impression ou à l’exportation
Vous pouvez également sélectionner Analyser dans Excel pour créer une connexion de tableau croisé dynamique, ce qui vous permet d’analyser le modèle sémantique à l’aide de l’interface familière d’Excel.

## Découvrir les données de diffusion en continu dans Real-Time hub
https://learn.microsoft.com/fr-fr/training/modules/discover-data-onelake/4-discover-streaming-data 
Effectué
100 XP
4 minutes
Dans la section précédente, vous avez appris à rechercher et à établir une connexion avec les données par lots stockées dans des lakehouses et des entrepôts de données. Toutefois, les données n’arrivent pas toujours par lots , parfois elles circulent en continu. Les niveaux d’inventaire changent à mesure que les produits vendent, les transactions sont transmises par les clients en ligne et les capteurs IoT envoient des lectures de température toutes les quelques secondes.

Avant de pouvoir incorporer des données de diffusion en continu dans votre solution, vous devez trouver les données appropriées à l’aide du hub Real-Time.

Découvrir les données de diffusion en continu
Le hubReal-Time est le catalogue centralisé permettant de découvrir et de gérer les données de streaming dans Microsoft Fabric. Alors que le catalogue OneLake présente les données par lots stockées dans les lakehouses et les entrepôts, le hub en temps réel affiche les flux d’événements ainsi que les tables KQL actives au sein de votre organisation.

Les flux d’événements sont des flux continus de données provenant de sources telles qu’Azure Event Hubs, des appareils IoT, Apache Kafka, la capture de données modifiées de base de données (CDC) ou des applications personnalisées. Chaque flux transporte des événements au fur et à mesure qu’ils se produisent, tels qu’un client effectuant un achat ou un capteur détectant un changement de température.

Les données de streaming circulent souvent dans des entrepôts d’événements, qui sont des conteneurs qui contiennent une ou plusieurs bases de données KQL. Ces bases de données stockent les événements basés sur le temps ou les événements et prennent en charge les requêtes rapides à l’aide du langage de requête Kusto (KQL). Les données sont automatiquement indexées et partitionnés par temps d’ingestion, ce qui permet une analyse rapide même pendant l’ingestion continue des données.

Tout comme vous parcourez le catalogue OneLake pour rechercher des lakehouses, vous parcourez le hub Real-Time pour découvrir les sources de données de streaming que d’autres équipes ont déjà créées. Cette étape de découverte vous aide à déterminer si les flux existants répondent à vos besoins. Si un flux capture déjà les données souhaitées, vous pouvez l’utiliser directement plutôt que de créer des pipelines de données en double.

Explorer les données de streaming
Pour accéder à Real-Time hub, sélectionnez Temps réel dans la navigation de gauche dans Fabric. Le hub s’ouvre sur la page de données de streaming , qui affiche les flux d’événements récemment créés et les tables KQL auxquelles vous avez accès.

Vous pouvez parcourir les flux par espace de travail, filtrer par type de source ou rechercher des noms de flux spécifiques. Lorsque vous sélectionnez un flux, vous voyez ses détails, notamment :

Nom de flux et élément source (eventstream ou base de données KQL)
Localisation du propriétaire de l'élément et de l'espace de travail
État de l’approbation
Libellés de sensibilité
Capture d’écran montrant la page principale du hub Real-Time avec des données de streaming et des options permettant d’ajouter de nouvelles sources de données.

Les détails du flux affichent également les informations d’activité. Vous pouvez vérifier si un flux reçoit activement des données et quand il a été mis à jour pour la dernière fois. Ces informations vous permettent d’évaluer si un flux est fiable pour une utilisation en production.

 Conseil

Avant d’utiliser un flux de données, passez en revue son schéma et ses exemples de données pour vérifier qu’il contient les champs dont vous avez besoin pour votre travail analytique.

Utiliser des flux découverts
Une fois que vous avez découvert un flux contenant des données utiles, vous avez plusieurs options selon qu’il s’agit d’un flux d’événements ou d’une table KQL :

Pour les flux d’événements :

Afficher les propriétés et le profil de données du flux
Définir des alertes à l’aide de Fabric Activateor pour déclencher des actions lorsque des conditions spécifiques se produisent
Créer des raccourcis si le flux d’événements envoie des données à un lakehouse
Pour les tables KQL :

Interroger les données directement à l’aide d’un ensemble de requêtes KQL pour une analyse en temps réel
Créer des visualisations dans des tableaux de bord Real-Time
Définir des alertes sur les résultats de la requête
Vous pouvez également créer un flux d’événements à partir des données que vous trouvez, afin de pouvoir transformer et atterrir les données en fonction des besoins. Cette approche vous permet d’ajouter votre propre logique métier et transformations sans modifier le flux d’origine.

Les données en temps réel peuvent être acheminées vers les lakehouses via des flux d’événements, créant ainsi un lien entre l’analyse en continu et l’analyse par lots. Cette architecture vous permet de créer des rapports qui combinent des données en temps réel et historiques.

Ajouter de nouvelles sources de diffusion en continu
Bien que la page de données de streaming vous aide à découvrir des flux existants, Real-Time hub fournit également l’expérience Ajouter des données pour connecter de nouvelles sources externes. Cette option est utile lorsque vous devez importer des données qui n’existent pas déjà dans Fabric.

Sélectionnez Ajouter des données pour accéder aux connecteurs pour :

Sources Microsoft : Azure Event Hubs, Azure IoT Hub, flux CDC de base de données
Événements Fabric : modifications des éléments de l’espace de travail, opérations de fichiers OneLake
Événements Azure : événements Azure Blob Storage
Sources externes : Apache Kafka, Amazon Kinesis, Google Cloud Pub/Sub
 Remarque

La connexion et la transformation de nouvelles sources de diffusion en continu impliquent une configuration plus avancée que celle décrite dans ce module. Pour plus d’informations sur l’utilisation des flux d’événements, consultez Vue d’ensemble des flux d’événements Microsoft Fabric.
