## Présentation
Effectué
100 XP
1 minute

Microsoft Fabric propose deux types de bases de données relationnelles : l'**entrepôt de données Fabric** (optimisé pour l'analytique à grande échelle) et la **base de données SQL dans Microsoft Fabric** (optimisée pour les applications transactionnelles opérationnelles).

La base de données SQL dans Fabric est une base de données transactionnelle polyvalente et conviviale pour les développeurs, reposant sur **Azure SQL Database**. Elle est conçue pour les charges de travail opérationnelles — applications web, systèmes de gestion, microservices — tout en étant nativement intégrée à l'écosystème Fabric.

La différence fondamentale avec Azure SQL Database est que SQL Database dans Fabric est un service **SaaS (Software as a Service)** plutôt que **PaaS (Platform as a Service)**. Cela signifie moins de maintenance pour les utilisateurs, qui peuvent se concentrer sur leurs activités principales plutôt que sur la gestion de l'infrastructure.

Dans ce module, vous apprendrez à créer et interroger une base de données SQL dans Fabric, à la sécuriser, à utiliser Copilot pour améliorer votre productivité, et à exploiter les fonctionnalités de mise en miroir et de virtualisation des données.

## Utiliser des bases de données SQL
Effectué
100 XP
9 minutes

Base de données SQL dans Microsoft Fabric est une base de données transactionnelle polyvalente et conviviale pour les développeurs, qui repose sur Azure SQL Database. Elle permet la création et la gestion de bases de données opérationnelles dans l'environnement Fabric.

### Différences entre SQL Database Fabric et Azure SQL Database

| Critère | SQL Database dans Fabric | Azure SQL Database |
|---|---|---|
| **Type de service** | SaaS (Software as a Service) | PaaS (Platform as a Service) |
| **Infrastructure** | Gérée entièrement par Microsoft | Configuration de tier, CPU, mémoire requise |
| **Facturation** | Via la capacité Fabric | Par instance/DTU/vCore |
| **Intégration Fabric** | Natif — données répliquées dans OneLake automatiquement | Via connexion externe ou mise en miroir |
| **Outils de gestion** | Portail Fabric + SSMS/Azure Data Studio | Portail Azure + SSMS/Azure Data Studio |

### Caractéristiques clés de SQL Database dans Fabric

L'une des fonctionnalités distinctives est la **réplication automatique des données dans OneLake** en quasi-temps réel au format Parquet. Cela facilite l'analyse sans nécessiter de processus ETL complexes et permet à d'autres services Fabric (Spark, notebooks, Power BI) d'accéder aux données opérationnelles.

### Création d'une base de données SQL

Pour créer une base de données SQL dans Fabric :

1. Accédez au portail Fabric et sélectionnez **Bases de données**.
2. Sous la section **Nouveau**, sélectionnez la vignette **Base de données SQL**.
3. Entrez un nom pour votre nouvelle base de données, puis sélectionnez **Créer**.

![Capture d'écran montrant la page Explorateur d'une base de données SQL nouvellement créée.](https://learn.microsoft.com/fr-fr/training/wwl-data-ai/get-started-sql-database-microsoft-fabric/media/2-new-database.png)

Une fois la base de données configurée, vous voyez le volet **Explorateur** affichant les objets de base de données. Trois options de démarrage rapide sont disponibles :

- **Exemple de données** : importer les exemples *AdventureWorksLT*.
- **T-SQL** : éditeur web pour créer des objets (schémas, tables, vues).
- **Chaînes de connexion** : obtenir les informations de connexion pour SSMS ou d'autres outils externes.

### Interroger une base de données SQL

Vous pouvez interroger une base de données SQL dans Fabric via :

- L'**éditeur web intégré** dans le portail Fabric
- **SQL Server Management Studio (SSMS)**
- **Azure Data Studio**
- **Visual Studio Code** avec l'extension SQL

L'option **Ouvrir dans** dans le portail lance automatiquement Visual Studio Code ou SSMS avec les propriétés de connexion préremplies.

![Capture d'écran montrant comment interroger une base de données SQL dans Microsoft Fabric.](https://learn.microsoft.com/fr-fr/training/wwl-data-ai/get-started-sql-database-microsoft-fabric/media/2-query.png)

**Exemple de requêtes T-SQL :**

```sql
-- Créer une table
CREATE TABLE dbo.Products (
    ProductID INT IDENTITY(1,1) PRIMARY KEY,
    ProductName NVARCHAR(100) NOT NULL,
    Price DECIMAL(10,2) NOT NULL,
    Stock INT DEFAULT 0
);

-- Insérer des données
INSERT INTO dbo.Products (ProductName, Price, Stock)
VALUES ('Laptop Pro', 1299.99, 50),
       ('Wireless Mouse', 29.99, 200),
       ('USB-C Hub', 49.99, 150);

-- Interroger avec filtrage
SELECT ProductName, Price
FROM dbo.Products
WHERE Stock > 100
ORDER BY Price DESC;
```

### Contrôle de code source

Le contrôle de code source est nativement intégré à la base de données SQL dans Microsoft Fabric :

- **Commit dans le contrôle de version** : convertit les objets de la base de données active en code (définitions d'objets écrites dans le référentiel Git).
- **Mise à jour depuis le contrôle de code source** : applique les changements depuis le référentiel vers la base de données, avec validation avant application.
- **Suivi de l'historique** : historique complet des modifications dans le système de contrôle de code source.

### Tableau de bord des performances

Le tableau de bord **Performances** simplifie le monitoring en supprimant les complexités liées aux opérations de base de données. Il offre différents niveaux de visibilité selon l'expertise :

- **Niveau débutant** : métriques de performance des requêtes de base.
- **Niveaux intermédiaire et avancé** : informations détaillées sur les requêtes, les attentes, les plans d'exécution.

Accès : clic droit sur la base de données > **Ouvrir le résumé des performances**, ou depuis la barre d'outils de l'**Éditeur de requête** > **Le résumé des performances**.

![Capture d'écran montrant l'option de tableau de bord de performances dans un éditeur de requête dans Microsoft Fabric.](https://learn.microsoft.com/fr-fr/training/wwl-data-ai/get-started-sql-database-microsoft-fabric/media/2-performance.png)

### Optimisation automatique des index

L'**optimisation automatique** utilise le Machine Learning pour optimiser les performances de vos requêtes. Elle identifie automatiquement les opportunités de réglage et les implémente. Dans l'onglet **Index automatique** du tableau de bord des performances, vous pouvez voir les index créés, supprimés et restaurés automatiquement au fil du temps.

## Bases de données sécurisées dans Fabric
Effectué
100 XP
5 minutes

La base de données SQL dans Fabric offre un mécanisme de sécurité sophistiqué à plusieurs niveaux, exploitant la puissance du moteur SQL familier.

### Rôles des espaces de travail

Les rôles d'espace de travail constituent la première couche de contrôle d'accès :

| Rôle | Accès |
|---|---|
| **Administrateur** | Contrôle total — gérer les membres, modifier tous les paramètres |
| **Membre** | Peut modifier le contenu et partager |
| **Contributeur** | Peut modifier le contenu |
| **Viewer** | Peut uniquement visualiser |

### Autorisations d'accès aux éléments

Des autorisations d'éléments peuvent être attribuées directement aux bases de données individuelles, sans accorder l'accès à tout l'espace de travail. Accès : élément dans l'espace de travail > **Gérer les autorisations**.

> **Remarque** : L'octroi d'autorisations d'élément n'a aucune incidence sur les métadonnées de sécurité situées à l'intérieur de la base de données.

### Protection des données (sécurité T-SQL granulaire)

Vous pouvez utiliser T-SQL pour accorder des autorisations spécifiques aux utilisateurs :

| Mécanisme | Description | Exemple |
|---|---|---|
| **Sécurité au niveau des objets** | Contrôle l'accès à des tables, vues, procédures spécifiques | `GRANT SELECT ON dbo.Products TO [user@company.com]` |
| **Sécurité au niveau des colonnes** | Restreint la visibilité de certaines colonnes | `DENY SELECT ON dbo.Employees(Salary) TO [user@company.com]` |
| **Sécurité au niveau des lignes (RLS)** | Filtre les lignes selon l'identité de l'utilisateur | Prédicats de filtre sur les tables |
| **Masquage dynamique des données** | Masque les données sensibles pour les utilisateurs non privilégiés | `ALTER TABLE Employees ALTER COLUMN Email ADD MASKED WITH (FUNCTION = 'email()')` |

**Exemple de sécurité au niveau des lignes (RLS) :**

```sql
-- Créer une fonction de prédicat
CREATE FUNCTION Security.fn_RegionFilter(@Region NVARCHAR(50))
RETURNS TABLE
WITH SCHEMABINDING
AS
RETURN SELECT 1 AS Result
WHERE @Region = SESSION_CONTEXT(N'UserRegion');
GO

-- Appliquer la politique de sécurité
CREATE SECURITY POLICY RegionPolicy
ADD FILTER PREDICATE Security.fn_RegionFilter(Region)
ON dbo.SalesData;
GO
```

Gérer les rôles de base de données depuis le portail Fabric : **Sécurité** > **Gérer la sécurité SQL**.

![Capture d'écran du portail Fabric montrant les options de sécurité SQL.](https://learn.microsoft.com/fr-fr/training/wwl-data-ai/get-started-sql-database-microsoft-fabric/media/3-manage-sql-security.png)

## Découvrez Copilot pour la base de données SQL
Effectué
100 XP
5 minutes

Dans un monde technologique en constante évolution, l'IA améliore la productivité des développeurs et des administrateurs de bases de données. Copilot dans SQL Database Fabric offre plusieurs fonctionnalités d'assistance intelligente.

### Fonctionnalités de Copilot pour SQL Database

**Microsoft Copilot** est intégré à la base de données SQL dans Fabric, améliorant la gestion et la résolution des problèmes SQL. Il augmente la productivité en offrant :

#### 1. Langage naturel vers SQL

La fonctionnalité de **langage naturel en SQL** traduit des descriptions en langage naturel en requêtes T-SQL dans l'éditeur de requête. Copilot est sensible au schéma — il connaît la structure de votre base de données pour générer des requêtes précises.

**Exemples de questions en langage naturel :**
```
Quels employés ont complété plus de deux projets ce trimestre ?
Listez tous les produits qui étaient en rupture de stock le mois dernier.
Classez chaque département par score de satisfaction des employés et montrez le nom du département, le score moyen et le rang.
Créez une contrainte de clé primaire nommée PK_Product_ProductID sur la colonne ProductID de la table Product.
```

#### 2. Complétion de code

Lors de la saisie de code T-SQL dans l'éditeur, Copilot propose des **suggestions automatiques contextuelles**, accélérant l'écriture de requêtes complexes.

#### 3. Actions rapides : Expliquer et Corriger

Copilot peut **corriger automatiquement les erreurs de code T-SQL** au fur et à mesure qu'elles se produisent. En partageant le contexte avec l'onglet de requête actif, il propose des suggestions pour corriger les erreurs de manière transparente.

Les boutons **Expliquer** et **Corriger** dans la barre d'outils de l'éditeur permettent :
- **Expliquer** : obtenir une explication en langage naturel d'une requête existante.
- **Corriger** : résoudre automatiquement les erreurs de syntaxe ou de logique.

#### Accéder à Copilot

Pour accéder aux fonctionnalités de Copilot dans le portail Fabric, ouvrez votre base de données SQL et :
- Sélectionnez le bouton **Copilot** dans le ruban pour ouvrir le volet de conversation.
- Utilisez les boutons **Expliquer** et **Corriger** dans la barre d'outils de l'éditeur de requête.

> **Remarque** : Copilot pour la base de données SQL n'utilise pas les données des tables pour générer des suggestions T-SQL — il utilise uniquement le schéma (métadonnées).

## Simplifier la gestion des données grâce à la mise en miroir et à la virtualisation
Effectué
100 XP
8 minutes

Les organisations sont souvent confrontées à des défis dans la gestion et l'analyse de leurs données en raison de la complexité d'intégration de différentes sources. Base de données SQL dans Microsoft Fabric répond à ces défis avec deux fonctionnalités clés : la **mise en miroir** et la **virtualisation des données**.

### Intégrer avec la mise en miroir

La **mise en miroir** permet de répliquer des bases de données depuis Azure SQL Database directement dans OneLake de Fabric. SQL Database dans Fabric est également automatiquement mis en miroir pour l'analytique, avec des données répliquées en continu en quasi-temps réel.

![Schéma de la mise en miroir de la base de données Fabric.](https://learn.microsoft.com/fr-fr/training/wwl-data-ai/get-started-sql-database-microsoft-fabric/media/5-mirroring.png)

**Avantages de la mise en miroir :**
- Réplication continue en quasi-temps réel (pas de latence batch).
- Aucun processus ETL complexe requis.
- Réduction du coût total de possession (TCO).
- Accès immédiat pour BI, IA, science des données et partage de données.

**Surveiller la réplication :** sélectionnez **Surveiller la réplication** sous l'onglet **Réplication**. En l'absence de mises à jour dans les tables sources, le moteur se désactive et reprend automatiquement à la détection de nouvelles données.

![Capture d'écran montrant comment surveiller un processus de mise en miroir.](https://learn.microsoft.com/fr-fr/training/wwl-data-ai/get-started-sql-database-microsoft-fabric/media/5-monitor.png)

### Explorer la virtualisation des données

La **virtualisation des données** vous permet d'accéder à des données de différentes sources sans les déplacer ni les copier physiquement. Elle fournit une vue unifiée des données provenant de différentes plateformes (tables Parquet, CSV, Delta disponibles dans un Lakehouse).

**Fonctionnalités T-SQL pour la virtualisation :**

| Fonctionnalité | Description | Exemple |
|---|---|---|
| **Informations d'identification incluses dans l'étendue** | Accès sécurisé aux sources de données externes | `CREATE DATABASE SCOPED CREDENTIAL MyCredential WITH IDENTITY = 'USER IDENTITY';` |
| **Source de données externe** | Définit des sources de données externes (OneLake, ADLS...) | `CREATE EXTERNAL DATA SOURCE ...` |
| **Format de fichier externe** | Spécifie le format des fichiers externes (Parquet, CSV, Delta) | `CREATE EXTERNAL FILE FORMAT MyFormat WITH (FORMAT_TYPE = PARQUET);` |
| **Table externe** | Crée des tables référençant des données externes | `CREATE EXTERNAL TABLE MyExtTable (...) WITH (LOCATION = '...', ...)` |

**Exemple de virtualisation avec une table externe :**

```sql
-- Créer les informations d'identification
CREATE DATABASE SCOPED CREDENTIAL MyOneLakeCred
WITH IDENTITY = 'USER IDENTITY';
GO

-- Créer la source de données externe (OneLake)
CREATE EXTERNAL DATA SOURCE MyOneLakeDS
WITH (
    LOCATION = 'abfss://workspace-id@onelake.dfs.fabric.microsoft.com/lakehouse-id',
    CREDENTIAL = MyOneLakeCred
);
GO

-- Créer le format de fichier
CREATE EXTERNAL FILE FORMAT ParquetFormat
WITH (FORMAT_TYPE = PARQUET);
GO

-- Créer la table externe pointant vers le fichier dans OneLake
CREATE EXTERNAL TABLE dbo.ExternalSales (
    SaleID INT,
    ProductName NVARCHAR(100),
    Amount DECIMAL(10,2),
    SaleDate DATE
)
WITH (
    LOCATION = 'Files/sales/data.parquet',
    DATA_SOURCE = MyOneLakeDS,
    FILE_FORMAT = ParquetFormat
);
GO

-- Interroger la table externe comme une table normale
SELECT ProductName, SUM(Amount) AS TotalSales
FROM dbo.ExternalSales
WHERE SaleDate >= '2025-01-01'
GROUP BY ProductName
ORDER BY TotalSales DESC;
```

## Vérification des connaissances
8 minutes

1. **Quelle est la principale différence entre SQL Database dans Fabric et Azure SQL Database ?**
   - a) SQL Database dans Fabric ne supporte pas le T-SQL
   - b) SQL Database dans Fabric est un service SaaS intégré nativement à l'écosystème Fabric, tandis qu'Azure SQL Database est un service PaaS ✓
   - c) Azure SQL Database réplique automatiquement les données dans OneLake
   - d) SQL Database dans Fabric ne peut pas être interrogé avec SSMS
   
   *SQL Database dans Fabric est un service SaaS (Software as a Service) qui nécessite moins de maintenance et s'intègre nativement à Fabric avec réplication automatique dans OneLake. Azure SQL Database est un service PaaS nécessitant une configuration de tier, de ressources et une connexion externe pour l'intégration Fabric.*

2. **Quelle fonctionnalité de SQL Database dans Fabric réplique automatiquement les données dans OneLake en quasi-temps réel pour l'analytique ?**
   - a) La virtualisation des données
   - b) La mise en miroir (Mirroring) ✓
   - c) L'optimisation automatique des index
   - d) Le contrôle de code source
   
   *La mise en miroir (Mirroring) réplique automatiquement les données de SQL Database dans Fabric (et depuis Azure SQL Database) vers OneLake en quasi-temps réel, éliminant les processus ETL complexes et permettant l'accès immédiat pour l'analytique.*

3. **Quel mécanisme de sécurité T-SQL permet de restreindre les lignes d'une table selon l'identité de l'utilisateur qui effectue la requête ?**
   - a) Masquage dynamique des données
   - b) Sécurité au niveau des colonnes (CLS)
   - c) Sécurité au niveau des lignes (RLS) ✓
   - d) Sécurité au niveau des objets
   
   *La sécurité au niveau des lignes (RLS) utilise des fonctions de prédicat de filtre pour restreindre automatiquement les lignes retournées par une requête selon l'identité ou le contexte de session de l'utilisateur.*

4. **Quelle fonctionnalité de Copilot pour SQL Database dans Fabric génère automatiquement des requêtes T-SQL depuis des descriptions textuelles ?**
   - a) L'optimisation automatique des index
   - b) La complétion de code uniquement
   - c) Le langage naturel vers SQL ✓
   - d) Les actions rapides Corriger
   
   *La fonctionnalité "langage naturel vers SQL" de Copilot traduit des questions ou descriptions en langage naturel en requêtes T-SQL valides, en utilisant la connaissance du schéma de la base de données pour générer des requêtes précises.*

5. **Quel objet T-SQL permet d'accéder à des fichiers Parquet stockés dans OneLake depuis une base de données SQL Fabric, sans copier les données ?**
   - a) Une table normale avec COPY INTO
   - b) Une vue SQL
   - c) Une table externe (External Table) ✓
   - d) Un synonym SQL
   
   *Les tables externes (External Tables) permettent de référencer des données stockées en dehors de la base de données (dans OneLake, Azure Data Lake Storage, etc.) sans déplacer ni copier physiquement les données, realisant la virtualisation des données.*

## Résumé
4 minutes

Dans ce module, vous avez découvert la base de données SQL dans Microsoft Fabric :

- **SQL Database dans Fabric** est une base de données transactionnelle SaaS basée sur Azure SQL Database, intégrée nativement à l'écosystème Fabric et conçue pour les charges de travail opérationnelles.
- La **réplication automatique dans OneLake** en quasi-temps réel (format Parquet) élimine les processus ETL complexes et rend les données disponibles pour tous les services Fabric (Spark, Power BI, notebooks).
- Les **fonctionnalités de sécurité** T-SQL granulaires — sécurité au niveau des objets, colonnes, lignes (RLS), et masquage dynamique des données — permettent un contrôle fin des accès.
- **Copilot pour SQL Database** améliore la productivité avec le langage naturel vers SQL, la complétion de code, et les actions rapides Expliquer/Corriger.
- La **mise en miroir** réplique en quasi-temps réel les données vers OneLake pour l'analytique, tandis que la **virtualisation des données** (tables externes) permet d'accéder aux fichiers OneLake sans les copier.
- Le **tableau de bord des performances** et l'**optimisation automatique des index** simplifient le monitoring et l'amélioration des performances.
