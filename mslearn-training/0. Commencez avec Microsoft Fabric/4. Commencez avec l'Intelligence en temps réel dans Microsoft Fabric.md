## Présentation
Effectué
100 XP
2 minutes

Dans le monde numérique actuel, les organisations génèrent des volumes massifs de données en continu : capteurs IoT, journaux d'application, transactions financières, flux de médias sociaux, signaux de sécurité... Ces données ont une valeur maximale lorsqu'elles sont analysées **au moment où elles se produisent**, avant que leur pertinence ne s'estompe.

Les solutions d'analytique traditionnelles basées sur des traitements par lots ne répondent pas à ce besoin : elles accumulent des données, puis les traitent périodiquement, créant un délai entre l'événement et l'insight. **Real-Time Intelligence (RTI)** dans Microsoft Fabric comble cet écart en fournissant une solution de bout en bout pour les données en mouvement.

Real-Time Intelligence est un service puissant qui permet à tous les membres de votre organisation d'extraire des insights et de visualiser leurs données en mouvement. Il offre une solution de bout en bout pour les scénarios où vous devez répondre aux événements au fur et à mesure qu'ils se produisent, traiter le flux continu de données ou analyser des journaux.

## Qu'est-ce que l'analytique de données en temps réel ?
Effectué
100 XP
5 minutes

### Comprendre les données en streaming

L'analytique en temps réel fait référence à la capacité d'analyser des données immédiatement après leur génération, en quasi-temps réel ou en temps réel. Contrairement au traitement par lots (batch), qui accumule des données puis les traite selon un planning, le traitement en flux continu (streaming) analyse les données au fur et à mesure qu'elles arrivent.

Même si le terme "temps réel" est utilisé, vos données n'ont pas nécessairement besoin de circuler à des vitesses et des volumes extrêmement élevés. Real-Time Intelligence vous donne des solutions qui réagissent aux événements au fur et à mesure qu'ils se produisent, plutôt que des solutions qui s'exécutent selon une planification.

### Cas d'usage typiques

Real-Time Intelligence dans Microsoft Fabric s'applique à un large éventail de scénarios métier :

| Domaine | Cas d'usage |
|---|---|
| **IoT / Industrie** | Surveillance de capteurs d'usine, détection d'anomalies sur équipements |
| **Finance** | Détection de fraudes en temps réel, surveillance des prix d'actions |
| **Retail** | Suivi de l'inventaire en temps réel, analyse du comportement d'achat |
| **Cybersécurité** | Détection d'intrusions, monitoring de la sécurité des applications IA |
| **Opérations** | Surveillance de l'infrastructure IT, alertes sur SLA |
| **IA générative** | Télémétrie d'agents, surveillance de la sécurité des contenus générés |

### Différence avec l'analytique batch

| Critère | Batch Analytics | Real-Time Analytics |
|---|---|---|
| **Latence** | Minutes à heures | Secondes à millisecondes |
| **Volume traité** | Grands lots périodiques | Flux continu d'événements |
| **Cas d'usage** | Rapports historiques, BI | Alertes, détection d'anomalies, actions immédiates |
| **Outil Fabric** | Lakehouse, Data Warehouse | Real-Time Intelligence (Eventhouse, Eventstreams) |

## Real-Time Intelligence dans Microsoft Fabric
Effectué
100 XP
8 minutes

Real-Time Intelligence dans Microsoft Fabric offre une architecture complète pour les données en mouvement, couvrant l'ingestion, la transformation, le stockage, l'analytique, la visualisation et les actions automatisées.

![Diagram de l'architecture de Real-Time Intelligence dans Microsoft Fabric.](https://learn.microsoft.com/fr-fr/fabric/real-time-intelligence/media/overview/overview-schematic.png)

### Composants clés de Real-Time Intelligence

#### 1. Real-Time Hub (Hub en temps réel)

Le **Real-Time Hub** est le catalogue centralisé de toutes les données en mouvement au sein de votre organisation. Il sert de point d'entrée unique pour :

- **Data Streams** : tous les flux de données actifs dans Fabric auxquels vous avez accès.
- **Microsoft Sources** : connexion rapide à des sources telles qu'Azure Event Hubs, Azure IoT Hub, Azure SQL DB CDC, Azure Cosmos DB CDC, PostgreSQL DB CDC.
- **Fabric Events** : événements liés aux éléments de l'espace de travail Fabric (éléments créés/modifiés) et aux événements Azure Blob Storage.

Le Real-Time Hub garantit que les données en streaming sont accessibles à tous les membres de l'organisation, favorisant une prise de décision rapide.

#### 2. Eventstreams

Les **Eventstreams** (flux d'événements) vous permettent de collecter, de transformer et d'envoyer de grandes quantités de données en temps réel vers différentes destinations, sans écrire de code.

**Capacités des Eventstreams :**
- Connecteurs sans code vers de nombreuses sources (Kafka, AWS Kinesis, Google Pub/Sub, MQTT, connecteurs météo)
- Filtrage, nettoyage, transformation, agrégations fenêtrées et détection de doublons
- Routage basé sur le contenu vers différentes destinations
- Flux dérivés (eventstreams dérivés) partagés dans le Real-Time Hub
- Alertes et gestion des règles intégrées directement dans l'interface

**Sources supportées (exemples) :**
- Azure Event Hubs
- Azure IoT Hub
- Apache Kafka
- Change Data Capture (CDC) pour Azure SQL DB, Cosmos DB, PostgreSQL
- Amazon Kinesis, Google Cloud Pub/Sub
- MQTT v3.1/v3.1.1

**Destinations supportées :**
- Eventhouse (base de données KQL)
- Lakehouse
- Data Warehouse
- Real-Time Dashboard

#### 3. Eventhouse et bases de données KQL

L'**Eventhouse** est le moteur d'analytique optimisé pour les données en mouvement. Il contient une ou plusieurs **bases de données KQL** (Kusto Query Language).

Les eventhouses sont spécialement adaptés aux événements de diffusion en continu basés sur le temps et comprennent des données structurées, semi-structurées et non structurées. Les données sont automatiquement organisées en fonction de leur arrivée, ce qui permet des requêtes rapides et détaillées même sur de grandes quantités.

**Fonctionnalités clés de l'Eventhouse :**
- Requêtes ultra-rapides avec **KQL** (Kusto Query Language) natif
- Point de terminaison d'analytique SQL géré pour les analyses T-SQL
- Données reflétées dans OneLake (copie logique)
- Détection native d'anomalies sur les données de séries chronologiques
- Copilot Kusto pour la génération de requêtes en langage naturel
- Intégration avec les notebooks Fabric (KQL, T-SQL, Python, Spark)

#### 4. Tableaux de bord en temps réel

Les **Real-Time Dashboards** (tableaux de bord en temps réel) permettent de visualiser les données en quasi-temps réel, avec des insights disponibles en quelques secondes après l'ingestion.

**Visualisations disponibles :**
- Graphiques de séries chronologiques
- Tableaux et grilles de données
- Cartes géospatiales (avec support GeoJSON et PMTiles)
- Cartes thermiques, polygones, extrusions 3D
- Intégration avec Copilot pour des questions en langage naturel

#### 5. Activateur (Fabric Activator)

**Activator** permet de configurer des alertes et des actions automatisées basées sur les données en temps réel. Lorsque certaines conditions sont remplies, il peut :

- Alerter des utilisateurs (email, Teams)
- Lancer des éléments de travail Fabric (pipeline, Spark job, dataflow)
- Exécuter des fonctions de données utilisateur
- Déclencher des flux Power Automate

La logique peut être un seuil simple, un modèle d'événements récurrents ou les résultats d'une requête KQL complexe.

## Ingérer et transformer des données en temps réel
Effectué
100 XP
6 minutes

### Créer un Eventstream

Pour ingérer des données en temps réel, vous créez un **Eventstream** dans votre espace de travail Fabric. Le processus est sans code :

1. Dans l'espace de travail, créez un nouvel Eventstream.
2. Sélectionnez une **source** parmi les connecteurs disponibles (Azure Event Hubs, Kafka, IoT Hub...).
3. Configurez les paramètres de connexion.
4. Optionnellement, ajoutez des **opérations de transformation** (filtrer, grouper, agréger...).
5. Sélectionnez une **destination** (Eventhouse, Lakehouse...).

### Opérations de transformation dans Eventstreams

Sans écrire de code, vous pouvez appliquer des transformations à vos flux de données :

| Opération | Description |
|---|---|
| **Filtrer** | Sélectionner uniquement les événements qui répondent à des conditions |
| **Agréger** | Calculer des métriques (somme, moyenne, comptage) sur des fenêtres temporelles |
| **Grouper** | Regrouper les événements par attribut |
| **Déduplication** | Supprimer les événements en double |
| **Enrichir** | Ajouter des données de contexte depuis un lakehouse |
| **Routage** | Diriger les événements vers différentes destinations selon le contenu |

### Fenêtres temporelles

Un concept fondamental du traitement de streaming est la **fenêtre temporelle** (time window). Elle définit comment regrouper les événements pour les agrégations :

- **Fenêtre glissante (Sliding window)** : fenêtre qui se déplace dans le temps avec des chevauchements.
- **Fenêtre basculante (Tumbling window)** : fenêtre de taille fixe, sans chevauchement.
- **Fenêtre de session** : groupe les événements liés dans une session d'activité.

## Stocker et interroger des données en temps réel
Effectué
100 XP
5 minutes

### Kusto Query Language (KQL)

Le **Kusto Query Language (KQL)** est le langage natif pour interroger les données dans un Eventhouse. C'est un langage simple mais puissant, optimisé pour les données tabulaires, les séries chronologiques et les journaux.

**Exemple de requête KQL basique :**

```kql
// Interroger les 100 derniers événements d'une table
MyTable
| take 100

// Filtrer et agréger les événements des dernières 24 heures
MyTable
| where TimeStamp > ago(24h)
| where EventType == "Error"
| summarize Count = count() by bin(TimeStamp, 1h), Source
| render timechart
```

**Comparaison KQL / SQL :**

| Opération | KQL | SQL |
|---|---|---|
| Filtrer | `\| where condition` | `WHERE condition` |
| Limiter | `\| take N` | `TOP N` |
| Trier | `\| sort by col desc` | `ORDER BY col DESC` |
| Agréger | `\| summarize agg by key` | `SELECT key, agg GROUP BY key` |
| Joindre | `\| join kind=inner (...)` | `INNER JOIN ...` |

### Créer un Eventhouse et une base de données KQL

Pour stocker des données en temps réel :

1. Créez un **Eventhouse** dans votre espace de travail Fabric.
2. Une **base de données KQL** est automatiquement créée au sein de l'Eventhouse.
3. Connectez votre Eventstream à l'Eventhouse comme destination.
4. Les données s'accumulent automatiquement et sont disponibles pour interrogation.

### Intégration OneLake

Les données dans un Eventhouse sont automatiquement reflétées dans OneLake sous forme de copie logique (format Delta-Parquet), sans dupliquer les données physiques. Cela permet aux autres charges de travail Fabric (Lakehouse, Data Warehouse, notebooks) d'accéder aux données de streaming.

## Visualiser des données en temps réel
Effectué
100 XP
2 minutes

### Tableaux de bord en temps réel

Les **Real-Time Dashboards** se connectent directement aux bases de données KQL et affichent les données avec des actualisations automatiques configurables (secondes ou minutes).

**Caractéristiques clés :**
- Actualisation automatique sans intervention manuelle
- Visualisations multiples (graphiques de lignes, barres, aires, cartes, tables)
- Interactions de filtrage intégrées
- Accès par langage naturel via Copilot
- Alertes directement configurables depuis le tableau de bord

### Sets de requêtes KQL (KQL Querysets)

Les **KQL Querysets** permettent de sauvegarder et partager des requêtes KQL. Ils servent de point d'entrée pour l'exploration des données Eventhouse et peuvent être utilisés pour créer des rapports Power BI.

### Rapports Power BI

Les données d'un Eventhouse peuvent être consommées dans des **rapports Power BI**, permettant de combiner des données historiques (lakehouse/entrepôt) avec des données en temps réel (eventhouse) dans un même rapport.

## Automatiser les actions
Effectué
100 XP
4 minutes

### Fabric Activator

**Activator** est le moteur d'actions automatisées de Real-Time Intelligence. Il surveille en continu les données en streaming et déclenche des actions lorsque des conditions spécifiques sont remplies.

**Architecture d'une règle Activator :**

1. **Source de données** : Real-Time Hub, requête KQL, rapport Power BI
2. **Condition** : seuil simple, pattern récurrent, ou résultat de requête KQL
3. **Action** : envoi d'une notification, lancement d'un pipeline, déclenchement d'un flux Power Automate

**Exemples de règles :**
- "Envoyer une alerte Teams si la température d'un capteur dépasse 80°C"
- "Lancer un pipeline de correction si le taux d'erreur dépasse 5% pendant 10 minutes"
- "Notifier l'équipe sécurité si plus de 100 requêtes échouées proviennent d'une même IP en 5 minutes"

### Cas d'usage IA générative

Pour les applications d'IA générative, vous pouvez configurer des flux de travail de correction via Activator :

- Surveiller les signaux de sécurité de contenu en temps réel
- Détecter des violations de règles (seuil de toxicité dépassé)
- Acheminer les événements vers des flux de quarantaine
- Déclencher des pipelines ou flux Power Automate pour limiter ou bloquer les accès

## Résumé
1 minute

Dans ce module, vous avez découvert Real-Time Intelligence dans Microsoft Fabric, la solution de bout en bout pour les données en mouvement :

- **Real-Time Hub** : catalogue centralisé pour découvrir et partager les données de streaming dans l'organisation.
- **Eventstreams** : collecte, transformation et routage de données en temps réel sans code, avec connecteurs vers de nombreuses sources (Kafka, Event Hubs, IoT Hub, CDC...).
- **Eventhouse / Bases de données KQL** : stockage optimisé pour les données de streaming, requêtable via KQL (natif) ou T-SQL, avec réplication automatique dans OneLake.
- **Real-Time Dashboards** : visualisation en quasi-temps réel avec actualisation automatique et Copilot.
- **Activator** : automatisation des actions (alertes, pipelines) basée sur des conditions définies sur les données en temps réel.

Real-Time Intelligence est particulièrement adapté aux scénarios IoT, détection de fraudes, monitoring opérationnel, et de plus en plus pour la surveillance des applications d'IA générative.
