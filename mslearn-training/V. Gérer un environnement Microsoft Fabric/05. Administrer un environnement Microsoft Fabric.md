## 1. Architecture d'administration de Microsoft Fabric

### La structure organisationnelle de Fabric

Microsoft Fabric est organisé de manière hiérarchique, ce qui permet de déléguer les responsabilités d'administration à différents niveaux :

```
Tenant Microsoft (organisation entière)
│
├── Capacité 1 (ex : F64 - Région France)
│   ├── Domaine "Finance"
│   │   ├── Workspace Finance DEV
│   │   ├── Workspace Finance TEST
│   │   └── Workspace Finance PROD
│   │
│   └── Domaine "Marketing"
│       ├── Workspace Marketing Analytics
│       └── Workspace Marketing Reports
│
└── Capacité 2 (ex : F32 - Région Belgique)
    └── Domaine "Sales EMEA"
        ├── Workspace Sales Belgium
        └── Workspace Sales Netherlands
```

**Les composants clés de cette architecture :**

- **Tenant** : l'organisation entière dans Microsoft Entra ID (ex : `company.onmicrosoft.com`). Un tenant peut contenir plusieurs capacités.
- **Capacité** : pool de ressources de calcul (Compute Units) alloué à une ou plusieurs organisations. Une capacité a un SKU (F2, F4, F8, F16, F32, F64, F128, F256, F512, F1024, F2048) et une région Azure.
- **Domaine** : regroupement logique d'espaces de travail par fonction métier (Finance, Marketing, RH...). Facilite la gouvernance délégée.
- **Workspace** : espace de travail contenant les éléments Fabric (lakehouses, notebooks, rapports, etc.)

### Les trois catégories de responsabilités d'administration

L'administration Fabric se divise en trois grandes catégories :

1. **Administration** : configurer la plateforme, gérer les fonctionnalités, surveiller l'usage
2. **Sécurité** : protéger les données avec les contrôles d'identité, d'accès, de chiffrement et de réseau
3. **Gouvernance** : définir et appliquer les politiques d'accès, de partage, de classification et d'audit

## 2. Les rôles d'administrateur Fabric

### Hiérarchie des rôles d'administration

Microsoft Fabric définit plusieurs rôles d'administrateur avec des responsabilités distinctes :

```
Rôles d'administration Fabric (du plus au moins privilégié)

Administrateur Power Platform
  ↓ sous-ensemble de
Administrateur Fabric
  ├── Gestion complète de Fabric au niveau tenant
  ├── Accès au portail d'administration
  └── Peut déléguer aux administrateurs de capacité

Administrateur de capacité
  ├── Gestion d'une capacité spécifique
  ├── Attribution de workspaces à la capacité
  └── Peut déléguer aux administrateurs de domaine

Administrateur de domaine
  ├── Gestion des workspaces d'un domaine
  └── Peut modifier certains paramètres au niveau du domaine

Administrateur de workspace
  ├── Gestion complète d'un workspace
  └── Gestion des membres et des éléments du workspace
```

**Comment assigner le rôle d'administrateur Fabric :**

Le rôle est assigné dans **Microsoft Entra ID** :
1. Accédez au portail Azure → **Microsoft Entra ID** → **Rôles et administrateurs**
2. Recherchez **"Fabric Administrator"** ou **"Power BI Administrator"**
3. Cliquez sur **+ Ajouter des affectations**
4. Sélectionnez l'utilisateur ou le groupe de sécurité

**Rôles Microsoft 365 donnant accès à l'administration Fabric :**

| Rôle | Accès au portail d'administration Fabric |
|------|----------------------------------------|
| Administrateur Fabric | Accès complet |
| Administrateur Power Platform | Accès complet |
| Administrateur global Microsoft 365 | Accès complet |
| Administrateur de capacité | Accès aux paramètres de capacité uniquement |

## 4. Les paramètres du locataire (Tenant Settings)

### Qu'est-ce que les Tenant Settings ?

Les **Tenant Settings** sont les paramètres de configuration globaux qui contrôlent quelles fonctionnalités sont disponibles et comment les utilisateurs peuvent interagir avec Microsoft Fabric dans votre organisation. Il existe plus de 200 paramètres organisés par catégorie.

**Niveaux de contrôle des paramètres :**

```
Niveau Organisation (par défaut)
├── Activé pour toute l'organisation
├── Désactivé pour toute l'organisation
└── Activé/Désactivé pour des groupes spécifiques

Niveau Capacité
└── Certains paramètres peuvent être surchargés au niveau capacité

Niveau Workspace
└── Certains paramètres peuvent être configurés par les admins workspace
```

### Paramètres tenant essentiels à configurer

**Paramètres de partage et de collaboration :**

```yaml
# Exemple de configuration recommandée pour une organisation sécurisée

Partager du contenu avec des utilisateurs externes :
  État : Activé
  Limité à : [groupe-partage-externe@company.com]

Permettre aux utilisateurs externes d'éditer les éléments :
  État : Désactivé

Publier sur le web :
  État : Désactivé (pour les environnements sensibles)
```

**Paramètres de développement et CI/CD :**

```yaml
Intégration Git :
  État : Activé pour l'ensemble de l'organisation
  Note : Restreindre aux groupes IT si souhaité

Pipelines de déploiement :
  État : Activé pour l'ensemble de l'organisation

Créer des espaces de travail :
  État : Activé uniquement pour : [fabric-workspace-creators@company.com]
  Note : Évite la prolifération non contrôlée de workspaces
```

**Paramètres de gouvernance et conformité :**

```yaml
Étiquettes de confidentialité Microsoft Purview :
  État : Activé pour l'ensemble de l'organisation

Permettre aux utilisateurs d'appliquer des étiquettes :
  État : Activé pour l'ensemble de l'organisation

Protection contre la perte de données (DLP) :
  État : Activé
  Politiques : Configurées dans Microsoft Purview

Permettre l'exportation vers Excel :
  État : Activé uniquement pour : [fabric-export-authorized@company.com]
  Note : Limiter pour les rapports avec données sensibles
```

**Paramètres de performance et de calcul :**

```yaml
Limites des actualisations planifiées :
  Actualisations maximales : 48 par jour (par défaut)

Actualisations incrémentales :
  État : Activé pour l'ensemble de l'organisation

DirectLake :
  État : Activé pour l'ensemble de l'organisation
```

### Configurer un paramètre tenant

1. Dans le portail d'administration → **Paramètres du locataire**
2. Utilisez la barre de recherche pour trouver le paramètre souhaité
3. Cliquez sur le paramètre pour l'étendre
4. Choisissez l'état (Activé / Désactivé)
5. Si activé, choisissez :
   - **Toute l'organisation** : s'applique à tous les utilisateurs
   - **Groupes de sécurité spécifiques** : s'applique uniquement aux membres des groupes sélectionnés
   - **Sauf ces groupes** : s'applique à tous sauf les membres des groupes spécifiés
6. Cliquez sur **Appliquer**

## 5. Gérer les capacités Fabric

### Comprendre les capacités et les SKUs

Une **capacité Microsoft Fabric** est un pool de ressources de calcul qui alimente les workloads Fabric. La taille d'une capacité est définie par son SKU (Stock-Keeping Unit), mesuré en **Compute Units (CU)** :

| SKU | CU | Usage recommandé |
|-----|-----|------------------|
| F2  | 2  | Développement / tests légers |
| F4  | 4  | POC et petits projets |
| F8  | 8  | Équipes petites à moyennes |
| F16 | 16 | Équipes moyennes |
| F32 | 32 | Projets d'entreprise moyens |
| F64 | 64 | Projets d'entreprise standard |
| F128 | 128 | Projets d'entreprise large scale |
| F256 | 256 | Très grand volume de données |
| F512 | 512 | Workloads critiques intensifs |
| F1024 | 1024 | Organisations de très grande taille |
| F2048 | 2048 | Organisations Enterprise tier |

**Équivalences avec les anciens SKUs Power BI Premium :**

```
Power BI Premium P1 ≈ Fabric F32 (32 CU)
Power BI Premium P2 ≈ Fabric F64 (64 CU)
Power BI Premium P3 ≈ Fabric F128 (128 CU)
Power BI Premium P4 ≈ Fabric F256 (256 CU)
Power BI Premium P5 ≈ Fabric F512 (512 CU)
```

### Créer une capacité Fabric

Les capacités Fabric se créent dans le **portail Azure** :

1. Accédez au portail Azure ([https://portal.azure.com](https://portal.azure.com))
2. Recherchez **"Microsoft Fabric"** dans la barre de recherche
3. Sélectionnez **+ Créer**
4. Remplissez les informations :

```
Abonnement : [Votre abonnement Azure]
Groupe de ressources : rg-fabric-production
Nom de la ressource : fabric-capacity-prod-fr
Région : France Central
Taille : F64
Administrateurs de capacité : [fabric-admin@company.com]
```

5. Cliquez sur **Examiner + créer** puis **Créer**

> **Note sur les coûts :** Les capacités Fabric sont facturées à la seconde. Suspendre une capacité inutilisée (nuits, week-ends) peut réduire significativement les coûts.

### Assigner un workspace à une capacité

1. Dans le **portail d'administration** Fabric → **Workspaces**
2. Trouvez le workspace à assigner
3. Cliquez sur **...** → **Paramètres**
4. Sous **Licence**, sélectionnez **Capacité Premium ou Fabric**
5. Sélectionnez la capacité dans la liste déroulante
6. Cliquez sur **Enregistrer**

Alternativement, depuis les paramètres du workspace :
1. Dans le workspace, cliquez sur **Paramètres du workspace**
2. Section **Licence** → **Type de licence** → **Fabric capacity**
3. Sélectionnez la capacité

### Mettre à l'échelle une capacité (Scale Up / Scale Down)

Pour ajuster la taille d'une capacité :

**Via le portail Azure :**
1. Accédez à la ressource de capacité Fabric dans le portail Azure
2. Dans le menu de gauche, sélectionnez **Mettre à l'échelle**
3. Sélectionnez le nouveau SKU cible
4. Cliquez sur **Enregistrer**

> **Note :** La mise à l'échelle est quasi instantanée et sans interruption de service.

**Via PowerShell :**

```powershell
# Installer le module Az.Fabric (si disponible) ou utiliser les API REST
# Méthode via API REST Azure

$subscriptionId = "votre-subscription-id"
$resourceGroup = "rg-fabric-production"
$capacityName = "fabric-capacity-prod-fr"
$targetSku = "F128"  # Montée en charge vers F128

$accessToken = (Get-AzAccessToken -ResourceUrl "https://management.azure.com/").Token

$body = @{
    sku = @{
        name = $targetSku
        tier = "Fabric"
    }
} | ConvertTo-Json

Invoke-RestMethod `
    -Uri "https://management.azure.com/subscriptions/$subscriptionId/resourceGroups/$resourceGroup/providers/Microsoft.Fabric/capacities/$capacityName?api-version=2023-11-01" `
    -Method PATCH `
    -Headers @{ Authorization = "Bearer $accessToken"; "Content-Type" = "application/json" } `
    -Body $body

Write-Output "Mise à l'échelle vers $targetSku démarrée."
```

### Suspendre et reprendre une capacité

Suspendre une capacité lorsqu'elle n'est pas utilisée (nuits, week-ends) permet de réduire les coûts, car Fabric est facturé à la consommation réelle.

**Via le portail Azure :**
1. Accédez à la ressource de capacité
2. Cliquez sur **Suspendre** dans la barre d'outils supérieure
3. Pour reprendre : cliquez sur **Reprendre**

**Automatiser la suspension/reprise avec Azure Automation :**

```powershell
# Script Azure Automation pour suspendre la capacité Fabric chaque soir à 19h

param(
    [string]$subscriptionId,
    [string]$resourceGroup,
    [string]$capacityName,
    [string]$action  # "suspend" ou "resume"
)

# Authentification avec Managed Identity
Connect-AzAccount -Identity

$token = (Get-AzAccessToken -ResourceUrl "https://management.azure.com/").Token
$headers = @{ Authorization = "Bearer $token"; "Content-Type" = "application/json" }
$baseUrl = "https://management.azure.com/subscriptions/$subscriptionId/resourceGroups/$resourceGroup/providers/Microsoft.Fabric/capacities/$capacityName"

if ($action -eq "suspend") {
    Invoke-RestMethod -Uri "$baseUrl/suspend?api-version=2023-11-01" `
        -Method POST -Headers $headers
    Write-Output "Capacité $capacityName suspendue à $(Get-Date)"
} elseif ($action -eq "resume") {
    Invoke-RestMethod -Uri "$baseUrl/resume?api-version=2023-11-01" `
        -Method POST -Headers $headers
    Write-Output "Capacité $capacityName reprise à $(Get-Date)"
}
```

## 6. Gérer les workspaces à l'échelle du tenant

### Vue d'ensemble des workspaces dans le portail d'administration

Dans le portail d'administration → **Workspaces**, les administrateurs peuvent voir **tous les workspaces** du tenant, quelle que soit leur capacité :

- Nom du workspace
- Capacité assignée
- Type (personnel "My Workspace" ou partagé)
- Nombre d'éléments
- Administrateurs du workspace

**Actions disponibles pour un administrateur Fabric :**
- Voir les détails d'un workspace
- Accéder à un workspace (même sans en être membre)
- Modifier la capacité assignée
- Supprimer un workspace
- Récupérer les logs d'audit d'un workspace

### Gouverner la création de workspaces

Par défaut, les utilisateurs Fabric peuvent créer des workspaces librement. Pour éviter une **prolifération incontrôlée** de workspaces :

1. Dans les **Paramètres du locataire** → Recherchez "Créer des espaces de travail"
2. Passez de "Toute l'organisation" à "Groupes de sécurité spécifiques"
3. Ajoutez uniquement les groupes autorisés à créer des workspaces (ex : `fabric-workspace-admins@company.com`)

**Convention de nommage recommandée pour les workspaces :**

Définissez et communiquez une convention de nommage officielle :

```
Format : [Domaine]-[Projet/Équipe]-[Environnement]

Exemples :
Finance-Reporting-PROD
Finance-Reporting-DEV
Marketing-Analytics-PROD
HR-Payroll-DEV
IT-DataPlatform-TEST
```

### Domaines — Organiser les workspaces par fonction métier

Les **domaines** sont des regroupements logiques de workspaces qui permettent de :
- Organiser les workspaces par fonction métier
- Déléguer l'administration à des experts du domaine
- Appliquer des paramètres spécifiques au domaine
- Améliorer la découvrabilité des données dans OneLake

**Créer un domaine :**

1. Portail d'administration → **Domaines**
2. Cliquez sur **+ Créer un domaine**
3. Nommez le domaine (ex : `Finance`)
4. Assignez des administrateurs de domaine
5. Assignez les workspaces au domaine

**Structure de gouvernance avec les domaines :**

```
Administrateur Fabric (IT Central)
├── Domaine Finance
│   Administrateur : cfo-team@company.com
│   ├── Workspace Finance DEV
│   ├── Workspace Finance PROD
│   └── Workspace Finance Analytics
│
├── Domaine Marketing
│   Administrateur : marketing-data@company.com
│   ├── Workspace Campaign Analytics
│   └── Workspace Customer 360
│
└── Domaine RH (HR)
    Administrateur : hr-ops@company.com
    ├── Workspace HR Analytics
    └── Workspace Payroll
```

## 7. Gérer les licences et les abonnements

### Types de licences Fabric

Microsoft Fabric utilise deux types de licences complémentaires :

**1. Licences de capacité (Capacity Licenses)**

Licences organisationnelles achetées comme ressources Azure. Elles fournissent un pool de ressources partagées pour tous les workspaces assignés à cette capacité.

```
Capacité F64 = 64 CU de ressources partagées
  ├── Workspace Finance (utilise ~20 CU en heures de pointe)
  ├── Workspace Marketing (utilise ~15 CU en heures de pointe)
  └── Workspace IT (utilise ~10 CU en heures de pointe)
  
Consommation totale = 45 CU < 64 CU → Pas de throttling
```

**2. Licences par utilisateur (Per-User Licenses)**

Licences individuelles requises pour que les utilisateurs interagissent avec Fabric :

| Licence | Description | Accès |
|---------|-------------|-------|
| **Fabric (Free)** | Gratuite | Peut créer des éléments dans "My Workspace" uniquement |
| **Fabric Pro** | Payante (~environ 10€/utilisateur/mois) | Accès complet à Fabric, partage dans workspaces partagés |
| **Fabric Premium Per User (PPU)** | Payante (plus élevée) | Accès aux fonctionnalités Premium sans capacité dédiée |

**Règle essentielle :** Pour qu'un utilisateur puisse accéder à du contenu dans un workspace partagé (avec capacité Fabric), il doit avoir au minimum une licence **Fabric (Free)** s'il accède à du contenu dans une capacité Fabric.

### Gérer les licences dans le Centre d'administration Microsoft 365

1. Accédez à [https://admin.microsoft.com](https://admin.microsoft.com)
2. **Facturation** → **Licences**
3. Sélectionnez **Microsoft Fabric** ou **Power BI Pro**
4. Assignez les licences aux utilisateurs individuellement ou via des groupes

**Désactiver l'inscription en libre-service :**

Pour éviter que les utilisateurs s'inscrivent eux-mêmes à Fabric Trial :

```powershell
# Désactiver le libre-service pour Microsoft Fabric Trial
Set-MSCommercePolicy -PolicyId AllowSelfServicePurchase -OfferId "CFQ7TTC0HB3W" -Enabled $false

# Vérifier l'état
Get-MSCommercePolicy -PolicyId AllowSelfServicePurchase -OfferId "CFQ7TTC0HB3W"
```

## 8. Surveiller l'utilisation et l'activité Fabric

### Outils de surveillance disponibles pour l'administrateur

En tant qu'administrateur Fabric, plusieurs outils de surveillance sont disponibles :

**1. Monitor Hub (pour les activités en temps réel)**
- Voir les exécutions en cours et récentes de tous les workspaces
- Filtrer par statut, type d'élément, utilisateur, workspace
- Accéder aux détails et logs des erreurs

**2. Capacity Metrics App (pour la consommation des ressources)**
- Analyser la consommation CU par workspace et par élément
- Identifier les phénomènes de throttling
- Prendre des décisions de mise à l'échelle

**3. Espace de travail de supervision de l'administration**

L'**espace de travail de supervision de l'administration** (Admin Monitoring Workspace) est un workspace Fabric créé automatiquement pour les administrateurs. Il contient un rapport pré-construit sur **l'utilisation et l'adoption des fonctionnalités** :

```
Admin Monitoring Workspace contient :
├── Rapport : Feature Usage and Adoption
│   ├── Vue d'ensemble de l'utilisation par workload
│   ├── Utilisateurs actifs par période
│   ├── Éléments les plus utilisés
│   └── Workspaces les plus actifs
│
└── Modèle sémantique associé
    (pour créer des rapports personnalisés)
```

**Accéder à l'espace de travail de supervision :**
1. Portail d'administration → **Workspace de supervision de l'administration**
2. Ou cherchez "Admin monitoring" dans la liste des workspaces

**4. Journaux d'audit (pour la conformité)**

Les journaux d'audit enregistrent toutes les activités utilisateur. Ils sont accessibles via :
- Portail d'administration → **Journaux d'audit** (redirige vers Microsoft Purview)
- Microsoft Purview → **Audit** → **Recherche dans le journal d'audit**

**Requête d'audit PowerShell pour les exports de données :**

```powershell
# Extraire les activités d'export des 30 derniers jours
Connect-PowerBIServiceAccount

$logs = Get-PowerBIActivityEvent `
    -StartDateTime "2026-04-27" `
    -EndDateTime "2026-05-27" `
    -ActivityType "ExportReport"

# Analyser les exports par utilisateur
$logs | Group-Object -Property UserId |
    Select-Object Name, Count |
    Sort-Object Count -Descending |
    Format-Table

# Extraire les activités de modification des permissions
$permLogs = Get-PowerBIActivityEvent `
    -StartDateTime "2026-04-27" `
    -EndDateTime "2026-05-27" `
    -ActivityType "ChangeWorkspaceAccess"

$permLogs | Export-Csv -Path "permission_changes.csv" -NoTypeInformation
```

### Analyser la consommation avec la Capacity Metrics App

La **Fabric Capacity Metrics App** fournit une analyse détaillée de la consommation :

**Installer l'application :**
1. Accédez à la **Capacity Metrics App** dans le portail Fabric (ou AppSource)
2. Installez l'application dans un workspace
3. Connectez-vous à votre capacité Fabric

**Métriques clés à surveiller :**

```
Vue Timepoint (par intervalle de 30 secondes) :
┌────────────────────────────────────────────────┐
│ Consommation CU sur 30 sec                     │
│                                                │
│  64 CU ┤                        ████           │
│        │              ██████████████           │
│  32 CU ┤     ██████████████████████████       │
│        │ ████████████████████████████████     │
│   0 CU └─────────────────────────────────►    │
│        8:00              12:00           18:00 │
│                                                │
│  Throttling déclenché : 14:30 - 15:00          │
└────────────────────────────────────────────────┘

Vue Multi-metric (tendances sur 7 jours) :
- CU Active Usage (utilisation réelle)
- CU Background (traitements en arrière-plan)
- Memory (consommation mémoire)
- Throttling (durée et fréquence)

Vue Item (détail par workspace/élément) :
- Top 10 des workspaces les plus consommateurs
- Top 10 des éléments les plus coûteux
```

**Actions basées sur les métriques :**

| Observation | Action recommandée |
|-------------|-------------------|
| Throttling régulier entre 9h-11h | Passer de F64 à F128 (scale up) ou décaler des traitements |
| Capacité peu utilisée (< 20% CU) | Réduire la capacité (scale down) pour économiser |
| Un seul workspace consomme 80% des CU | Identifier les traitements gourmands et optimiser |
| Throttling uniquement lors des actualisations nocturnes | Configurer une actualisation progressive ou optimiser les modèles |

## 9. Administration avancée — Workspaces "My Workspace" et espaces personnels

### Gouverner "My Workspace"

Chaque utilisateur Fabric dispose d'un espace de travail personnel **"My Workspace"**. Ces workspaces sont privés et ne peuvent pas être assignés à une capacité par défaut. Ils posent des défis de gouvernance :

- Les utilisateurs peuvent y stocker des données sensibles sans supervision
- Le contenu n'est pas visible pour les administrateurs par défaut
- Si l'utilisateur quitte l'organisation, le contenu peut être perdu

**Options de gouvernance pour "My Workspace" :**

1. **Auditer les activités** dans "My Workspace" via les journaux d'audit
2. **Configurer des politiques DLP** (Data Loss Prevention) via Microsoft Purview pour détecter les données sensibles
3. **Activer le paramètre** "Administrateurs peuvent accéder aux espaces de travail personnels des utilisateurs" dans les tenant settings (pour les cas d'urgence)

### Récupérer le contenu d'un utilisateur ayant quitté l'organisation

Lorsqu'un utilisateur quitte l'organisation, son "My Workspace" et son contenu risquent d'être perdus. Pour récupérer le contenu :

```powershell
# Lister les éléments d'un My Workspace spécifique
Connect-PowerBIServiceAccount

# Obtenir le workspace de l'utilisateur qui a quitté
$userId = "ancien-employe-id"
$workspace = Get-PowerBIWorkspace -Filter "type eq 'PersonalGroup'" |
    Where-Object { $_.Users.Identifier -eq $userId }

# Prendre le contrôle du workspace (option admin)
# via le portail d'administration → Workspaces → Mon espace de travail de [utilisateur]
```

## 10. PowerShell et API REST pour l'administration

### Module PowerShell MicrosoftPowerBIMgmt

Le module PowerShell `MicrosoftPowerBIMgmt` est l'outil principal pour automatiser l'administration Fabric :

```powershell
# Installer le module
Install-Module -Name MicrosoftPowerBIMgmt -Force -AllowClobber

# Se connecter (interactif ou avec Service Principal)
Connect-PowerBIServiceAccount

# Lister tous les workspaces du tenant
Get-PowerBIWorkspace -All -Scope Organization |
    Select-Object Id, Name, State, IsOnDedicatedCapacity, CapacityId |
    Format-Table

# Lister les workspaces sans capacité dédiée (à risque)
Get-PowerBIWorkspace -All -Scope Organization |
    Where-Object { -not $_.IsOnDedicatedCapacity } |
    Select-Object Name, State

# Assigner un workspace à une capacité via PowerShell
Set-PowerBIWorkspace `
    -Id "workspace-guid" `
    -CapacityId "capacity-guid"

# Lister les membres d'un workspace
Get-PowerBIWorkspaceUser -Id "workspace-guid" |
    Select-Object Identifier, UserPrincipalName, AccessRight

# Exporter la liste complète des workspaces en CSV
Get-PowerBIWorkspace -All -Scope Organization |
    Export-Csv -Path "fabric_workspaces_inventory.csv" -NoTypeInformation
```

### API REST d'administration Fabric

Les **API REST Fabric** permettent des opérations d'administration avancées :

**Lister les capacités via l'API REST :**

```powershell
$token = (Connect-PowerBIServiceAccount | Select-Object -ExpandProperty AccessToken)
$headers = @{ Authorization = "Bearer $token" }

# Lister toutes les capacités
$capacities = Invoke-RestMethod `
    -Uri "https://api.fabric.microsoft.com/v1/capacities" `
    -Headers $headers

$capacities.value | Select-Object displayName, sku, region, state |
    Format-Table
```

**Inventaire complet des workspaces :**

```powershell
# Script d'inventaire complet pour audit
$allWorkspaces = @()
$skip = 0
$top = 100

do {
    $batch = Invoke-RestMethod `
        -Uri "https://api.powerbi.com/v1.0/myorg/admin/groups?`$top=$top&`$skip=$skip" `
        -Headers $headers

    $allWorkspaces += $batch.value
    $skip += $top
} while ($batch.value.Count -eq $top)

# Exporter
$allWorkspaces | Select-Object id, name, state, type, capacityId |
    Export-Csv -Path "workspace_inventory_$(Get-Date -Format 'yyyyMMdd').csv" -NoTypeInformation

Write-Output "Total workspaces : $($allWorkspaces.Count)"
```

## 11. Vérification des connaissances

**Question 1 :** Un utilisateur a besoin de gérer les paramètres d'une capacité Fabric spécifique mais ne doit pas pouvoir modifier les paramètres du tenant global. Quel rôle lui assignez-vous ?

A) Administrateur Fabric
B) Administrateur Power Platform
C) Administrateur de capacité
D) Administrateur de workspace

**Réponse correcte : C**
*Le rôle d'administrateur de capacité permet de gérer une capacité spécifique (mise à l'échelle, suspension, attribution de workspaces) sans donner accès aux paramètres globaux du tenant. C'est le principe du moindre privilège.*

---

**Question 2 :** Votre organisation remarque que des coûts Fabric élevés sont générés la nuit alors qu'aucun utilisateur ne travaille. Quelle est la solution la plus efficace pour réduire les coûts ?

A) Réduire le SKU de la capacité en permanence
B) Configurer un Azure Automation Runbook pour suspendre la capacité le soir et la reprendre le matin
C) Supprimer tous les workspaces non critiques
D) Désactiver toutes les actualisations planifiées nocturnes

**Réponse correcte : B**
*La suspension programmée de la capacité Fabric pendant les heures creuses (nuits, week-ends) est la solution optimale. La capacité ne consomme pas de CU lorsqu'elle est suspendue, réduisant significativement la facture Azure. Azure Automation peut automatiser cette tâche avec un planning.*

---

**Question 3 :** En tant qu'administrateur Fabric, vous constatez que des workspaces se créent de manière non contrôlée. Quelle action effectuez-vous dans les tenant settings pour y remédier ?

A) Désactiver complètement la création de workspaces pour tous les utilisateurs
B) Restreindre la création de workspaces à des groupes de sécurité approuvés uniquement
C) Supprimer régulièrement les workspaces non autorisés
D) Activer l'audit de la création de workspaces

**Réponse correcte : B**
*Dans les tenant settings, le paramètre "Créer des espaces de travail" peut être restreint à des groupes de sécurité spécifiques. Ainsi, seuls les membres du groupe autorisé (ex : équipes IT) peuvent créer des workspaces, empêchant la prolifération non contrôlée.*

---

**Question 4 :** Vous souhaitez que chaque domaine métier (Finance, Marketing, RH) soit géré par son propre équipe data sans que les administrateurs IT centraux soient impliqués dans chaque décision. Quelle fonctionnalité Fabric utilisez-vous ?

A) Des workspaces séparés par domaine avec des admins workspace dédiés
B) Des capacités Fabric séparées par domaine
C) Des domaines Fabric avec des administrateurs de domaine dédiés
D) Des paramètres tenant configurés par groupe de sécurité

**Réponse correcte : C**
*Les domaines Fabric permettent de regrouper des workspaces par fonction métier et d'assigner des administrateurs de domaine qui peuvent gérer leurs workspaces de manière autonome. L'administrateur Fabric central définit les règles globales tandis que les experts métier gèrent leurs domaines.*

---

**Question 5 :** Lors de l'analyse de la Capacity Metrics App, vous constatez que la capacité F64 est en throttling tous les jours de 14h à 16h. Quelles sont les deux actions appropriées ?

A) Ignorer le throttling car il est temporaire
B) Passer à une capacité F128 (scale up permanent) OU optimiser les traitements de 14h-16h pour les décaler
C) Supprimer les workspaces qui consomment le plus
D) Désactiver le throttling dans les paramètres tenant

**Réponse correcte : B**
*Deux approches complémentaires : (1) scale up vers F128 si le budget le permet, résolvant le problème immédiatement ; (2) analyser quels traitements causent le pic et les décaler à des heures creuses ou les optimiser. La combinaison des deux est idéale.*

## Résumé

Dans ce module, vous avez appris à administrer un environnement Microsoft Fabric :

- **L'architecture Fabric** s'articule en Tenant → Capacités → Domaines → Workspaces. Chaque niveau peut avoir ses propres administrateurs délégués.
- **Les rôles d'administrateur** (Fabric Admin, Capacity Admin, Domain Admin, Workspace Admin) permettent de distribuer les responsabilités selon le principe du moindre privilège.
- **Le portail d'administration** centralise toutes les configurations : paramètres tenant, capacités, workspaces, journaux d'audit.
- **Les Tenant Settings** permettent de contrôler les fonctionnalités disponibles pour l'organisation — plus de 200 paramètres organisés par catégorie.
- **La gestion des capacités** inclut la création de capacités Fabric dans Azure, la mise à l'échelle (scale up/down), et la suspension pour optimiser les coûts.
- **Les domaines** organisent les workspaces par fonction métier et permettent une gouvernance délégée à des experts métier.
- **Les licences** Fabric combinent des licences de capacité (achetées dans Azure) et des licences par utilisateur (Microsoft 365).
- **Les outils de surveillance** incluent : Monitor Hub (activités), Capacity Metrics App (consommation CU), Admin Monitoring Workspace (adoption), et journaux d'audit (conformité).
- **PowerShell et les API REST** permettent d'automatiser les tâches d'administration et d'effectuer des inventaires complets du tenant.
