## 1. L'éditeur de requêtes SQL dans Fabric

### Présentation de l'interface

L'éditeur de requêtes SQL de Microsoft Fabric est un environnement de développement intégré (IDE) web, disponible directement dans le navigateur. Il offre :

- **IntelliSense** : complétion automatique des noms de tables, colonnes et mots-clés T-SQL
- **Mise en évidence syntaxique** : colorisation du code SQL pour améliorer la lisibilité
- **Validation côté client** : détection des erreurs de syntaxe avant exécution
- **Multi-onglets** : possibilité d'ouvrir plusieurs requêtes en parallèle
- **Sauvegarde** : enregistrement des requêtes comme **SQL Query** dans l'espace de travail
- **Partage** : partage des requêtes SQL avec d'autres membres de l'équipe

### Fonctionnalités avancées de l'éditeur

**Exécution partielle** : sélectionner une portion du code et appuyer sur F5 ou cliquer sur Run pour exécuter uniquement la sélection — utile pour tester des sous-requêtes.

**Plan d'exécution** : afficher le plan d'exécution estimé ou réel pour identifier les goulots d'étranglement de performance.

**Résultats** : les résultats s'affichent dans un volet inférieur avec :
- Pagination pour les grands ensembles de résultats
- Téléchargement en CSV ou Excel
- Visualisation rapide sous forme de graphique

**Raccourcis clavier utiles :**
- `Ctrl + Shift + M` : paramètres de modèle
- `Ctrl + K + C` : commenter la sélection
- `Ctrl + K + U` : décommenter la sélection
- `F5` ou `Ctrl + Enter` : exécuter la requête ou la sélection

## 2. Requêtes analytiques T-SQL avancées

### Requêtes d'agrégation fondamentales

Les requêtes analytiques d'un data warehouse impliquent quasi-systématiquement des agrégations sur des faits, groupées par des attributs de dimensions :

```sql
-- Analyse des revenus par mois et par mode de transport
-- (exemple avec le warehouse de taxis du lab)
SELECT
    d.MonthName                             AS Mois,
    COUNT(*)                                AS NombreTrips,
    SUM(t.TotalAmount)                      AS RevenuTotal,
    AVG(t.TotalAmount)                      AS RevenuMoyen,
    MIN(t.TotalAmount)                      AS RevenuMinimum,
    MAX(t.TotalAmount)                      AS RevenuMaximum,
    ROUND(AVG(t.TripDurationSeconds)/60.0, 1) AS DureeMoyenne_Min,
    ROUND(AVG(t.TripDistanceMiles), 2)      AS DistanceMoyenne_Miles
FROM dbo.Trip AS t
JOIN dbo.[Date] AS d ON t.DateID = d.DateID
GROUP BY d.MonthName
ORDER BY MIN(d.DateID);
```

### JOIN multi-tables avec filtres complexes

```sql
-- Top 10 villes de destination avec filtres de qualité de données
SELECT TOP 10
    g.City                              AS VilleDestination,
    COUNT(*)                            AS NombreTrips,
    ROUND(SUM(t.TotalAmount), 2)        AS RevenuTotal,
    ROUND(AVG(t.TripDurationSeconds)/60.0, 1) AS DureeMoyenne_Min,
    ROUND(AVG(t.TripDistanceMiles), 2)  AS DistanceMoyenne_Miles,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 2) AS PourcentageDuTotal
FROM dbo.Trip AS t
JOIN dbo.Geography AS g
    ON t.DropoffGeographyID = g.GeographyID
WHERE
    t.TripDurationSeconds BETWEEN 60 AND 7200   -- Entre 1 min et 2 heures
    AND t.TripDistanceMiles BETWEEN 0.1 AND 50  -- Entre 0.1 et 50 miles
    AND t.TotalAmount > 0                        -- Montant positif uniquement
GROUP BY g.City
ORDER BY NombreTrips DESC;
```

### Requêtes par jour de semaine avec comparaisons

```sql
-- Performance par jour de semaine avec indicateurs d'efficacité
SELECT
    d.DayName                                               AS JourSemaine,
    COUNT(*)                                                AS NombreTrips,
    ROUND(AVG(t.TripDurationSeconds) / 60.0, 1)            AS DureeMoyenne_Min,
    ROUND(AVG(t.TripDistanceMiles), 2)                      AS DistanceMoyenne_Miles,
    ROUND(AVG(t.TotalAmount), 2)                            AS MontantMoyen,
    -- Vitesse moyenne approximative (miles/heure)
    ROUND(
        AVG(t.TripDistanceMiles) /
        NULLIF(AVG(t.TripDurationSeconds) / 3600.0, 0),
        1
    )                                                       AS VitesseMoyenne_MPH,
    -- Classement par nombre de trips
    RANK() OVER (ORDER BY COUNT(*) DESC)                    AS Classement
FROM dbo.Trip AS t
JOIN dbo.[Date] AS d ON t.DateID = d.DateID
GROUP BY d.DayName
ORDER BY NombreTrips DESC;
```

## 3. Vérification de la cohérence des données

La vérification de la cohérence des données est une étape critique avant toute analyse. Elle permet de détecter les anomalies qui pourraient fausser les résultats.

### Vérifications standards de qualité

```sql
-- 1. Vérifier les trips avec une durée anormalement longue (> 24 heures)
SELECT COUNT(*) AS TripsAnomalementLongs
FROM dbo.Trip
WHERE TripDurationSeconds > 86400;  -- 86400 secondes = 24 heures

-- 2. Vérifier les trips avec une durée négative (erreur de données)
SELECT COUNT(*) AS TripsAvecDureeNegative
FROM dbo.Trip
WHERE TripDurationSeconds < 0;

-- 3. Vérifier les montants nuls ou négatifs
SELECT COUNT(*) AS TripsAvecMontantInvalide
FROM dbo.Trip
WHERE TotalAmount <= 0;

-- 4. Vérifier les orphelins (faits sans dimension correspondante)
SELECT COUNT(*) AS FactsSansDate
FROM dbo.Trip t
LEFT JOIN dbo.[Date] d ON t.DateID = d.DateID
WHERE d.DateID IS NULL;

SELECT COUNT(*) AS FactsSansGeographie
FROM dbo.Trip t
LEFT JOIN dbo.Geography g ON t.DropoffGeographyID = g.GeographyID
WHERE g.GeographyID IS NULL;

-- 5. Rapport complet de qualité des données
SELECT
    'TotalTrips'            AS Indicateur, COUNT(*) AS Valeur
FROM dbo.Trip
UNION ALL
SELECT 'DuréeNégative',     COUNT(*) FROM dbo.Trip WHERE TripDurationSeconds < 0
UNION ALL
SELECT 'DuréeExcessive',    COUNT(*) FROM dbo.Trip WHERE TripDurationSeconds > 86400
UNION ALL
SELECT 'MontantNul',        COUNT(*) FROM dbo.Trip WHERE TotalAmount = 0
UNION ALL
SELECT 'MontantNégatif',    COUNT(*) FROM dbo.Trip WHERE TotalAmount < 0
UNION ALL
SELECT 'DistanceNégative',  COUNT(*) FROM dbo.Trip WHERE TripDistanceMiles < 0
UNION ALL
SELECT 'SansDonnéeGéo',     COUNT(*) FROM dbo.Trip WHERE DropoffGeographyID IS NULL
ORDER BY Indicateur;
```

### Corriger les anomalies

```sql
-- Option 1 : Supprimer les trips avec une durée négative
DELETE FROM dbo.Trip
WHERE TripDurationSeconds < 0;

-- Option 2 : Remplacer par la médiane (préserver les données)
-- Calculer la médiane de la durée
WITH Mediane AS (
    SELECT
        PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY TripDurationSeconds)
            OVER () AS MedianeDuree
    FROM dbo.Trip
    WHERE TripDurationSeconds > 0
)
UPDATE t
SET t.TripDurationSeconds = (SELECT TOP 1 MedianeDuree FROM Mediane)
FROM dbo.Trip t
WHERE t.TripDurationSeconds < 0;

-- Option 3 : Marquer comme invalides sans supprimer
ALTER TABLE dbo.Trip ADD IsValidData BIT DEFAULT 1;

UPDATE dbo.Trip
SET IsValidData = 0
WHERE TripDurationSeconds < 0
   OR TotalAmount < 0
   OR TripDistanceMiles < 0;

-- Toujours filtrer sur IsValidData = 1 dans les analyses
SELECT * FROM dbo.Trip WHERE IsValidData = 1;
```

## 4. Fonctions de fenêtrage (Window Functions)

Les fonctions de fenêtrage sont particulièrement puissantes pour les analyses comparatives dans un data warehouse car elles permettent de calculer des valeurs agrégées sans GROUP BY, en maintenant le détail des lignes individuelles.

### RANK, DENSE_RANK et ROW_NUMBER

```sql
-- Classement des villes par revenu avec différents types de rang
SELECT
    g.City,
    ROUND(SUM(t.TotalAmount), 2)    AS RevenuTotal,
    COUNT(*)                         AS NombreTrips,
    -- RANK : laisse des trous en cas d'égalité (1, 2, 2, 4...)
    RANK()          OVER (ORDER BY SUM(t.TotalAmount) DESC) AS RangAvecTrous,
    -- DENSE_RANK : pas de trous (1, 2, 2, 3...)
    DENSE_RANK()    OVER (ORDER BY SUM(t.TotalAmount) DESC) AS RangSansTrous,
    -- ROW_NUMBER : numérotation unique même en cas d'égalité (1, 2, 3, 4...)
    ROW_NUMBER()    OVER (ORDER BY SUM(t.TotalAmount) DESC, g.City) AS NumeroLigne
FROM dbo.Trip t
JOIN dbo.Geography g ON t.DropoffGeographyID = g.GeographyID
GROUP BY g.City
ORDER BY RevenuTotal DESC;
```

### SUM et AVG cumulatifs (Running Totals)

```sql
-- Revenus cumulatifs mois par mois
SELECT
    d.Year,
    d.Month,
    d.MonthName,
    ROUND(SUM(t.TotalAmount), 2)    AS RevenuMensuel,
    -- Total cumulatif depuis le début de l'année
    ROUND(
        SUM(SUM(t.TotalAmount)) OVER (
            PARTITION BY d.Year
            ORDER BY d.Month
            ROWS UNBOUNDED PRECEDING
        ),
        2
    )                               AS RevenuCumulatif,
    -- Moyenne glissante sur 3 mois
    ROUND(
        AVG(SUM(t.TotalAmount)) OVER (
            PARTITION BY d.Year
            ORDER BY d.Month
            ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
        ),
        2
    )                               AS MoyenneGlissante3Mois
FROM dbo.Trip t
JOIN dbo.[Date] d ON t.DateID = d.DateID
GROUP BY d.Year, d.Month, d.MonthName
ORDER BY d.Year, d.Month;
```

### LEAD et LAG pour les comparaisons temporelles

```sql
-- Comparaison des revenus avec le mois précédent et le mois suivant
SELECT
    d.Year,
    d.Month,
    d.MonthName,
    ROUND(SUM(t.TotalAmount), 2)    AS RevenuMensuel,
    -- Mois précédent
    ROUND(LAG(SUM(t.TotalAmount), 1) OVER (
        PARTITION BY d.Year ORDER BY d.Month
    ), 2)                           AS RevenuMoisPrecedent,
    -- Mois suivant
    ROUND(LEAD(SUM(t.TotalAmount), 1) OVER (
        PARTITION BY d.Year ORDER BY d.Month
    ), 2)                           AS RevenuMoisSuivant,
    -- Variation en % par rapport au mois précédent
    ROUND(
        100.0 * (
            SUM(t.TotalAmount) -
            LAG(SUM(t.TotalAmount), 1) OVER (PARTITION BY d.Year ORDER BY d.Month)
        ) / NULLIF(
            LAG(SUM(t.TotalAmount), 1) OVER (PARTITION BY d.Year ORDER BY d.Month),
            0
        ),
        1
    )                               AS VariationPctMoisPrecedent
FROM dbo.Trip t
JOIN dbo.[Date] d ON t.DateID = d.DateID
GROUP BY d.Year, d.Month, d.MonthName
ORDER BY d.Year, d.Month;
```

### PERCENTILE_CONT et PERCENTILE_DISC

```sql
-- Distribution statistique des montants de trips
SELECT DISTINCT
    d.MonthName,
    -- Médiane (50e percentile)
    ROUND(PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY t.TotalAmount)
        OVER (PARTITION BY d.MonthName), 2) AS MedianeMontant,
    -- 25e percentile (Q1)
    ROUND(PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY t.TotalAmount)
        OVER (PARTITION BY d.MonthName), 2) AS Q1Montant,
    -- 75e percentile (Q3)
    ROUND(PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY t.TotalAmount)
        OVER (PARTITION BY d.MonthName), 2) AS Q3Montant
FROM dbo.Trip t
JOIN dbo.[Date] d ON t.DateID = d.DateID
WHERE t.TotalAmount > 0
ORDER BY MIN(d.DateID);
```

## 5. CTE (Common Table Expressions) et sous-requêtes avancées

### CTE récursives pour les hiérarchies

```sql
-- Analyse des ventes avec CTE multiples enchaînées
WITH
-- CTE 1 : Ventes mensuelles de base
VentesBase AS (
    SELECT
        d.Year,
        d.Month,
        d.MonthName,
        COUNT(*)                AS NombreTrips,
        SUM(t.TotalAmount)      AS RevenuTotal
    FROM dbo.Trip t
    JOIN dbo.[Date] d ON t.DateID = d.DateID
    WHERE t.TotalAmount > 0
    GROUP BY d.Year, d.Month, d.MonthName
),
-- CTE 2 : Statistiques globales pour comparaison
StatistiquesGlobales AS (
    SELECT
        AVG(RevenuTotal)            AS MoyenneGlobale,
        MAX(RevenuTotal)            AS MaxGlobal,
        MIN(RevenuTotal)            AS MinGlobal
    FROM VentesBase
),
-- CTE 3 : Enrichissement avec comparaison
VentesEnrichies AS (
    SELECT
        v.*,
        s.MoyenneGlobale,
        ROUND(v.RevenuTotal - s.MoyenneGlobale, 2)  AS EcartALaMoyenne,
        CASE
            WHEN v.RevenuTotal > s.MoyenneGlobale * 1.1 THEN 'Au-dessus'
            WHEN v.RevenuTotal < s.MoyenneGlobale * 0.9 THEN 'En-dessous'
            ELSE 'Normal'
        END                                         AS PerformanceRelative
    FROM VentesBase v
    CROSS JOIN StatistiquesGlobales s
)
SELECT *
FROM VentesEnrichies
ORDER BY Year, Month;
```

### Sous-requêtes corrélées

```sql
-- Trips dont le montant est supérieur à la moyenne de leur ville de destination
SELECT
    t.TripID,
    g.City,
    t.TotalAmount,
    (SELECT AVG(t2.TotalAmount)
     FROM dbo.Trip t2
     JOIN dbo.Geography g2 ON t2.DropoffGeographyID = g2.GeographyID
     WHERE g2.City = g.City) AS MoyenneVille,
    t.TotalAmount - (SELECT AVG(t2.TotalAmount)
                     FROM dbo.Trip t2
                     JOIN dbo.Geography g2 ON t2.DropoffGeographyID = g2.GeographyID
                     WHERE g2.City = g.City) AS EcartALaMoyenneVille
FROM dbo.Trip t
JOIN dbo.Geography g ON t.DropoffGeographyID = g.GeographyID
WHERE t.TotalAmount > (
    SELECT AVG(t2.TotalAmount)
    FROM dbo.Trip t2
    JOIN dbo.Geography g2 ON t2.DropoffGeographyID = g2.GeographyID
    WHERE g2.City = g.City
)
ORDER BY g.City, t.TotalAmount DESC;
```

## 6. Créer et utiliser des vues

### Créer des vues pour les besoins de reporting

Les vues encapsulent la logique de requête complexe et offrent une interface simplifiée aux utilisateurs finaux et aux rapports Power BI :

```sql
-- Vue de reporting : statistiques mensuelles de trips
CREATE VIEW dbo.vw_StatistiquesMensuelles
AS
SELECT
    d.Year                                          AS Annee,
    d.Month                                         AS Mois,
    d.MonthName                                     AS NomMois,
    COUNT(*)                                        AS NombreTrips,
    ROUND(SUM(t.TotalAmount), 2)                    AS RevenuTotal,
    ROUND(AVG(t.TotalAmount), 2)                    AS RevenuMoyen,
    ROUND(AVG(t.TripDurationSeconds) / 60.0, 1)     AS DureeMoyenne_Min,
    ROUND(AVG(t.TripDistanceMiles), 2)              AS DistanceMoyenne_Miles
FROM dbo.Trip AS t
JOIN dbo.[Date] AS d ON t.DateID = d.DateID
WHERE t.TotalAmount > 0
    AND t.TripDurationSeconds > 0
GROUP BY d.Year, d.Month, d.MonthName;
GO

-- Vue filtrée pour janvier uniquement (exemple du lab)
CREATE VIEW dbo.vw_JanvierTrips
AS
SELECT
    d.DayName                                       AS JourSemaine,
    ROUND(AVG(t.TripDurationSeconds) / 60.0, 1)     AS DureeMoyenne_Min,
    ROUND(AVG(t.TripDistanceMiles), 2)              AS DistanceMoyenne_Miles
FROM dbo.Trip AS t
JOIN dbo.[Date] AS d ON t.DateID = d.DateID
WHERE d.Month = '01'
GROUP BY d.DayName;
GO

-- Utilisation des vues
SELECT * FROM dbo.vw_StatistiquesMensuelles ORDER BY Annee, Mois;
SELECT * FROM dbo.vw_JanvierTrips ORDER BY DureeMoyenne_Min DESC;
```

### Enregistrer une requête comme vue directement depuis l'éditeur

Dans l'interface Fabric, il est possible de créer une vue directement depuis l'éditeur SQL sans écrire l'instruction `CREATE VIEW` manuellement :

1. Écrire la requête SELECT dans l'éditeur
2. Sélectionner tout le texte de la requête SELECT
3. Cliquer sur le bouton **Enregistrer comme vue** (à côté du bouton Run)
4. Nommer la vue dans la boîte de dialogue
5. La vue apparaît dans l'Explorateur sous Schémas > dbo > Vues

## 7. L'éditeur de requêtes visuel

### Présentation et cas d'usage

L'éditeur de requêtes visuel (Visual Query Editor) est une interface graphique sans code permettant de construire des requêtes en faisant glisser des tables sur un canvas. C'est l'outil idéal pour :

- Les analystes non-développeurs qui souhaitent explorer les données
- La découverte rapide des données disponibles
- Les requêtes simples de filtrage et d'agrégation
- La création de sous-ensembles de données pour export Excel

### Workflow dans l'éditeur visuel

1. **Accéder à l'éditeur** : Home > Nouvelle requête SQL > Nouvelle requête visuelle
2. **Ajouter des tables** : faire glisser les tables depuis l'Explorateur vers le canvas
3. **Fusionner des tables** : cliquer sur **(+)** sur une table et sélectionner "Fusionner les requêtes"
4. **Configurer la jointure** :
   - Table gauche : FactSalesOrder / Trip
   - Table droite : dimension souhaitée
   - Colonne de jointure : clé étrangère correspondante
   - Type de jointure : Gauche externe (Left Outer) le plus courant
5. **Développer les colonnes** : cliquer sur la flèche de la colonne fusion pour sélectionner les champs souhaités
6. **Appliquer des transformations** :
   - Filtrer les lignes
   - Grouper et agréger
   - Trier
   - Supprimer des colonnes
7. **Analyser** : utiliser "Visualiser les résultats" ou "Télécharger en Excel"

### Limitations de l'éditeur visuel

| Fonctionnalité | Éditeur visuel | Éditeur SQL |
|---------------|----------------|-------------|
| JOIN multi-tables | Limité (fusions séquentielles) | Complet |
| Fonctions de fenêtrage | Non supporté | Complet |
| CTE et sous-requêtes | Non supporté | Complet |
| Procédures stockées | Non supporté | Complet |
| Modifications de schéma (DDL) | Non supporté | Complet |
| Filtres complexes | Basique | Illimité |
| Performance sur grands volumes | Bonne | Excellente |
| Courbe d'apprentissage | Très faible | Modérée |

## 8. Connexion depuis des outils externes

### SQL Server Management Studio (SSMS)

SSMS est l'IDE SQL de référence pour les professionnels. Pour se connecter à un Data Warehouse Fabric depuis SSMS :

1. Dans le warehouse Fabric, copier la **chaîne de connexion SQL** depuis les paramètres
   - Format : `xxxx.datawarehouse.fabric.microsoft.com`
2. Ouvrir SSMS et cliquer sur **Nouvelle connexion**
3. Configurer :
   - **Serveur** : chaîne de connexion copiée
   - **Authentification** : Microsoft Entra ID - Universal avec MFA
   - **Base de données** : nom du warehouse
4. Se connecter et naviguer dans l'Explorateur d'objets

### Azure Data Studio

Azure Data Studio est une alternative cross-platform (Windows, macOS, Linux) :

1. Ajouter une nouvelle connexion
2. Type de serveur : Microsoft SQL Server
3. Serveur : chaîne de connexion du warehouse
4. Authentification : Microsoft Entra ID
5. Le warehouse apparaît comme une base de données SQL standard

### Connexion via ODBC / JDBC

Pour les applications personnalisées, les pilotes ODBC et JDBC Microsoft SQL Server fonctionnent directement avec le Data Warehouse Fabric :

```
# Exemple de chaîne de connexion ODBC
Driver={ODBC Driver 18 for SQL Server};
Server=xxxx.datawarehouse.fabric.microsoft.com;
Database=MonWarehouse;
Authentication=ActiveDirectoryInteractive;
```

### Power BI Desktop en DirectLake

Power BI Desktop se connecte automatiquement au modèle sémantique par défaut du warehouse via DirectLake, offrant des performances optimales sans duplication de données.

## Vérification des connaissances

**Question 1.** Quelle est la différence entre `RANK()` et `DENSE_RANK()` dans une fonction de fenêtrage T-SQL ?

A) Il n'y a aucune différence, ce sont des synonymes  
B) `RANK()` laisse des trous en cas d'égalité (ex: 1, 2, 2, 4) ; `DENSE_RANK()` n'en laisse pas (ex: 1, 2, 2, 3)  
C) `DENSE_RANK()` est plus rapide que `RANK()` sur les grands volumes  
D) `RANK()` s'applique aux colonnes numériques uniquement  

**Réponse correcte : B** — `RANK()` saute les rangs en cas d'égalité (deux lignes ex aequo en position 2 : la suivante est en position 4). `DENSE_RANK()` ne crée pas de trous (la suivante serait en position 3).

**Question 2.** Vous souhaitez calculer le revenu cumulatif mois par mois dans une même année. Quelle syntaxe de fenêtrage utilisez-vous ?

A) `GROUP BY ROLLUP(d.Year, d.Month)`  
B) `SUM(revenue) OVER (PARTITION BY Year ORDER BY Month ROWS UNBOUNDED PRECEDING)`  
C) `SUM(revenue) OVER (ORDER BY Month)`  
D) `RUNNING_TOTAL(revenue) GROUP BY Month`  

**Réponse correcte : B** — La clause `ROWS UNBOUNDED PRECEDING` dans une fonction SUM OVER calcule le total cumulatif depuis le début de la partition jusqu'à la ligne courante. `PARTITION BY Year` repart à zéro pour chaque année.

**Question 3.** Quelle méthode d'authentification est recommandée pour connecter SQL Server Management Studio à un Data Warehouse Fabric ?

A) Authentification SQL Server (login/password)  
B) Windows Authentication  
C) Microsoft Entra ID - Universal avec MFA  
D) Clé API Fabric  

**Réponse correcte : C** — Les Data Warehouses Fabric utilisent Microsoft Entra ID (anciennement Azure Active Directory) pour l'authentification. L'option "Universal avec MFA" dans SSMS supporte l'authentification multifacteur requise par les organisations.

**Question 4.** Vous souhaitez créer une vue pour encapsuler une requête de reporting complexe. Quelle affirmation est correcte concernant les vues dans un Data Warehouse Fabric ?

A) Les vues ne peuvent pas contenir de JOIN entre plusieurs tables  
B) Une vue doit inclure une clause ORDER BY pour être valide  
C) Les vues encapsulent la logique SQL et peuvent être utilisées directement par Power BI et SSMS  
D) Les vues dans Fabric sont toujours matérialisées (les données sont stockées physiquement)  

**Réponse correcte : C** — Les vues dans Fabric sont des objets SQL standards qui encapsulent la logique de requête. Elles sont accessibles comme des tables depuis tous les outils compatibles SQL (Power BI, SSMS, Azure Data Studio, etc.) et sont des vues logiques (non matérialisées par défaut).

**Question 5.** L'éditeur de requêtes visuel de Fabric est particulièrement adapté pour quel type d'utilisation ?

A) Créer des procédures stockées complexes avec gestion des erreurs  
B) Exécuter des scripts DDL de création de tables et de schémas  
C) Explorer et joindre des tables de manière visuelle sans écrire de T-SQL, pour des analyses simples  
D) Optimiser les plans d'exécution des requêtes analytiques  

**Réponse correcte : C** — L'éditeur visuel est conçu pour les analystes non-développeurs qui souhaitent explorer et joindre des tables graphiquement. Il ne supporte pas les fonctions avancées comme les CTE, les fenêtres ou les procédures stockées.

## Résumé

Dans ce module, vous avez maîtrisé les techniques d'interrogation d'un Data Warehouse Fabric :

- L'**éditeur de requêtes SQL** intégré offre IntelliSense, multi-onglets et visualisation des résultats
- Les **requêtes analytiques T-SQL** avancées (agrégations, JOIN multi-tables, conditions complexes) sont la base de l'exploitation d'un DW
- La **vérification de cohérence** est une étape obligatoire avant toute analyse : détecter les durées négatives, les montants nuls, les orphelins
- Les **fonctions de fenêtrage** (RANK, SUM OVER, LAG/LEAD, PERCENTILE) permettent des analyses comparatives puissantes sans réduire la granularité des données
- Les **vues** encapsulent la logique de reporting et offrent une interface simplifiée aux utilisateurs finaux et à Power BI
- L'**éditeur visuel** démocratise l'accès aux données pour les non-développeurs
- SSMS et Azure Data Studio se connectent au warehouse via **Microsoft Entra ID**
