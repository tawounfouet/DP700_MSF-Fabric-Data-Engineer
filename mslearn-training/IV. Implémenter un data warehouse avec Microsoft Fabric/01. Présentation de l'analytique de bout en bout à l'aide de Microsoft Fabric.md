## 1. Introduction à Microsoft Fabric

### Qu'est-ce que Microsoft Fabric ?

Microsoft Fabric est une plateforme analytique de bout en bout unifiée, proposée sous forme de **Software-as-a-Service (SaaS)**. Annoncée en mai 2023 et disponible en disponibilité générale depuis novembre 2023, Fabric rassemble sous un même toit tous les outils nécessaires au cycle de vie complet de la donnée : ingestion, stockage, transformation, modélisation et visualisation.

Avant Fabric, les équipes data devaient jongler avec de nombreux services distincts : Azure Data Factory pour les pipelines ETL, Azure Synapse Analytics pour le data warehouse, Azure Databricks pour le traitement Spark, et Power BI pour la visualisation. Chaque service avait ses propres mécanismes d'authentification, sa propre facturation, et ses propres connecteurs. Fabric résout ce problème de fragmentation en proposant une expérience cohérente et intégrée.

La valeur principale de Fabric repose sur trois piliers :

1. **Unification** — Un seul produit, une seule interface, une seule identité, une seule gouvernance
2. **OneLake** — Une couche de stockage partagée et unifiée basée sur Azure Data Lake Storage Gen2
3. **IA intégrée** — Copilot et d'autres capacités d'intelligence artificielle disponibles nativement dans chaque workload

### Le cycle analytique de bout en bout

Une solution analytique moderne couvre typiquement les étapes suivantes :

```
Données sources  →  Ingestion  →  Stockage brut  →  Transformation  →  Stockage analytique  →  Reporting
(ERP, SaaS, IoT)    (pipelines)    (data lake)        (ETL/ELT)          (data warehouse)       (Power BI)
```

Dans Fabric, chaque étape de ce cycle correspond à un workload spécialisé, mais tous partagent le même stockage OneLake et la même gouvernance. Un ingénieur data, un analyste et un data scientist peuvent collaborer sur les mêmes données sans copier ni déplacer quoi que ce soit.

## 2. OneLake : le fondement du stockage unifié

### Architecture d'OneLake

OneLake est l'équivalent de OneDrive pour les données analytiques d'entreprise. C'est une couche de stockage hiérarchique unique, **automatiquement provisionnée** pour chaque tenant Microsoft Fabric, sans configuration supplémentaire.

Caractéristiques clés d'OneLake :

| Caractéristique | Description |
|----------------|-------------|
| **Format ouvert** | Stockage au format Delta/Parquet, accessible via Apache Spark, T-SQL, Python |
| **Hiérarchie** | Organisation en tenant → espace de travail → éléments (lakehouses, warehouses) |
| **Zoning** | Zones Bronze / Silver / Gold ou Raw / Curated / Serving |
| **Accès unifié** | Accessible par tous les workloads Fabric sans copie de données |
| **Compatibilité ADLS Gen2** | Accessible via les API Azure Data Lake Storage Gen2 existantes |
| **Raccourcis OneLake** | Pointeurs vers des données externes (ADLS, AWS S3, Google Cloud Storage) sans déplacement |

### Lakehouses et Warehouses dans OneLake

Les deux principaux types d'éléments de stockage dans Fabric sont :

**Le Lakehouse** : un conteneur qui combine la flexibilité d'un data lake (fichiers Delta Parquet dans OneLake) avec la puissance requêtable d'un data warehouse (endpoint SQL automatique en lecture seule). Idéal pour les data engineers qui travaillent en PySpark ou SQL.

**Le Data Warehouse** : un entrepôt de données relationnel complet avec support T-SQL transactionnel (INSERT, UPDATE, DELETE), modélisation dimensionnelle, et performance optimisée pour les requêtes analytiques complexes. Idéal pour les équipes SQL traditionnelles.

```
OneLake
├── Espace de travail "Finance"
│   ├── Lakehouse "RawData"        → Bronze zone (CSV, JSON bruts)
│   ├── Lakehouse "CuratedData"    → Silver zone (Delta Parquet nettoyés)
│   └── Warehouse "FinanceDW"      → Gold zone (tables dimensionnelles)
└── Espace de travail "Marketing"
    ├── Lakehouse "MarketingData"
    └── Warehouse "MarketingDW"
```

### Raccourcis OneLake (Shortcuts)

Les raccourcis permettent de référencer des données stockées dans d'autres emplacements (autres lakehouses, ADLS Gen2, AWS S3, Google Cloud Storage, Dataverse) sans les copier physiquement. C'est un concept fondamental pour éviter la duplication des données et maintenir une source unique de vérité.

Exemple d'utilisation : une équipe marketing qui stocke ses données dans AWS S3 peut créer un raccourci OneLake pour rendre ces données accessibles directement dans Fabric, sans migration ni duplication.

## 3. Les workloads Microsoft Fabric

Fabric est organisé en **six expériences (workloads)** principales, accessibles depuis le sélecteur en bas à gauche de l'interface :

### 3.1 Data Factory

Data Factory dans Fabric hérite des capacités d'Azure Data Factory et de Power Query pour l'orchestration des pipelines d'intégration de données. Il comprend :

- **Pipelines de données** : orchestration d'activités ETL/ELT (copie, transformation, déclencheurs basés sur événements ou calendriers)
- **Dataflows Gen2** : transformation de données visuelle basée sur Power Query avec publication dans OneLake ou d'autres destinations

Cas d'usage typiques : ingestion quotidienne de données depuis un ERP SAP vers OneLake, transformation de fichiers CSV bruts en tables Delta structurées.

### 3.2 Synapse Data Engineering

Ce workload est dédié au **traitement de données à grande échelle avec Apache Spark**. Il comprend :

- **Lakehouses** : conteneurs de données combinant stockage Delta et endpoint SQL
- **Notebooks** : environnement de développement interactif pour Python, Scala, SQL et R sur Spark
- **Spark Job Definitions** : exécution planifiée de scripts Spark en production
- **Environnements** : gestion des bibliothèques et configurations Spark partagées

### 3.3 Synapse Data Warehouse

C'est le workload central de ce module. Il offre un **entrepôt de données relationnel** avec :

- Support T-SQL complet (DDL, DML, DCL)
- Modélisation dimensionnelle (tables de faits et de dimensions)
- Sécurité granulaire (RLS, CLS, Dynamic Data Masking)
- Intégration Power BI en mode DirectLake pour des rapports haute performance

### 3.4 Synapse Real-Time Intelligence

Workload dédié à **l'analytique en temps réel** sur des flux de données en mouvement :

- **Eventstream** : ingestion et routage de données en streaming (IoT Hub, Event Hubs, Kafka)
- **Eventhouse / KQL Database** : base de données analytique optimisée pour les séries temporelles et logs
- **KQL Queryset** : requêtes en Kusto Query Language (KQL)
- **Real-Time Dashboard** : tableaux de bord actualisés en quasi-temps réel

### 3.5 Power BI

L'expérience de reporting et de business intelligence de Fabric. Avec l'intégration OneLake, Power BI peut se connecter directement aux données via le mode **DirectLake** qui combine la performance du mode Import avec la fraîcheur des données du mode Direct Query, sans duplication.

### 3.6 Data Activator (Reflex)

Workload permettant de **déclencher des actions automatiques** basées sur des conditions détectées dans les données. Exemples : envoyer une alerte Teams quand le stock d'un produit passe sous un seuil, déclencher un pipeline quand une anomalie est détectée dans un flux de données.

### Tableau récapitulatif des workloads

| Workload | Rôle principal | Technologie sous-jacente | Persona cible |
|----------|---------------|--------------------------|---------------|
| Data Factory | Orchestration ETL/ELT | ADF + Power Query | Data Engineer |
| Data Engineering | Traitement Spark | Apache Spark | Data Engineer |
| Data Warehouse | SQL analytique | Synapse DW | Analyste / DBA |
| Real-Time Intelligence | Streaming analytics | Kusto / KQL | Ingénieur temps réel |
| Power BI | Reporting & BI | Power BI | Analyste / BI Dev |
| Data Activator | Actions automatisées | Reflex | Analyste / Dev |

## 4. Le modèle de capacité et les licences

### Capacités Fabric

Microsoft Fabric fonctionne sur un modèle de **capacité** : une unité de calcul partagée qui alimente tous les workloads d'un ou plusieurs espaces de travail. Les capacités sont mesurées en **Fabric Capacity Units (CU)**.

Types de capacités disponibles :

| Type | Description | Cas d'usage |
|------|-------------|-------------|
| **Trial** | 60 jours gratuits, 64 CU | Évaluation et apprentissage |
| **F-SKU (Fabric)** | De F2 à F2048 CU, facturation à la seconde | Charges de travail variables, cloud-natif |
| **P-SKU (Premium)** | De P1 à P5, mensuel/annuel | Organisations avec Power BI Premium existant |
| **Embedded (A-SKU)** | Pour les applications ISV | Déploiements embarqués |

La taille de capacité détermine le nombre d'opérations simultanées, la taille des données traitables et la vitesse d'exécution des jobs Spark. La facturation F-SKU est à la seconde, ce qui permet de mettre en pause les capacités la nuit pour réduire les coûts.

### Espaces de travail (Workspaces)

Un espace de travail est le conteneur organisationnel de Fabric. Il regroupe les éléments (lakehouses, warehouses, notebooks, pipelines, rapports) et définit les autorisations d'accès via des rôles :

- **Admin** : accès complet à l'espace de travail et ses paramètres
- **Member** : peut créer, modifier et partager des éléments
- **Contributor** : peut créer et modifier des éléments
- **Viewer** : accès en lecture seule aux éléments publiés

## 5. Gouvernance et sécurité avec Microsoft Purview

### Intégration native Purview-Fabric

Microsoft Purview est la plateforme de gouvernance des données de Microsoft. Dans Fabric, Purview est intégré nativement pour offrir :

- **Catalogue de données** : découverte et documentation automatique des éléments Fabric (tables, colonnes, pipelines)
- **Lignage des données** : traçabilité complète de l'origine à la destination, depuis l'ingestion jusqu'aux rapports
- **Étiquettes de sensibilité** : classification des données (Confidentiel, Hautement confidentiel, Public) propagée automatiquement depuis le catalogue vers Power BI
- **Protection des informations** : application des politiques de conformité (RGPD, HIPAA) sur les données Fabric
- **Audit et conformité** : journalisation de toutes les activités d'accès et de modification des données

### Hub de données OneLake

Le **Hub de données OneLake** (accessible depuis Fabric) est l'interface centralisée pour découvrir et accéder aux données de l'organisation. Il permet :

- D'explorer tous les lakehouses et warehouses accessibles
- D'identifier les tables certifiées ou promues par l'organisation
- De créer des raccourcis vers des données partagées
- De consulter les métadonnées et la documentation des datasets

## 6. Naviguer dans l'interface Microsoft Fabric

### Accès et connexion

Pour accéder à Microsoft Fabric :
1. Ouvrir [https://app.fabric.microsoft.com](https://app.fabric.microsoft.com) dans un navigateur
2. Se connecter avec un compte Microsoft organisationnel ou un compte d'essai Fabric
3. Le portail d'accueil affiche les éléments récents, les espaces de travail et les ressources d'apprentissage

### Structure de l'interface

L'interface Fabric est organisée en plusieurs zones :

- **Barre latérale gauche** : navigation vers les espaces de travail, OneLake, la création d'éléments et les paramètres
- **Sélecteur d'expérience** (en bas à gauche) : basculer entre les différents workloads (Data Engineering, Data Warehouse, etc.)
- **Zone centrale** : accueil du workload sélectionné avec les éléments récents et les accès rapides
- **Barre de recherche** : recherche globale sur tous les éléments et espaces de travail

### Créer un espace de travail

1. Dans la barre latérale gauche, cliquer sur **Espaces de travail**
2. Cliquer sur **+ Nouvel espace de travail**
3. Donner un nom unique, sélectionner le mode de licence (Trial, Premium, Fabric)
4. Optionnel : configurer la description, les contacts et les paramètres avancés
5. Cliquer sur **Appliquer**

Une fois créé, l'espace de travail est vide et prêt à accueillir des éléments de n'importe quel workload Fabric.

## 7. Comparaison Fabric vs solutions traditionnelles

| Critère | Architecture traditionnelle | Microsoft Fabric |
|---------|----------------------------|-----------------|
| **Nombre de services** | 5 à 10 services séparés | 1 plateforme unifiée |
| **Stockage** | Multiple (ADLS, SQL DW, Blob) | OneLake unique |
| **Sécurité** | Gérée service par service | Centralisée (Purview + Entra ID) |
| **Facturation** | Par service | Par capacité (CU) |
| **Mouvement de données** | Fréquent (copies entre services) | Minimal (raccourcis OneLake) |
| **Gouvernance** | Fragmentée | Intégrée nativement |
| **Courbe d'apprentissage** | Élevée | Modérée (interface unifiée) |
| **IA/Copilot** | Add-on externe | Natif dans chaque workload |

## Vérification des connaissances

**Question 1.** Qu'est-ce qu'OneLake dans Microsoft Fabric ?

A) Un service de base de données relationnelle séparé d'Azure  
B) Une couche de stockage unifiée et partagée, automatiquement provisionnée par tenant Fabric  
C) Un outil de visualisation de données intégré à Power BI  
D) Un type de pipeline ETL spécifique à Fabric  

**Réponse correcte : B** — OneLake est la fondation de stockage unique de Fabric, basée sur ADLS Gen2, partagée entre tous les workloads sans copie de données.

---

**Question 2.** Quel workload Fabric faut-il utiliser pour analyser des données en temps réel provenant de capteurs IoT ?

A) Synapse Data Engineering  
B) Data Factory  
C) Synapse Real-Time Intelligence  
D) Data Activator  

**Réponse correcte : C** — Synapse Real-Time Intelligence (avec Eventstream et Eventhouse/KQL Database) est spécialement conçu pour l'ingestion et l'analyse de données en streaming comme les flux IoT.

---

**Question 3.** Quelle est la différence principale entre un Lakehouse et un Data Warehouse dans Fabric ?

A) Le Lakehouse ne supporte que Python, le Data Warehouse ne supporte que SQL  
B) Le Lakehouse offre un endpoint SQL en lecture seule ; le Data Warehouse supporte T-SQL complet incluant INSERT/UPDATE/DELETE  
C) Le Data Warehouse ne peut pas stocker de fichiers non structurés, le Lakehouse si  
D) Il n'y a pas de différence, ce sont des synonymes dans Fabric  

**Réponse correcte : B** — Le Lakehouse expose un endpoint SQL automatique en lecture seule pour les tables Delta. Le Data Warehouse Fabric offre un T-SQL transactionnel complet avec capacité d'écriture.

---

**Question 4.** Comment Microsoft Purview s'intègre-t-il à Microsoft Fabric ?

A) Purview est un outil externe sans intégration native dans Fabric  
B) Purview gère uniquement la facturation des capacités Fabric  
C) Purview fournit le catalogue de données, le lignage, les étiquettes de sensibilité et la conformité de manière native dans Fabric  
D) Purview est utilisé uniquement pour la création de rapports Power BI  

**Réponse correcte : C** — Purview est intégré nativement dans Fabric pour la gouvernance complète : catalogage, lignage, classification, protection et audit.

---

**Question 5.** Un raccourci OneLake (Shortcut) permet de :

A) Copier des données d'une source externe vers OneLake pour améliorer les performances  
B) Référencer des données stockées ailleurs (ADLS, S3, autre lakehouse) sans les déplacer physiquement  
C) Créer des alias pour les noms de tables dans un Data Warehouse  
D) Configurer des liens entre rapports Power BI et sources de données  

**Réponse correcte : B** — Un raccourci OneLake est un pointeur logique vers des données externes. Les données ne sont pas copiées, ce qui évite la duplication et réduit les coûts de stockage.

## Résumé

Microsoft Fabric est une plateforme analytique unifiée de bout en bout qui simplifie radicalement l'architecture des solutions data modernes. Ses points clés à retenir :

- **OneLake** est la couche de stockage unique et partagée au format Delta/Parquet, fondation de tous les workloads
- Les **six workloads** (Data Factory, Data Engineering, Data Warehouse, Real-Time Intelligence, Power BI, Data Activator) couvrent tout le cycle de vie analytique
- Le **modèle de capacité** (F-SKU, P-SKU, Trial) permet une facturation flexible et mutualisée
- **Microsoft Purview** assure la gouvernance, le lignage et la conformité de manière centralisée
- Les **raccourcis OneLake** permettent d'accéder à des données externes sans duplication

Ce module pose les bases conceptuelles nécessaires pour les modules suivants qui approfondissent chaque aspect de l'implémentation d'un data warehouse dans Fabric.
