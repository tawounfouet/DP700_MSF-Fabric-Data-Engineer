## 1. Introduction à Copilot dans Fabric Data Warehouse

### Qu'est-ce que Copilot dans Fabric ?

Copilot dans Microsoft Fabric est un assistant IA intégré qui exploite les modèles de langage de grande taille (LLM) de Microsoft pour aider les utilisateurs à travailler plus efficacement avec les données. Dans le contexte du Data Warehouse, Copilot comprend le schéma de votre entrepôt et peut générer du T-SQL précis basé sur des descriptions en langage naturel.

Copilot dans le Data Warehouse Fabric se distingue par plusieurs capacités clés :

1. **Conscience du schéma** : Copilot analyse automatiquement les tables, colonnes et relations de votre warehouse pour générer du SQL contextuel
2. **Génération de SQL** : convertit des descriptions en langage naturel en requêtes T-SQL valides
3. **Explication de code** : décrit en français ce que fait une requête T-SQL complexe
4. **Correction automatique** : détecte et corrige les erreurs de syntaxe SQL
5. **Complétion inline** : suggère la suite du code pendant la frappe, comme un IDE
6. **Actions rapides** : boutons contextuels pour expliquer, corriger ou optimiser une sélection de code

### Prérequis techniques pour Copilot

| Condition | Détail |
|-----------|--------|
| **Licence** | Capacité Fabric F64 ou supérieur (ou Premium P1+) |
| **Région** | Disponible dans les régions Azure supportant les services OpenAI |
| **Activation** | L'administrateur Fabric doit activer Copilot dans les paramètres du tenant |
| **Rôle** | L'utilisateur doit avoir accès au workspace et au warehouse |

### Responsabilité de l'IA et utilisation éthique

Copilot est un assistant, pas un remplaçant du jugement humain. Avant d'utiliser le SQL généré en production :

- **Toujours valider** le code généré contre le schéma et la logique métier
- **Tester** sur des données de développement avant la production
- **Vérifier les accès** : Copilot peut générer des requêtes qui exposent des données sensibles si les permissions ne sont pas correctement configurées
- **Documenter** les requêtes générées pour la traçabilité

## 2. Accéder à Copilot dans le Data Warehouse

1. Naviguer vers votre Data Warehouse dans Fabric

## 3. Génération de SQL avec Copilot

### Commande /generate-sql

La commande `/generate-sql` est la principale façon d'utiliser Copilot pour créer des requêtes analytiques. Copilot analyse le schéma de votre warehouse et génère le T-SQL correspondant à votre description.

**Exemples de prompts de génération :**

```copilot-prompt
/generate-sql Calcule le revenu mensuel des ventes
```

Copilot peut générer :
```sql
SELECT
    d.MonthName                 AS Mois,
    d.Year                      AS Annee,
    SUM(f.SalesTotal)           AS RevenuTotal,
    COUNT(DISTINCT f.OrderID)   AS NombreCommandes
FROM FactSalesOrder AS f
JOIN DimDate AS d
    ON f.SalesOrderDateKey = d.DateKey
GROUP BY d.Year, d.MonthName, d.Month
ORDER BY d.Year, d.Month;
```

---

```copilot-prompt
/generate-sql Récupère les données de revenu des ventes groupées par année, mois, nom du mois et région des ventes
```

Copilot peut générer :
```sql
SELECT
    d.[Year]                        AS Annee,
    d.[Month]                       AS Mois,
    d.MonthName                     AS NomMois,
    c.CountryRegion                 AS RegionVentes,
    SUM(so.SalesTotal)              AS RevenuTotal
FROM FactSalesOrder AS so
JOIN DimDate AS d
    ON so.SalesOrderDateKey = d.DateKey
JOIN DimCustomer AS c
    ON so.CustomerKey = c.CustomerKey
GROUP BY
    d.[Year], d.[Month], d.MonthName, c.CountryRegion
ORDER BY
    d.[Year], d.[Month], c.CountryRegion;
```

---

```copilot-prompt
/generate-sql Récupère une liste détaillée des produits, organisée par catégorie. Pour chaque catégorie de produit, afficher les produits disponibles avec leurs prix et les classer par prix dans leur catégorie
```

Copilot peut générer :
```sql
SELECT
    p.Category                      AS Categorie,
    p.ProductName                   AS NomProduit,
    p.ListPrice                     AS PrixListe,
    RANK() OVER (
        PARTITION BY p.Category
        ORDER BY p.ListPrice DESC
    )                               AS ClassementPrix
FROM DimProduct AS p
ORDER BY p.Category, ClassementPrix;
```

### Affiner les requêtes générées

Copilot maintient le contexte de la conversation, ce qui permet d'affiner itérativement les requêtes :

```copilot-prompt
Ajoute aussi la quantité totale vendue et filtre pour inclure uniquement les produits vendus plus de 100 fois
```

La deuxième requête s'appuie sur la précédente pour ajouter les modifications demandées.

### Créer des vues avec Copilot

```copilot-prompt
/generate-sql Crée une vue dans le schéma dbo qui affiche le revenu des ventes groupé par année, mois, nom du mois et région des ventes
```

Copilot peut générer :
```sql
CREATE VIEW [dbo].[vw_VentesParRegionEtMois] AS
SELECT
    d.[Year]        AS Annee,
    d.[Month]       AS Mois,
    d.MonthName     AS NomMois,
    c.CountryRegion AS RegionVentes,
    SUM(so.SalesTotal) AS RevenuTotal
FROM [dbo].[FactSalesOrder] AS so
JOIN [dbo].[DimDate] AS d
    ON so.SalesOrderDateKey = d.DateKey
JOIN [dbo].[DimCustomer] AS c
    ON so.CustomerKey = c.CustomerKey
GROUP BY d.[Year], d.[Month], d.MonthName, c.CountryRegion;
```

> **Note :** Copilot peut parfois inclure le nom de la base de données comme préfixe dans les vues (ex: `[NomDB].[dbo].[Table]`), ce qui cause une erreur dans Fabric. Utiliser "Corriger les erreurs" pour que Copilot supprime automatiquement ce préfixe.

## 4. Saisie semi-automatique du code (Code Completion)

### Complétion inline pendant la frappe

La saisie semi-automatique Copilot fonctionne directement dans l'éditeur SQL, suggérant la suite du code pendant que vous tapez. C'est similaire aux outils comme GitHub Copilot pour les développeurs.

**Comment l'utiliser :**

1. Commencer à taper une requête SQL dans l'éditeur
2. Copilot affiche une suggestion en gris après votre curseur
3. Appuyer sur **Tab** pour accepter la suggestion complète
4. Appuyer sur **Ctrl + Flèche droite** pour accepter mot par mot
5. Continuer à taper pour ignorer la suggestion

**Exemple de complétion :**

```sql
-- Vous tapez :
SELECT d.Year, d.MonthName,

-- Copilot suggère automatiquement (en gris) :
SUM(f.SalesTotal) AS RevenuTotal, COUNT(*) AS NombreCommandes
FROM FactSalesOrder AS f
JOIN DimDate AS d ON f.SalesOrderDateKey = d.DateKey
GROUP BY d.Year, d.MonthName
ORDER BY d.Year, d.Month;
```

### Complétions contextuelles basées sur le schéma

Copilot analyse votre schéma en temps réel pour des suggestions précises :

- Après `FROM dbo.`, Copilot suggère les noms de tables existants
- Après `JOIN dbo.NomTable ON`, Copilot suggère les colonnes de jointure probables
- Après `WHERE`, Copilot suggère les filtres courants basés sur les colonnes disponibles
- Après `GROUP BY`, Copilot complète avec toutes les colonnes non-agrégées dans le SELECT

## 5. Actions rapides Copilot

### Expliquer la requête sélectionnée

Sélectionner une requête T-SQL complexe, puis utiliser l'action rapide **Expliquer** pour obtenir une description en français de ce que fait le code :

```sql
-- Requête sélectionnée :
WITH RankedSales AS (
    SELECT
        p.Category,
        c.CustomerName,
        SUM(f.SalesTotal) AS TotalVentes,
        ROW_NUMBER() OVER (PARTITION BY p.Category ORDER BY SUM(f.SalesTotal) DESC) AS Rang
    FROM FactSalesOrder f
    JOIN DimProduct p ON f.ProductKey = p.ProductKey
    JOIN DimCustomer c ON f.CustomerKey = c.CustomerKey
    GROUP BY p.Category, c.CustomerName
)
SELECT Category, CustomerName, TotalVentes
FROM RankedSales
WHERE Rang = 1
ORDER BY TotalVentes DESC;
```

Copilot peut expliquer :
> "Cette requête identifie le meilleur client (celui avec le plus haut chiffre d'affaires) pour chaque catégorie de produit. Elle utilise une CTE avec une fonction de fenêtrage ROW_NUMBER() qui numérote les clients au sein de chaque catégorie selon leurs ventes décroissantes. Ensuite, le filtre WHERE Rang = 1 garde uniquement le premier client de chaque catégorie."

### Corriger les erreurs de requête

Après l'exécution d'une requête qui échoue, Copilot peut analyser le message d'erreur et corriger automatiquement le code :

**Erreur courante : préfixe de base de données dans une vue**
```sql
-- Requête incorrecte (générée initialement par Copilot) :
CREATE VIEW [MonWarehouse].[dbo].[vw_VentesParMois] AS
SELECT ...
-- ❌ Erreur : Msg 2714, "Database name not allowed"
```

Après avoir cliqué sur **Corriger les erreurs de requête** :
```sql
-- Requête corrigée automatiquement :
-- Auto-Fix: Suppression du préfixe du nom de base de données
CREATE VIEW [dbo].[vw_VentesParMois] AS
SELECT ...
-- ✅ Exécution réussie
```

**Erreur courante : colonne ambiguë**
```sql
-- Avant correction :
SELECT Year, Month, SalesTotal
FROM FactSalesOrder f
JOIN DimDate d ON f.SalesOrderDateKey = d.DateKey
-- ❌ Erreur : "Ambiguous column name 'Year'"
```

```sql
-- Après correction Copilot :
SELECT d.Year, d.Month, f.SalesTotal
FROM FactSalesOrder f
JOIN DimDate d ON f.SalesOrderDateKey = d.DateKey
-- ✅ Colonnes qualifiées avec alias de table
```

### Optimiser une requête

L'action rapide **Optimiser** suggère des améliorations de performance :

- Ajout d'index hints si approprié
- Remplacement de sous-requêtes corrélées par des JOIN
- Suggestion d'utiliser EXISTS plutôt que IN pour les sous-requêtes
- Proposition de CTE pour améliorer la lisibilité et potentiellement la performance

## 6. Bonnes pratiques pour des prompts efficaces

### Principes fondamentaux

La qualité du SQL généré par Copilot dépend directement de la qualité de vos prompts. Voici les principes à suivre :

**1. Être spécifique et précis**

| Prompt vague | Prompt efficace |
|-------------|----------------|
| "Montre-moi les ventes" | "Calcule le chiffre d'affaires mensuel en 2024 par région, avec le nombre de commandes et le panier moyen" |
| "Analyse les produits" | "Liste les 10 produits les plus vendus par catégorie en 2024, triés par chiffre d'affaires décroissant" |
| "Rapport clients" | "Identifie les clients qui n'ont pas commandé depuis 90 jours et dont le total d'achats 2023 dépasse 1000€" |

**2. Nommer clairement les tables et colonnes**

Un schéma bien nommé améliore considérablement les résultats de Copilot :

```sql
-- Nommage flou (résultats Copilot moins précis) :
CREATE TABLE t1 (col1 INT, col2 VARCHAR(50), col3 DECIMAL(10,2));

-- Nommage explicite (Copilot comprend mieux le contexte) :
CREATE TABLE dbo.FactSalesOrder (
    SalesOrderKey           INT             NOT NULL,
    SalesOrderNumber        VARCHAR(30)     NOT NULL,
    CustomerKey             INT             NOT NULL,
    ProductKey              INT             NOT NULL,
    SalesOrderDateKey       INT             NOT NULL,
    SalesAmount             DECIMAL(10,2)   NOT NULL
);
```

**3. Mentionner les agrégations et filtres souhaités explicitement**

```copilot-prompt
-- Prompt efficace avec tous les détails
/generate-sql 
Calcule pour chaque catégorie de produit :
- Le chiffre d'affaires total (SalesAmount)
- Le nombre de commandes distinctes
- Le nombre de clients uniques
- Le panier moyen par commande
Filtre uniquement les données de 2024
Trie par chiffre d'affaires décroissant
```

**4. Utiliser le contexte des tables disponibles**

Avant de promter, vérifier dans l'Explorateur d'objets quelles tables sont disponibles et mentionner les noms exacts dans le prompt.

### Patterns de prompts recommandés

```copilot-prompt
-- Pattern 1 : Analyse temporelle
/generate-sql Montre l'évolution du [métrique] par [période] avec comparaison [N-1 ou mois précédent]

-- Pattern 2 : Classement
/generate-sql Identifie le top [N] [entités] par [métrique] pour [période/filtre]

-- Pattern 3 : Cohérence des données  
/generate-sql Vérifie les anomalies dans [table] : [valeurs nulles / doublons / valeurs hors-plage]

-- Pattern 4 : Création d'objets
/generate-sql Crée une vue nommée [nom] qui [description de ce que la vue doit retourner]

-- Pattern 5 : Procédure stockée
/generate-sql Crée une procédure stockée [nom] qui prend [paramètres] et [description de l'action]
```

## 7. Copilot et conception de schéma

### Impact du schéma sur la qualité des résultats

La qualité du SQL généré par Copilot est directement corrélée à la clarté du schéma. Un bon schéma pour Copilot possède :

**Noms de tables descriptifs :**
- `FactSalesOrder` (bon) vs `FSO` (mauvais)
- `DimCustomer` (bon) vs `Customers_dim_v2` (mauvais)

**Noms de colonnes explicites :**
- `SalesOrderDateKey` (bon) vs `date_key` (mauvais)
- `TotalSalesAmount` (bon) vs `amt` (mauvais)

**Commentaires de table (descriptions) :**
L'ajout de descriptions aux tables et colonnes dans les métadonnées améliore la compréhension de Copilot.

### Architecture recommandée pour optimiser Copilot

```sql
-- Schéma bien conçu pour Copilot
CREATE TABLE dbo.FactSalesOrder
(
    -- Clé de substitution
    SalesOrderKey           INT             NOT NULL,
    -- Clés métier
    SalesOrderNumber        VARCHAR(30)     NOT NULL,
    SalesOrderLineNumber    TINYINT         NOT NULL,
    -- Clés étrangères vers les dimensions (nommage cohérent *Key)
    CustomerKey             INT             NOT NULL,
    ProductKey              INT             NOT NULL,
    SalesOrderDateKey       INT             NOT NULL,   -- Référence DimDate.DateKey
    ShipDateKey             INT             NULL,       -- Référence DimDate.DateKey
    -- Mesures numériques (nommage explicite)
    OrderQuantity           SMALLINT        NOT NULL,
    UnitPrice               DECIMAL(10,2)   NOT NULL,
    UnitPriceDiscount       DECIMAL(5,2)    NOT NULL DEFAULT 0,
    SalesAmount             DECIMAL(10,2)   NOT NULL,  -- = Qty * Price * (1-Discount)
    TaxAmount               DECIMAL(10,2)   NOT NULL DEFAULT 0,
    TotalDue                DECIMAL(10,2)   NOT NULL   -- = SalesAmount + TaxAmount
);
```

## Vérification des connaissances

**Question 1.** Quel est le prérequis de licence minimum pour utiliser Copilot dans un Data Warehouse Fabric ?

A) N'importe quelle licence Fabric (y compris Trial gratuit)  
B) Capacité Fabric F64 ou supérieur, ou Premium P1+  
C) Licence Power BI Pro uniquement  
D) Abonnement Azure OpenAI séparé  

**Réponse correcte : B** — Copilot dans Fabric Data Warehouse nécessite une capacité payante d'au moins F64 (Fabric SKU) ou Premium P1. La capacité Trial de 60 jours ne supporte pas Copilot.

---

**Question 2.** Après avoir généré une vue avec Copilot qui échoue avec une erreur "Database name not allowed", quelle action rapide Copilot utilisez-vous pour corriger automatiquement le problème ?

A) "Expliquer la requête"  
B) "Optimiser la requête"  
C) "Corriger les erreurs de requête"  
D) Ré-écrire manuellement toute la requête  

**Réponse correcte : C** — L'action rapide "Corriger les erreurs de requête" (Fix query errors) analyse l'erreur SQL et propose une correction automatique. Dans ce cas, Copilot supprime le préfixe du nom de base de données non autorisé dans les définitions de vues.

---

**Question 3.** Quelle pratique améliore le plus la qualité du SQL généré par Copilot ?

A) Écrire des prompts aussi courts et vagues que possible pour laisser Copilot interpréter  
B) Nommer les tables et colonnes de manière explicite et descriptive dans le schéma, et rédiger des prompts spécifiques incluant les métriques et filtres souhaités  
C) Toujours utiliser des abréviations pour les noms de tables (ex: FSO pour FactSalesOrder)  
D) Éviter de mentionner les noms de tables dans les prompts  

**Réponse correcte : B** — Un schéma bien nommé (tables et colonnes explicites) combiné avec des prompts détaillés (métriques, filtres, agrégations spécifiés) produit le SQL le plus précis. Copilot utilise les noms du schéma pour construire les requêtes.

---

**Question 4.** Quelle est la fonctionnalité de complétion inline de Copilot dans l'éditeur SQL ?

A) Copilot génère automatiquement toute la requête dès qu'on ouvre un nouvel onglet SQL  
B) Pendant la frappe, Copilot affiche des suggestions de code en gris que l'on accepte avec Tab  
C) Copilot corrige les fautes d'orthographe dans les noms de colonnes  
D) Copilot exécute automatiquement les requêtes sans cliquer sur Run  

**Réponse correcte : B** — La complétion inline (code completion) affiche des suggestions contextuelles en gris pendant la frappe. L'utilisateur peut accepter la suggestion complète avec Tab, ou accepter mot par mot avec Ctrl+Flèche droite.

---

**Question 5.** Comment utiliser Copilot de manière responsable dans un contexte professionnel ?

A) Faire confiance à 100% au code généré par Copilot et le déployer directement en production  
B) Toujours valider le code généré contre le schéma et la logique métier, tester sur des données de développement, et documenter les requêtes pour la traçabilité  
C) Utiliser Copilot uniquement pour des tâches non critiques comme la génération de rapports sans enjeux  
D) Désactiver les permissions SQL des utilisateurs finaux et laisser Copilot gérer tous les accès  

**Réponse correcte : B** — Copilot est un assistant qui accélère le travail mais ne remplace pas le jugement humain. Il faut systématiquement valider le code généré, le tester en développement, vérifier la logique métier et documenter les décisions pour la gouvernance.

## Résumé

Dans ce module, vous avez découvert comment Copilot dans Microsoft Fabric Data Warehouse transforme le développement SQL :

- **Panneau Copilot** accessible depuis le ruban Home du warehouse, avec suggestions prêtes à l'emploi et historique de conversation
- **`/generate-sql`** est la commande principale pour générer des requêtes T-SQL depuis des descriptions en langage naturel
- La **complétion inline** suggère du code pendant la frappe, comme un IDE moderne, en s'appuyant sur la connaissance du schéma
- Les **actions rapides** (Expliquer, Corriger, Optimiser) permettent d'interagir avec le code existant
- La qualité des résultats dépend de la **qualité du schéma** (nommage explicite) et de la **précision des prompts**
- Copilot doit être utilisé de manière **responsable** : toujours valider le code généré avant déploiement en production
