## 1. Présentation

*1 minute*

Apache Spark est le moteur de traitement de données distribué le plus populaire du secteur. Conçu pour traiter des téraoctets de données en parallèle sur des clusters de machines, Spark est devenu la technologie de référence pour les pipelines de données à grande échelle, le Machine Learning, et l'analytique avancée.

Microsoft Fabric intègre Apache Spark nativement dans sa plateforme, permettant aux data engineers et data scientists d'analyser et transformer des données dans un lakehouse à grande échelle sans avoir à gérer l'infrastructure des clusters.

**Pourquoi Spark plutôt que SQL classique ?**
- **Volume** : Spark peut traiter des pétaoctets de données que les moteurs SQL traditionnels ne peuvent pas gérer efficacement
- **Variété** : Spark lit nativement CSV, JSON, Parquet, Delta, ORC, Avro, et plus encore
- **Flexibilité** : Spark permet des transformations complexes (ML, NLP, graphes) impossibles en SQL pur
- **Streaming** : Spark Structured Streaming permet le traitement en temps réel

## 2. Se préparer à l'utilisation d'Apache Spark

*3 minutes*

### Comment Spark fonctionne dans Fabric

Dans Microsoft Fabric, Spark tourne sur des **pools Spark** — des clusters de calcul provisionnés automatiquement. Contrairement aux plateformes traditionnelles où vous devez créer et gérer des clusters manuellement, Fabric gère tout cela de manière transparente.

**Architecture d'un job Spark dans Fabric :**

```
Notebook / Job Spark
        ↓
  Driver Node (coordonne)
        ↓
  ┌─────┼─────┐
Executor Executor Executor  (workers parallèles)
  ↓         ↓         ↓
OneLake  OneLake  OneLake  (stockage distribué)
```

Le **Driver** orchestre l'exécution du programme. Les **Executors** font le vrai travail en parallèle sur des partitions de données.

### Configuration du Starter Pool

Microsoft Fabric inclut un **Starter Pool** pré-configuré qui démarre automatiquement en 5-15 secondes (contre 2-5 minutes pour un cluster traditionnel). Ce pool est idéal pour l'exploration et le développement.

**Accéder aux paramètres Spark d'un workspace :**
1. Workspace → Settings → Data Engineering / Science
2. Section Spark settings
3. Configurer le pool : nombre de nœuds, famille de nœuds (Memory Optimized, Compute Optimized), etc.

**Types de nœuds disponibles dans Fabric :**
| Type | vCores | RAM | Cas d'usage |
|------|--------|-----|------------|
| Small | 4 | 32 GB | Développement, tests |
| Medium | 8 | 64 GB | Workloads standards |
| Large | 16 | 128 GB | Données volumineuses |
| X-Large | 32 | 256 GB | ML intensif |
| Memory Optimized | 4-32 | Jusqu'à 400 GB | DataFrames très larges |

### Notebooks vs Spark Job Definition

Fabric propose deux manières d'exécuter du code Spark :

**Notebooks :**
- Interface interactive cellule par cellule
- Idéal pour l'exploration, la visualisation, le développement
- Supporte plusieurs langages dans un même notebook (PySpark, Scala, SQL, R)
- Résultats visibles immédiatement sous chaque cellule

**Spark Job Definition :**
- Exécution programmatique d'un script Python/Scala comme un job batch
- Idéal pour les pipelines automatisés planifiés
- Soumission via l'interface Fabric ou des pipelines Data Factory
- Pas d'interface interactive

## 3. Exécuter du code Spark

*3 minutes*

### Créer et utiliser un Notebook

Dans Fabric, les notebooks sont créés depuis un lakehouse :
1. Ouvrir un lakehouse
2. **Open notebook** → **New notebook**
3. Le notebook est automatiquement connecté au lakehouse

### Structure d'un Notebook Fabric

Un notebook est composé de **cellules** de deux types :

**Cellule Code** (Python par défaut) :
```python
# Cellule de code PySpark
df = spark.read.format("csv") \
    .option("header", "true") \
    .load("Files/orders/2019.csv")
display(df.limit(5))
```

**Cellule Markdown** :
```markdown
## Exploration des données de ventes

Analyse des commandes 2019-2021 pour identifier les tendances.
```

### Démarrer une Session Spark

La première exécution d'une cellule de code démarre automatiquement une session Spark. **Ce démarrage prend 30-90 secondes** la première fois — c'est normal. Les cellules suivantes de la même session s'exécutent immédiatement.

```python
# Vérifier la version Spark et la configuration
print(f"Version Spark : {spark.version}")
print(f"Appname : {spark.sparkContext.appName}")

# Voir la configuration du Spark Context
for conf in spark.sparkContext.getConf().getAll():
    if "fabric" in conf[0].lower() or "executor" in conf[0].lower():
        print(conf)
```

### Magie des langages dans un Notebook

Dans un notebook Fabric, vous pouvez changer de langage à la volée avec des commandes magiques :

```python
# Cellule PySpark (défaut)
df = spark.table("sales")
```

```sql
%%sql
-- Cellule SQL
SELECT * FROM sales LIMIT 10
```

```scala
// %%scala
// Cellule Scala
val df = spark.table("sales")
```

## 4. Utiliser des données dans un DataFrame Spark

*5 minutes*

### Qu'est-ce qu'un DataFrame Spark ?

Un **DataFrame Spark** est une collection distribuée de données organisées en colonnes nommées, similaire à une table SQL ou un DataFrame pandas. La différence fondamentale : les données ne sont pas sur votre machine, elles sont distribuées sur le cluster et traitées en parallèle.

**Analogie** : Un DataFrame Spark est comme un tableau Excel géant découpé en milliers de petits morceaux traités simultanément par des centaines d'ordinateurs.

### Lire des données depuis le Lakehouse

```python
# Lire un seul fichier CSV (schema auto-inféré)
df = spark.read.format("csv") \
    .option("header", "true") \
    .option("inferSchema", "true") \
    .load("Files/orders/2019.csv")

display(df.limit(10))
```

```python
# Lire plusieurs fichiers avec un wildcard
from pyspark.sql.types import *

# Définir le schéma explicitement (meilleure pratique)
orderSchema = StructType([
    StructField("SalesOrderNumber", StringType()),
    StructField("SalesOrderLineNumber", IntegerType()),
    StructField("OrderDate", DateType()),
    StructField("CustomerName", StringType()),
    StructField("Email", StringType()),
    StructField("Item", StringType()),
    StructField("Quantity", IntegerType()),
    StructField("UnitPrice", FloatType()),
    StructField("Tax", FloatType())
])

# Charger tous les fichiers CSV du dossier orders/
df = spark.read.format("csv") \
    .schema(orderSchema) \
    .load("Files/orders/*.csv")

print(f"Nombre de lignes : {df.count()}")
print(f"Nombre de colonnes : {len(df.columns)}")
df.printSchema()
```

> **Bonne pratique** : Toujours définir le schéma explicitement plutôt qu'utiliser `inferSchema`. L'inférence de schéma nécessite une première lecture complète du fichier, ce qui est coûteux sur de grandes données.

### Filtrer un DataFrame

```python
# Sélectionner des colonnes spécifiques
customers = df.select("CustomerName", "Email")
print(f"Total clients : {customers.count()}")
print(f"Clients uniques : {customers.distinct().count()}")

# Filtrer avec where/filter
mountain_bike_customers = df.select("CustomerName", "Email") \
    .where(df['Item'] == 'Road-250 Red, 52')
    
print(f"Acheteurs Road-250 Red, 52 : {mountain_bike_customers.distinct().count()}")
display(mountain_bike_customers.distinct())
```

### Agréger et Grouper des données

```python
# Somme des quantités vendues par produit
productSales = df.select("Item", "Quantity") \
    .groupBy("Item") \
    .sum()

display(productSales.orderBy("sum(Quantity)", ascending=False))
```

```python
from pyspark.sql.functions import year, col, count, sum as spark_sum, avg, round as spark_round

# Ventes par année
yearlySales = df.select(year(col("OrderDate")).alias("Year")) \
    .groupBy("Year") \
    .count() \
    .orderBy("Year")

display(yearlySales)
```

### Transformer un DataFrame

```python
from pyspark.sql.functions import year, month, split, col

# Ajouter des colonnes dérivées
transformed_df = df \
    .withColumn("Year", year(col("OrderDate"))) \
    .withColumn("Month", month(col("OrderDate"))) \
    .withColumn("FirstName", split(col("CustomerName"), " ").getItem(0)) \
    .withColumn("LastName", split(col("CustomerName"), " ").getItem(1))

# Réordonner et filtrer les colonnes
transformed_df = transformed_df[
    "SalesOrderNumber", "SalesOrderLineNumber", "OrderDate",
    "Year", "Month", "FirstName", "LastName",
    "Email", "Item", "Quantity", "UnitPrice", "Tax"
]

display(transformed_df.limit(5))
```

### Sauvegarder le résultat transformé

```python
# Sauvegarder en Parquet (format columnar efficace)
transformed_df.write \
    .partitionBy("Year") \
    .mode("overwrite") \
    .parquet("Files/transformed/orders")

# OU sauvegarder comme table Delta dans le lakehouse
transformed_df.write \
    .format("delta") \
    .mode("overwrite") \
    .saveAsTable("orders_transformed")

print("Données transformées sauvegardées !")
```

> **Partitionnement** : `partitionBy("Year")` crée des sous-dossiers par année (`Year=2019/`, `Year=2020/`, etc.), ce qui accélère dramatiquement les requêtes filtrées sur la colonne Year.

## 5. Utiliser des données à l'aide de Spark SQL

*7 minutes*

### Spark SQL : SQL natif dans Spark

Spark SQL permet d'écrire des requêtes SQL standard directement dans Spark. Vous pouvez l'utiliser de deux façons :

**Option 1 : spark.sql() en PySpark**
```python
# Requête SQL retournant un DataFrame Spark
result = spark.sql("""
    SELECT 
        Item,
        SUM(Quantity * UnitPrice) AS Revenue,
        COUNT(*) AS NumOrders,
        AVG(UnitPrice) AS AvgPrice
    FROM sales
    GROUP BY Item
    ORDER BY Revenue DESC
    LIMIT 10
""")
display(result)
```

**Option 2 : Cellule %%sql (magic)**
```sql
%%sql

SELECT 
    Item,
    SUM(Quantity * UnitPrice) AS Revenue,
    COUNT(*) AS NumOrders
FROM sales
GROUP BY Item
ORDER BY Revenue DESC
LIMIT 10;
```

### Créer des Vues Temporaires

Les vues temporaires permettent de transformer un DataFrame en "table SQL" accessible pour la durée de la session :

```python
# Créer une vue à partir d'un DataFrame PySpark
yearlySales = df.select(
    year(col("OrderDate")).alias("Year"),
    col("Item"),
    col("Quantity"),
    (col("Quantity") * col("UnitPrice")).alias("Revenue")
)
yearlySales.createOrReplaceTempView("yearly_sales")

# Maintenant requêtable en SQL
result = spark.sql("""
    SELECT Year, SUM(Revenue) AS TotalRevenue
    FROM yearly_sales
    GROUP BY Year
    ORDER BY Year
""")
display(result)
```

```sql
%%sql
-- Utiliser la vue créée ci-dessus
SELECT Year, Item, SUM(Revenue) AS ItemRevenue
FROM yearly_sales
WHERE Year = 2021
GROUP BY Year, Item
ORDER BY ItemRevenue DESC
LIMIT 5;
```

### Tables cataloguées vs Vues temporaires

| Aspect | Vue Temporaire | Table Delta (cataloguée) |
|--------|---------------|--------------------------|
| Durée de vie | Session courante uniquement | Persiste après la session |
| Stockage | Métadonnées en mémoire | Fichiers Delta sur OneLake |
| Partagée entre notebooks | Non | Oui |
| Requêtable via SQL endpoint | Non | Oui |
| Cas d'usage | Calculs intermédiaires | Données finales réutilisables |

### Fonctions Spark SQL utiles

```sql
%%sql

-- Window functions : rang par catégorie
SELECT 
    Item,
    Revenue,
    RANK() OVER (ORDER BY Revenue DESC) AS RevenueRank,
    PERCENT_RANK() OVER (ORDER BY Revenue DESC) AS RevenuePercentile
FROM (
    SELECT Item, SUM(Quantity * UnitPrice) AS Revenue
    FROM sales
    GROUP BY Item
) product_revenue;
```

```python
# Jointure entre deux DataFrames/tables
customers_df = spark.sql("""
    SELECT DISTINCT CustomerName, Email
    FROM sales
    WHERE Year = 2021
""")

orders_2021 = spark.sql("""
    SELECT CustomerName, COUNT(*) AS OrderCount, SUM(Quantity * UnitPrice) AS TotalSpent
    FROM sales
    WHERE year(OrderDate) = 2021
    GROUP BY CustomerName
""")

# Jointure PySpark
customer_summary = customers_df.join(orders_2021, "CustomerName", "inner")
display(customer_summary.orderBy("TotalSpent", ascending=False))
```

## 6. Visualiser des données dans un notebook Spark

*5 minutes*

### Visualisations intégrées avec display()

La fonction `display()` de Fabric génère automatiquement des visualisations interactives. Après l'exécution, vous pouvez basculer entre vue tableau et différents types de graphiques.

```python
from pyspark.sql.functions import year, col, sum as spark_sum

# Préparer les données à visualiser
monthly_revenue = spark.sql("""
    SELECT 
        year(OrderDate) AS Year,
        month(OrderDate) AS Month,
        SUM(Quantity * UnitPrice) AS Revenue
    FROM sales
    GROUP BY year(OrderDate), month(OrderDate)
    ORDER BY Year, Month
""")

# display() crée automatiquement des options de graphiques
display(monthly_revenue)
```

Après avoir cliqué sur le résultat, sélectionnez **+ New chart** pour créer :
- Graphique en barres (idéal pour comparer des catégories)
- Graphique linéaire (tendances temporelles)
- Graphique en secteurs (parts de marché)
- Nuage de points (corrélations)

### Visualisation avancée avec matplotlib

```python
import matplotlib.pyplot as plt
import pandas as pd

# Convertir le DataFrame Spark en pandas pour matplotlib
# Attention : uniquement pour des données agrégées (petits volumes !)
revenue_pd = spark.sql("""
    SELECT Item, SUM(Quantity * UnitPrice) AS Revenue
    FROM sales
    GROUP BY Item
    ORDER BY Revenue DESC
    LIMIT 10
""").toPandas()

# Créer un graphique en barres horizontal
fig, ax = plt.subplots(figsize=(12, 6))
ax.barh(revenue_pd['Item'], revenue_pd['Revenue'], color='steelblue')
ax.set_xlabel('Chiffre d\'affaires (€)')
ax.set_title('Top 10 produits par chiffre d\'affaires')
ax.invert_yaxis()  # Afficher le premier en haut

plt.tight_layout()
plt.show()
```

> **Important** : `toPandas()` transfère toutes les données du cluster vers le driver. À utiliser **uniquement** sur des données agrégées ou des échantillons. Sur des millions de lignes, cela peut provoquer des erreurs mémoire.

### Visualisation avec seaborn

```python
import seaborn as sns
import matplotlib.pyplot as plt

# Données agrégées par année et produit
top_products = spark.sql("""
    SELECT 
        year(OrderDate) AS Year,
        Item,
        SUM(Quantity) AS TotalQuantity
    FROM sales
    WHERE Item IN (
        SELECT Item FROM (
            SELECT Item, SUM(Quantity) AS Q
            FROM sales GROUP BY Item ORDER BY Q DESC LIMIT 5
        )
    )
    GROUP BY year(OrderDate), Item
""").toPandas()

# Pivot pour le heatmap
pivot = top_products.pivot(index='Item', columns='Year', values='TotalQuantity')

plt.figure(figsize=(10, 6))
sns.heatmap(pivot, annot=True, fmt='.0f', cmap='YlOrRd')
plt.title('Quantités vendues : Top 5 produits par année')
plt.show()
```

## 8. Évaluation des connaissances

*10 minutes*

**Question 1** : Qu'est-ce qu'un Starter Pool dans Microsoft Fabric ?

- A) Un pool de connexions SQL préconfiguré pour les requêtes analytiques
- B) Un cluster Spark pré-provisionné qui démarre rapidement (30-90 sec) sans gestion manuelle
- C) Un ensemble de notebooks de démarrage pour les débutants
- D) Une bibliothèque Python préinstallée pour l'analyse de données

> **Réponse : B** — Le Starter Pool est un cluster Spark géré par Fabric qui démarre en 30-90 secondes, permettant un démarrage rapide sans configuration d'infrastructure.

---

**Question 2** : Quelle est la différence entre une Vue Temporaire et une Table Delta cataloguée dans Spark ?

- A) Les vues temporaires sont plus rapides à requêter que les tables Delta
- B) Les vues temporaires n'existent que pendant la session courante, les tables Delta persistent après la fermeture du notebook
- C) Les vues temporaires supportent les transactions ACID, les tables Delta ne le font pas
- D) Il n'y a aucune différence fonctionnelle

> **Réponse : B** — Les vues temporaires (`createOrReplaceTempView`) existent uniquement pendant la session Spark. Les tables Delta sont persistées dans le lakehouse et accessibles par tous les notebooks et le SQL endpoint.

---

**Question 3** : Pourquoi est-il recommandé de définir le schéma explicitement plutôt qu'utiliser `inferSchema=true` ?

- A) `inferSchema` produit des types de données incorrects systématiquement
- B) `inferSchema` nécessite une lecture complète des données pour déduire le schéma, ce qui est coûteux sur de gros fichiers
- C) `inferSchema` n'est pas supporté dans Microsoft Fabric
- D) Un schéma explicite permet d'exécuter des requêtes en parallèle

> **Réponse : B** — L'inférence de schéma effectue une première passe de lecture sur tous les fichiers pour déterminer les types, ce qui double le temps de chargement. Sur de gros volumes, cela peut être très coûteux.

---

**Question 4** : Dans quel cas l'utilisation de `toPandas()` est-elle acceptable ?

- A) Toujours, car pandas est plus rapide que Spark pour les analyses
- B) Uniquement sur des données agrégées ou des échantillons de petite taille
- C) Uniquement pour les visualisations avec matplotlib
- D) Jamais, `toPandas()` est dépréciée dans Fabric

> **Réponse : B** — `toPandas()` transfère toutes les données vers la mémoire du driver. Sur de gros DataFrames, cela provoque des erreurs OutOfMemory. Il faut d'abord agréger ou échantillonner avant de convertir en pandas.

---

**Question 5** : Quel est l'avantage du partitionnement (`partitionBy`) lors de l'écriture d'un DataFrame ?

- A) Réduire la taille des fichiers en compressant les données identiques
- B) Créer des sous-dossiers par valeur de colonne, accélérant les requêtes filtrées sur cette colonne (partition pruning)
- C) Permettre l'écriture en parallèle sur plusieurs tables simultanément
- D) Chiffrer les données par partition pour améliorer la sécurité

> **Réponse : B** — Le partitionnement crée des sous-dossiers (ex: `Year=2021/`) permettant à Spark de ne lire que les partitions pertinentes lors de filtres (`WHERE Year = 2021`), ce qui évite de scanner l'intégralité des données.

## 9. Résumé

*1 minute*

Dans ce module, vous avez appris à utiliser Apache Spark dans Microsoft Fabric :

- **Spark Pools** : Fabric gère l'infrastructure, le Starter Pool démarre en 30-90 sec
- **Notebooks** : Interface interactive multi-langage (PySpark, SQL, Scala)
- **DataFrames** : Collections distribuées avec API pour filtrer, agréger, transformer
- **Spark SQL** : Requêtes SQL dans Spark via `spark.sql()` ou cellules `%%sql`
- **Vues Temporaires** : Tables SQL éphémères pour la session courante
- **Visualisations** : `display()` pour graphiques intégrés, matplotlib/seaborn pour avancé

### Points clés pour l'examen DP-700

1. Spark est **distribué** — les transformations sont exécutées en parallèle
2. `inferSchema=True` est **coûteux** — préférer un schéma explicite
3. `createOrReplaceTempView` crée une vue **temporaire** (session uniquement)
4. `saveAsTable` crée une table **persistante** dans le lakehouse
5. `toPandas()` transfère **toutes les données** vers le driver — utiliser avec parcimonie
