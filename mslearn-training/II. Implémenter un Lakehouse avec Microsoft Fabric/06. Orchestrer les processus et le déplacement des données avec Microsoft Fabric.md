## 1. Présentation

*1 minute*

Microsoft Fabric inclut les fonctionnalités complètes de **Data Factory** — la plateforme d'intégration de données Azure. Les **Pipelines** sont le composant central de cette intégration : ils orchestrent des séquences d'activités pour déplacer, transformer et charger des données de manière automatisée et fiable.

Contrairement aux Dataflows Gen2 (orientés transformation visuelle), les pipelines excellent dans :
- **L'orchestration complexe** : enchaînement conditionnel d'activités, gestion des erreurs
- **L'ingestion à grande échelle** : copie de téraoctets depuis des centaines de sources
- **L'intégration d'outils** : combiner Copy Data + Notebook Spark + Dataflow + Stored Procedure dans un seul workflow

## 2. Comprendre les Pipelines

*6 minutes*

### Qu'est-ce qu'un Pipeline Fabric ?

Un **Pipeline** est un workflow visuel composé d'**activités** connectées entre elles. Chaque activité effectue une opération spécifique (copier des données, exécuter un notebook, exécuter une procédure stockée, attendre une condition, etc.).

**Composants d'un Pipeline :**

```
Pipeline "Ingestion Quotidienne"
│
├── [Delete Data] ──→ [Copy Data] ──→ [Notebook] ──→ [If Condition]
│       ↓ (En cas d'erreur)                               ├──→ [Web Activity : Success Alert]
│    [Fail Activity]                                       └──→ [Web Activity : Failure Alert]
│
└── Trigger : Planifié quotidiennement à 6h00 UTC
```

### Types d'activités disponibles

**Activités de mouvement de données :**
| Activité | Description |
|----------|-------------|
| **Copy Data** | Copier des données de n'importe quelle source vers n'importe quelle destination |
| **Delete Data** | Supprimer des fichiers dans un stockage |

**Activités de transformation :**
| Activité | Description |
|----------|-------------|
| **Notebook** | Exécuter un notebook Spark Fabric |
| **Dataflow** | Exécuter un Dataflow Gen2 |
| **Stored Procedure** | Exécuter une procédure stockée SQL |
| **Script** | Exécuter un script SQL |

**Activités de contrôle de flux :**
| Activité | Description |
|----------|-------------|
| **If Condition** | Branchement conditionnel (succès/échec/condition personnalisée) |
| **For Each** | Itérer sur une liste et exécuter des activités pour chaque élément |
| **Until** | Boucle jusqu'à ce qu'une condition soit remplie |
| **Wait** | Pause pendant un nombre de secondes défini |
| **Set Variable** | Définir une variable de pipeline |
| **Get Metadata** | Récupérer des métadonnées d'un fichier ou dossier |

**Connexions entre activités :**
- **On Success** (vert) : L'activité suivante s'exécute si la précédente réussit
- **On Failure** (rouge) : L'activité suivante s'exécute si la précédente échoue
- **On Completion** (bleu) : L'activité suivante s'exécute toujours, peu importe le résultat
- **On Skip** (jaune) : L'activité suivante s'exécute si la précédente a été ignorée

### Variables et paramètres de Pipeline

Les pipelines supportent des **variables** (valeurs modifiables pendant l'exécution) et des **paramètres** (valeurs passées au démarrage du pipeline) :

```json
// Paramètre défini dans le pipeline
{
  "name": "source_folder",
  "type": "String",
  "defaultValue": "Files/new_data"
}

// Utilisation dans une activité Copy Data
// Source Path: @{pipeline().parameters.source_folder}/*.csv
```

### Expressions dynamiques

Les champs des activités supportent des **expressions dynamiques** avec le langage d'expression Fabric (similaire à ARM templates) :

```
// Date du jour au format YYYYMMDD
@formatDateTime(utcNow(), 'yyyyMMdd')

// Nom de fichier avec date
@concat('export_', formatDateTime(utcNow(), 'yyyyMMdd'), '.csv')

// Condition basée sur une variable
@equals(variables('status'), 'success')

// Référencer un paramètre
@pipeline().parameters.table_name
```

## 3. Utiliser l'activité Copy Data

*3 minutes*

### Qu'est-ce que Copy Data ?

L'activité **Copy Data** est l'activité fondamentale de Data Factory. Elle copie des données depuis n'importe quelle source vers n'importe quelle destination, avec des capacités de :
- **Conversion de format** : CSV → Parquet, JSON → Delta, etc.
- **Transformation légère** : mapping de colonnes, types de données
- **Performance** : copie parallèle sur plusieurs connexions simultanées
- **Fiabilité** : reprise sur erreur, retry automatique

**Note importante** : Une **Copy Job** et une activité **Copy Data** sont différentes dans Fabric :
- **Copy Job** : outil standalone simplifié pour la copie de données, sans pipeline
- **Copy Data activity** : activité configurée dans un pipeline, supporte l'orchestration avec d'autres activités

### Configuration d'une activité Copy Data

**1. Configurer la Source :**

Pour une source HTTP (fichier CSV distant) :
```
Connection Type : HTTP
URL : https://raw.githubusercontent.com/MicrosoftLearning/dp-data/main/sales.csv
Connection name : sales-csv-http
Authentication kind : Anonymous
File format : DelimitedText (CSV)
  ├── Column delimiter : Comma (,)
  ├── Row delimiter : Line feed (\n)
  └── First row as header : Enabled
```

Pour une source Azure SQL Database :
```
Connection Type : Azure SQL Database
Server : myserver.database.windows.net
Database : AdventureWorks
Authentication : SQL Authentication (username/password)
Table/Query : [dbo].[SalesOrders] (ou requête SQL personnalisée)
```

**2. Configurer la Destination :**

Pour un lakehouse Fabric :
```
Connection : OneLake Catalog → sélectionner votre lakehouse
Root folder : Files
File path : new_data / sales.csv
```

Pour une table Delta dans le lakehouse :
```
Connection : OneLake Catalog → sélectionner votre lakehouse
Root folder : Tables
Table : dbo.sales_raw
Write mode : Append (ou Overwrite)
```

**3. Test et prévisualisation :**
- **Test connection** : Vérifier la connectivité source/destination
- **Preview data** : Voir un échantillon des données avant d'exécuter

### Exemple de pipeline complet : Delete + Copy + Transform

Un pattern ETL classique dans Fabric :

```
Pipeline "Ingest Sales Data"

1. [Delete old files] ─→ [Copy Data] ─→ [Load Sales Notebook]
   Supprimer les CSV     Copier sales.csv  Transformer et charger
   du dossier new_data   vers Files/new_data  dans dbo.sales table
```

Configuration de l'activité Delete Data :
```
Source : Lakehouse (votre lakehouse)
File path type : Wildcard file path
Folder path : Files / new_data
Wildcard file name : *.csv
Recursively : Enabled
Enable logging : Disabled
```

## 4. Utiliser des modèles de Pipeline

*3 minutes*

### Modèles disponibles dans Fabric

Microsoft Fabric propose des **modèles de pipeline** prédéfinis pour les scénarios d'ingestion courants. Ces modèles accélèrent le développement en fournissant une structure de départ.

**Accéder aux modèles :**
Dans l'éditeur de pipeline → **Use a template** (sur l'écran de démarrage)

**Modèles disponibles :**
| Modèle | Description |
|--------|-------------|
| Copy data from a source to a destination | Ingestion basique source → lakehouse |
| Ingest data from SQL database | SQL Server/Azure SQL → Lakehouse |
| Full load from SQL to Lakehouse | Chargement complet avec upsert |
| Incrementally load from SQL | Chargement incrémental par watermark |
| Copy data from REST API | API REST → Lakehouse |

### Personnaliser un modèle

Après avoir sélectionné un modèle :
1. Remplir les paramètres de configuration (source, destination, credentials)
2. Le modèle génère automatiquement le pipeline avec les activités pré-configurées
3. Vous pouvez modifier, ajouter ou supprimer des activités selon vos besoins

## 5. Exécuter et surveiller des Pipelines

*5 minutes*

### Déclencheurs (Triggers)

Un pipeline peut être déclenché de plusieurs façons :

**Manuel :**
- Bouton **Run** dans l'interface de l'éditeur de pipeline
- Idéal pour le développement et les tests

**Planifié (Schedule Trigger) :**
```
Type : Schedule
Start date/time : 2024-06-01 06:00:00 UTC
Recurrence : Daily
Time zone : Europe/Paris

// Ou expression CRON pour plus de flexibilité :
Cron : 0 6 * * *  (tous les jours à 6h00 UTC)
```

**Sur événement (Event Trigger) :**
```
Type : Storage Event
Storage account : adlsgen2account
Container : raw-data
Blob path begins with : incoming/
Event : Blob created
```
Déclenche le pipeline automatiquement quand un nouveau fichier est créé dans ADLS Gen2.

**Depuis un autre Pipeline :**
Activité **Execute Pipeline** dans le pipeline parent pour appeler un pipeline enfant.

### Configurer un Trigger planifié

1. Dans l'éditeur du pipeline, **Add trigger** → **New/Edit**
2. Sélectionner **New** → Type **Schedule**
3. Configurer :
   - Start time, Time zone, Recurrence (Minutes/Hours/Days/Weeks/Months)
4. **Save** et **Activate** le trigger
5. Le pipeline s'exécutera automatiquement selon le planning défini

### Surveiller l'exécution d'un Pipeline

**Depuis l'interface Fabric :**
1. Dans le workspace, aller dans **Monitor** (menu gauche → icône moniteur)
2. Sélectionner **Pipeline runs**
3. Filtrer par nom de pipeline, date, statut

**Informations disponibles :**
- **Run ID** : Identifiant unique de l'exécution
- **Start time / End time / Duration** : Timing de l'exécution
- **Status** : Succeeded, Failed, In Progress, Cancelled
- **Triggered by** : Manual, Schedule, Event
- **Activity runs** : Détail de chaque activité (expandable)

**Analyser une exécution en détail :**
1. Cliquer sur un pipeline run
2. Le diagramme affiche le statut de chaque activité avec des icônes colorées
3. Cliquer sur une activité pour voir :
   - Durée
   - Données lues/écrites
   - Messages d'erreur détaillés
   - Logs de débogage

### Déboguer un Pipeline

Le mode **Debug** permet d'exécuter le pipeline pas à pas pendant le développement :

1. Dans l'éditeur, cliquer **Debug** (au lieu de Run)
2. Le pipeline s'exécute et affiche le statut en temps réel dans le volet Output
3. Les activités réussies sont en vert, les échouées en rouge
4. Vous pouvez voir les messages d'erreur immédiatement

**Points d'arrêt (Breakpoints) :**
- Clic droit sur une activité → **Set as breakpoint**
- Le debug s'arrête avant cette activité
- Permet d'inspecter les variables et résultats intermédiaires

## 6. Combiner Copy Data et Notebook dans un Pipeline ETL

*Pratique avancée*

### Architecture du pipeline ETL complet

```
Pipeline "Ingest Sales Data"
│
├── Activity 1: [Delete old files]  ← Nettoyer avant d'ingérer
│     Type: Delete Data
│     Source: Files/new_data/*.csv
│     → On Completion →
│
├── Activity 2: [Copy sales.csv]    ← Copier depuis source HTTP
│     Type: Copy Data
│     Source: HTTP / sales.csv
│     Destination: Files/new_data/sales.csv
│     → On Success →
│
└── Activity 3: [Load Sales notebook] ← Transformer et charger
      Type: Notebook
      Notebook: Load Sales
      Parameters: table_name = dbo.new_sales
```

### Créer le Notebook de transformation

```python
# Cellule paramètre (marquée comme "parameter cell")
table_name = "dbo.sales"  # Valeur par défaut, surchargée par le pipeline
```

```python
from pyspark.sql.functions import *

# Lire les données copiées par Copy Data
df = spark.read.format("csv") \
    .option("header","true") \
    .load("Files/new_data/*.csv")

# Transformations
df = df \
    .withColumn("Year", year(col("OrderDate"))) \
    .withColumn("Month", month(col("OrderDate"))) \
    .withColumn("FirstName", split(col("CustomerName"), " ").getItem(0)) \
    .withColumn("LastName", split(col("CustomerName"), " ").getItem(1))

# Réordonner les colonnes
df = df[
    "SalesOrderNumber", "SalesOrderLineNumber", "OrderDate", 
    "Year", "Month", "FirstName", "LastName", 
    "EmailAddress", "Item", "Quantity", "UnitPrice", "TaxAmount"
]

# Charger dans la table Delta (le nom de table vient du paramètre)
df.write.format("delta").mode("append").saveAsTable(table_name)

print(f"Données chargées dans la table '{table_name}' : {df.count()} lignes")
```

### Configurer l'activité Notebook dans le Pipeline

1. Ajouter une activité **Notebook**
2. La connecter au Copy Data avec **On Success**
3. Dans **Settings** :
   - **Notebook** : Sélectionner "Load Sales"
   - **Base parameters** : Ajouter `table_name` = `String` = `dbo.new_sales`

Le paramètre `table_name` surcharge la valeur par défaut dans le notebook, permettant de réutiliser le même notebook avec des tables différentes selon le contexte.

## 7. Exercice — Ingérer des données avec un Pipeline

*60 minutes*

> **Prérequis** : Accès à une capacité Fabric

### Étapes de l'exercice

**Étape 1 — Créer l'environnement**
1. Créer un workspace Fabric
2. Créer un Lakehouse (laisser "Lakehouse schemas" coché)
3. Dans l'explorateur : `Files` → `...` → **New subfolder** → `new_data`

**Étape 2 — Créer le premier Pipeline**
1. Dans le workspace : **New item** → search "Pipeline" → **Data pipeline** → nommer `Ingest Sales Data`
2. Dans l'éditeur : **Copy data** → **Add copy data activity**
3. Configurer la **Source** :
   - Connection : Browse all → créer connection HTTP
   - URL : `https://raw.githubusercontent.com/MicrosoftLearning/dp-data/main/sales.csv`
   - Authentication : Anonymous
   - File format : DelimitedText
   - Settings : First row as header = True
4. Configurer la **Destination** :
   - Connection : Browse all → sélectionner votre lakehouse
   - Root folder : Files
   - File path : `new_data` / `sales.csv`
5. Test connection → Preview data
6. **Save** → **Run** → attendre le succès
7. Vérifier dans le lakehouse : `Files/new_data/sales.csv` existe

**Étape 3 — Créer le Notebook de transformation**
1. Ouvrir le lakehouse → **Open notebook** → **New notebook**
2. Première cellule : marquer comme parameter cell :
```python
table_name = "dbo.sales"
```
3. Ajouter la cellule de transformation (code de la section 6 ci-dessus)
4. **Run all** pour tester
5. Vérifier la création de la table `dbo.sales` dans l'explorateur
6. Renommer le notebook en `Load Sales` (Settings → Name)

**Étape 4 — Améliorer le Pipeline**
1. Retourner dans le pipeline `Ingest Sales Data`
2. Ajouter une activité **Delete Data** avant Copy Data :
   - Source : Lakehouse
   - File path : `Files / new_data`, wildcard `*.csv`
   - Connecter avec **On Completion** → Copy Data
3. Ajouter une activité **Notebook** après Copy Data :
   - Notebook : `Load Sales`
   - Parameter : `table_name` = String = `dbo.new_sales`
   - Connecter avec **On Success** → après Copy Data
4. **Save** → **Run** → surveiller l'exécution dans le volet Output
5. Vérifier que la table `dbo.new_sales` est créée dans le lakehouse

**Étape 5 — Surveiller l'exécution**
1. Dans le menu gauche, aller dans **Monitor**
2. Sélectionner **Pipeline runs**
3. Trouver l'exécution récente de `Ingest Sales Data`
4. Cliquer dessus pour voir le détail de chaque activité
5. Inspecter les durées et les données traitées

## 8. Évaluation des connaissances

*3 minutes*

**Question 1** : Quelle est la différence entre une connexion **On Success** et **On Completion** entre deux activités dans un pipeline ?

- A) Il n'y a pas de différence fonctionnelle
- B) On Success déclenche l'activité suivante seulement si la précédente réussit ; On Completion la déclenche toujours, qu'elle réussisse ou échoue
- C) On Success est pour les activités SQL, On Completion est pour les activités Spark
- D) On Completion est déprécié et remplacé par On Success dans Fabric

> **Réponse : B** — On Success (vert) → exécution conditionnelle en cas de réussite. On Completion (bleu) → exécution inconditionnelle après la fin. Utile pour les activités de nettoyage ou de notification qui doivent toujours s'exécuter.

---

**Question 2** : Quelle est la différence entre une Copy Job et une activité Copy Data dans Microsoft Fabric ?

- A) La Copy Job copie des données en streaming, l'activité Copy Data fait du batch
- B) Une Copy Job est un outil standalone simplifié, une activité Copy Data fait partie d'un pipeline et supporte l'orchestration avec d'autres activités
- C) L'activité Copy Data est limitée aux sources Fabric, la Copy Job supporte toutes les sources externes
- D) Ce sont des noms différents pour le même outil

> **Réponse : B** — La Copy Job est un outil autonome pour la copie simple et rapide. L'activité Copy Data est intégrée dans les pipelines et permet l'orchestration avec Delete Data, Notebook, conditions, etc.

---

**Question 3** : Comment passer une valeur dynamique à un notebook Spark depuis un pipeline ?

- A) En modifiant directement le code du notebook depuis l'interface pipeline
- B) En créant un paramètre dans le pipeline et en le référençant dans la cellule "parameter cell" du notebook
- C) En utilisant une variable d'environnement Fabric
- D) Il n'est pas possible de passer des paramètres à un notebook depuis un pipeline

> **Réponse : B** — Le notebook doit avoir une "parameter cell" avec des variables déclarées. Le pipeline peut surcharger ces valeurs via les "Base parameters" dans les settings de l'activité Notebook.

---

**Question 4** : Quel type de trigger déclenchera automatiquement un pipeline lorsqu'un nouveau fichier arrive dans Azure Data Lake Storage Gen2 ?

- A) Schedule trigger
- B) Manual trigger
- C) Storage Event trigger
- D) Pipeline trigger

> **Réponse : C** — Le Storage Event trigger (aussi appelé Event-based trigger) se déclenche sur des événements de stockage : création ou suppression de blob dans ADLS Gen2 ou Azure Blob Storage.

---

**Question 5** : Dans le monitoring d'un pipeline, que signifie le statut "Succeeded" pour une activité Copy Data ?

- A) Les données ont été copiées et validées dans la destination
- B) L'activité a été lancée avec succès mais le résultat n'est pas encore connu
- C) L'activité s'est terminée sans erreur, les données ont été copiées de la source vers la destination
- D) La connexion à la source a réussi, mais la copie peut encore être en cours

> **Réponse : C** — "Succeeded" signifie que l'activité a terminé son exécution complète avec succès : la connexion a été établie, les données ont été lues de la source, transformées si nécessaire, et écrites dans la destination.

## Résumé

*1 minute*

Dans ce module, vous avez appris à orchestrer les processus de données avec les Pipelines Microsoft Fabric :

- **Pipelines** = workflows d'activités pour orchestrer l'ingestion et la transformation
- **Copy Data** = activité fondamentale pour copier de n'importe quelle source vers n'importe quelle destination
- **Activités de contrôle** = If Condition, For Each, Wait pour des workflows complexes
- **Notebook Activity** = intégrer des transformations Spark dans un pipeline
- **Paramètres** = rendre les pipelines réutilisables avec des valeurs dynamiques
- **Triggers** = déclencher les pipelines manuellement, par planning, ou sur événement
- **Monitoring** = surveiller les exécutions avec détail par activité

### Points clés pour l'examen DP-700

1. Copy Data = activité pipeline / Copy Job = outil standalone
2. On Success → conditionnel / On Completion → toujours
3. "Parameter cell" dans le notebook pour recevoir des paramètres du pipeline
4. Schedule trigger = cron / Event trigger = nouveau fichier ADLS
5. Le monitoring détaille chaque activité : durée, données traitées, erreurs
