## 1. Présentation

*2 minutes*

L'ingestion de données est l'une des étapes les plus critiques de tout pipeline analytique. Avant de pouvoir analyser les données, il faut les extraire de leur source (bases de données opérationnelles, fichiers CSV, APIs, SaaS), les nettoyer, les transformer, et les charger dans le système analytique cible.

Microsoft Fabric propose plusieurs outils pour cette ingestion. Les **Dataflows Gen2** sont l'outil no-code/low-code idéal pour les data engineers et analystes qui préfèrent une interface visuelle à la programmation pure.

**Dataflows Gen2 vs autres outils d'ingestion Fabric :**

| Outil | Approche | Cas d'usage |
|-------|----------|------------|
| Dataflows Gen2 | Visuel (Power Query) | Transformations de niveau analytique, utilisateurs non-développeurs |
| Pipelines + Copy Activity | Configuration | Ingestion de gros volumes, copie simple source → destination |
| Notebooks Spark | Code (PySpark) | Transformations complexes, ML, logique métier avancée |
| Shortcuts | Référence | Accès aux données sans copie |

## 2. Comprendre les Dataflows Gen2 dans Microsoft Fabric

*7 minutes*

### Qu'est-ce qu'un Dataflow Gen2 ?

Un **Dataflow Gen2** est un composant de Data Factory dans Microsoft Fabric qui permet de :
1. **Connecter** des sources de données hétérogènes (plus de 150 connecteurs)
2. **Transformer** les données visuellement avec Power Query Online
3. **Charger** les données transformées dans une destination (lakehouse, warehouse, Azure SQL, etc.)

La technologie sous-jacente est **Power Query** — la même technologie qui propulse les transformations dans Power BI, Excel, et Azure Data Factory. Si vous connaissez Power Query, vous connaissez déjà les Dataflows Gen2.

### Architecture d'un Dataflow Gen2

```
Sources de données              Dataflow Gen2              Destinations
──────────────────     →    ──────────────────────     →  ──────────────
CSV / Excel                   Power Query Online            Lakehouse
SQL Server                    ┌─────────────────┐          Warehouse
Azure SQL Database            │  Source Query   │          Azure SQL DB
SharePoint                    │  + Étapes de    │          KQL Database
REST API                      │  transformation │          Power BI Dataset
Salesforce                    └─────────────────┘          OneLake
+ 150 connecteurs                   M Code
```

### Dataflows Gen2 vs Gen1 (legacy)

Les **Dataflows Gen2** (aussi appelés Dataflows dans Fabric) apportent plusieurs améliorations par rapport à la génération précédente :

| Fonctionnalité | Dataflows Gen1 (Power BI) | Dataflows Gen2 (Fabric) |
|----------------|--------------------------|-------------------------|
| Destinations | Uniquement Power BI datasets | Lakehouse, Warehouse, Azure SQL, + |
| Intégration Pipelines | Limitée | Complète (activité Dataflow dans les pipelines) |
| Performance | Moteur Power Query | Moteur de calcul Fabric optimisé |
| Staging automatique | Non | Oui (données intermédiaires en lakehouse) |
| Monitoring | Basique | Avancé (Run history, métriques) |

### Le moteur Power Query Online

Power Query Online utilise le **langage M** (Power Query Formula Language) pour définir les transformations. Vous n'avez pas besoin de connaître M — l'interface visuelle génère le code M automatiquement pour chaque transformation que vous appliquez.

**Exemple de code M généré automatiquement :**
```
let
    Source = Csv.Document(Web.Contents("https://raw.githubusercontent.com/.../orders.csv")),
    #"Promoted Headers" = Table.PromoteHeaders(Source, [PromoteAllScalars=true]),
    #"Changed Type" = Table.TransformColumnTypes(#"Promoted Headers", {
        {"OrderDate", type date},
        {"Quantity", Int64.Type},
        {"UnitPrice", type number}
    }),
    #"Added MonthNo" = Table.AddColumn(#"Changed Type", "MonthNo", 
        each Date.Month([OrderDate]), Int64.Type)
in
    #"Added MonthNo"
```

## 3. Explorer un Dataflow Gen2 dans Microsoft Fabric

*7 minutes*

### Créer un Dataflow Gen2

**Depuis un Lakehouse :**
1. Ouvrir le lakehouse
2. Sur la page d'accueil : **Get data** → **New Dataflow Gen2**
3. L'éditeur Power Query Online s'ouvre

**Depuis un Workspace :**
1. Dans le workspace : **+ New item** → **Dataflow Gen2**

### Connecter une source de données

Power Query Online propose plus de 150 connecteurs. Quelques exemples courants :

**Fichiers texte/CSV :**
1. Dans l'éditeur, sélectionner **Import from a Text/CSV file**
2. Choisir entre upload local ou URL distante
3. Configurer le séparateur, l'encodage, la ligne d'en-tête

**Exemple avec un fichier CSV distant :**
```
URL : https://raw.githubusercontent.com/MicrosoftLearning/dp-data/main/orders.csv
Connection : Create new connection
Authentication : Anonymous
```

**Base de données SQL Server :**
1. Sélectionner **SQL Server database**
2. Renseigner le serveur, la base de données, les credentials
3. Choisir les tables/vues à importer

**Fichier Excel SharePoint :**
1. Sélectionner **SharePoint Online List** ou **Excel**
2. Fournir l'URL SharePoint
3. Authentification avec compte Microsoft organisationnel

### Transformer les données avec Power Query

Une fois la source connectée, l'éditeur Power Query affiche :
- **Aperçu des données** : les premières lignes de la source
- **Ruban de transformation** : onglets Home, Transform, Add column, View
- **Volet Applied Steps** : liste de toutes les transformations appliquées (à droite)

**Transformations courantes :**

**Changer le type d'une colonne :**
1. Cliquer sur l'icône de type à gauche du nom de colonne
2. Sélectionner le nouveau type (Date, Whole Number, Text, etc.)
3. Une étape "Changed Type" est ajoutée automatiquement

**Ajouter une colonne calculée :**
1. Onglet **Add column** → **Custom column**
2. Nommer la colonne (ex: `MonthNo`)
3. Saisir la formule M : `Date.Month([OrderDate])`
4. Sélectionner le type de données : **Whole Number**

```
// Formule pour extraire le numéro de mois
Date.Month([OrderDate])

// Formule pour créer une colonne de chiffre d'affaires
[Quantity] * [UnitPrice]

// Formule conditionnelle
if [Quantity] > 10 then "Large Order" else "Standard Order"
```

**Filtrer des lignes :**
1. Cliquer sur la flèche du filtre d'une colonne
2. Sélectionner des valeurs, appliquer des conditions (>, <, contient, etc.)

**Renommer des colonnes :**
1. Double-cliquer sur le nom d'une colonne
2. Saisir le nouveau nom

**Combiner des requêtes (Merge/Append) :**
- **Merge** : Jointure entre deux requêtes (équivalent d'un JOIN SQL)
- **Append** : Union de plusieurs requêtes (équivalent d'un UNION SQL)

### Visualiser le Diagram Flow

Le **Diagram Flow** (disponible dans View → Diagram view) affiche graphiquement la chaîne de transformations et les connexions entre les requêtes :

```
[CSV Source] → [Promoted Headers] → [Changed Types] → [Added MonthNo] → [Lakehouse Destination]
```

Chaque étape du diagramme peut être sélectionnée pour voir l'aperçu des données à ce stade précis.

## 4. Configurer la destination de données

*5 minutes*

### Types de destinations supportées

Un Dataflow Gen2 peut charger les données dans plusieurs types de destinations :

| Destination | Type | Cas d'usage |
|-------------|------|------------|
| Lakehouse (Table Delta) | Fabric | Analytique avec Spark et SQL |
| Warehouse | Fabric | Analytique SQL enterprise |
| Azure SQL Database | Azure | Opérationnel + analytique |
| Azure Data Explorer (KQL) | Azure | Time series, logs |
| Fabric KQL Database | Fabric | Analyse en temps réel |

### Configurer la destination Lakehouse

1. Dans l'éditeur Power Query, onglet **Home** → **Add data destination**
2. Sélectionner **Lakehouse**
3. Se connecter avec le compte organisationnel
4. Choisir le workspace et le lakehouse cible
5. Spécifier le nom de la table (nouvelle ou existante)

**Options de chargement :**

| Mode | Description | Cas d'usage |
|------|-------------|------------|
| **Replace** | Vide et recharge la table à chaque exécution | Données complètes qui changent entièrement |
| **Append** | Ajoute les nouvelles lignes sans supprimer l'existant | Ingestion incrémentale, données cumulatives |

**Étapes de configuration :**
1. Sélectionner **Next** après avoir choisi le lakehouse
2. Nommer la table cible (ex: `orders`)
3. Choisir le mode : **Append** ou **Replace**
4. Désactiver "Use automatic settings" pour contrôler les types manuellement
5. **Save settings**
6. Cliquer **Save & run** dans le ruban Home

**Vérifier le résultat :**
Après l'exécution, dans l'explorateur du lakehouse, la table `orders` apparaît sous le dossier Tables avec toutes les données transformées.

### Surveillance d'un Dataflow

Après exécution, vous pouvez consulter l'historique :
- Dans le workspace, sélectionner les **...** du Dataflow → **Settings**
- Voir **Run history** : horodatage, durée, statut (Success/Failed)
- En cas d'échec : consulter les messages d'erreur pour diagnostiquer

## 5. Intégrer Dataflows Gen2 et Pipelines dans Microsoft Fabric

*2 minutes*

### Pourquoi intégrer Dataflows dans des Pipelines ?

Un Dataflow seul peut être exécuté manuellement ou planifié. Mais pour des workflows complexes où vous avez besoin :
- D'enchaîner plusieurs Dataflows dans un ordre précis
- De combiner un Dataflow avec une activité Notebook ou Copy Data
- De gérer les erreurs et les notifications
- D'exécuter des activités en parallèle ou en séquence conditionnelle

...vous devez intégrer le Dataflow dans un **Pipeline Data Factory**.

### Ajouter un Dataflow à un Pipeline

1. Dans le workspace, **+ New item** → **Data pipeline**
2. Dans l'éditeur de pipeline, sélectionner **Pipeline activity** → **Dataflow**
3. Sur le canvas, sélectionner l'activité Dataflow
4. Dans le panneau Settings → **Dataflow** : sélectionner le Dataflow créé précédemment
5. Sauvegarder et exécuter le pipeline

**Architecture typique Pipeline + Dataflow :**
```
Pipeline "Daily Ingestion"
├── Copy Activity (ingérer fichiers bruts vers Files/)
├── Dataflow Activity (transformer et charger vers Tables/)
│     └── → orders (table Delta dans le lakehouse)
└── Notebook Activity (créer agrégats Gold si nécessaire)
```

### Planifier l'exécution

Un Pipeline peut être déclenché :
- **Manuellement** (bouton Run dans l'interface)
- **Planifié** (Schedule trigger : tous les jours à 6h, toutes les heures, etc.)
- **Sur événement** (Storage event trigger : nouveau fichier dans ADLS)
- **Depuis un autre Pipeline** (Execute Pipeline activity)

**Configurer un trigger planifié :**
1. Dans le pipeline, **Add trigger** → **New/Edit**
2. Sélectionner **Schedule**
3. Configurer la récurrence (quotidien, hebdomadaire, cron expression)
4. Sélectionner le fuseau horaire
5. Activer le trigger

## 6. Exercice — Créer et utiliser un Dataflow Gen2 dans Microsoft Fabric

*30 minutes*

> **Prérequis** : Accès à une capacité Fabric

### Étapes de l'exercice

**Étape 1 — Créer un workspace et un lakehouse**
1. Naviguer vers [app.fabric.microsoft.com](https://app.fabric.microsoft.com)
2. Créer un workspace avec capacité Fabric
3. Créer un **Lakehouse** (nom de votre choix)

**Étape 2 — Créer un Dataflow Gen2**
1. Sur la page du lakehouse : **Get data** → **New Dataflow Gen2**
2. L'éditeur Power Query s'ouvre

**Étape 3 — Connecter la source CSV**
1. Sélectionner **Import from a Text/CSV file**
2. Configurer avec les paramètres suivants :
   - **Link to file** : Sélectionné
   - **URL** : `https://raw.githubusercontent.com/MicrosoftLearning/dp-data/main/orders.csv`
   - **Connection** : Create new connection
   - **Authentication kind** : Anonymous
3. Cliquer **Next** pour prévisualiser, puis **Create**

**Étape 4 — Ajouter des transformations**
1. Vérifier que la colonne `OrderDate` est de type **Date** (changer si nécessaire)
2. Onglet **Add column** → **Custom column**
3. Configurer :
   - **New column name** : `MonthNo`
   - **Data type** : Whole Number
   - **Formula** : `Date.Month([OrderDate])`
4. Cliquer **OK**
5. Vérifier dans l'aperçu que la colonne `MonthNo` contient des nombres 1-12

**Étape 5 — Configurer la destination Lakehouse**
1. Onglet **Home** → **Add data destination** → **Lakehouse**
2. Se connecter avec le compte organisationnel
3. Trouver et sélectionner votre lakehouse
4. Table name : `orders`
5. Cliquer **Next**
6. Désactiver "Use automatic settings"
7. Mode : **Append**
8. **Save settings**

**Étape 6 — Activer le Diagram view et sauvegarder**
1. View → **Diagram view** pour visualiser le flux
2. Onglet **Home** → **Save & run**
3. Attendre la fin d'exécution (2-5 minutes)
4. Vérifier dans le lakehouse que la table `orders` a été créée avec les données

**Étape 7 — Créer un Pipeline avec le Dataflow**
1. Dans le workspace : **+ New item** → **Data pipeline** → nommer `Load data`
2. **Pipeline activity** → **Dataflow**
3. Sélectionner le Dataflow créé dans Settings → Dataflow
4. Sauvegarder et exécuter le pipeline
5. Vérifier que le pipeline réussit

## 7. Évaluation des connaissances

*10 minutes*

**Question 1** : Quelle est la principale différence entre un Dataflow Gen2 et un Dataflow Gen1 (Power BI) ?

- A) Le Gen2 supporte uniquement les sources Azure, le Gen1 supporte toutes les sources
- B) Le Gen2 permet de charger les données dans plusieurs types de destinations (lakehouse, warehouse, Azure SQL), pas seulement les datasets Power BI
- C) Le Gen1 est plus rapide car il utilise DirectQuery, le Gen2 utilise Import
- D) Le Gen2 nécessite du code PySpark, le Gen1 est entièrement no-code

> **Réponse : B** — La différence majeure des Dataflows Gen2 est la flexibilité des destinations : lakehouse, warehouse, Azure SQL, KQL database, etc. Les Gen1 étaient limités aux datasets Power BI.

---

**Question 2** : Dans un Dataflow Gen2, qu'est-ce que le "Applied Steps" (étapes appliquées) ?

- A) La liste des tables source connectées au Dataflow
- B) Les étapes de chargement dans la destination (table cible)
- C) La liste ordonnée des transformations appliquées à la requête, chacune pouvant être inspectée ou modifiée
- D) Le journal d'exécution du Dataflow avec les temps de traitement

> **Réponse : C** — Le volet Applied Steps montre chaque transformation dans l'ordre. Vous pouvez cliquer sur n'importe quelle étape pour voir l'état des données à ce point, modifier l'étape, ou la supprimer.

---

**Question 3** : Quel mode de chargement faut-il choisir si vous voulez que le Dataflow ajoute uniquement les nouvelles données sans supprimer les données existantes ?

- A) Replace (Remplacer)
- B) Merge (Fusionner)
- C) Append (Ajouter)
- D) Overwrite (Écraser)

> **Réponse : C** — Le mode **Append** ajoute les nouvelles lignes aux données existantes. Le mode **Replace** vide et recharge entièrement la table à chaque exécution.

---

**Question 4** : Pourquoi intégrer un Dataflow Gen2 dans un Pipeline Data Factory ?

- A) Pour améliorer les performances d'exécution du Dataflow
- B) Pour orchestrer le Dataflow avec d'autres activités, gérer les erreurs, et planifier des workflows complexes
- C) Pour transformer les données en temps réel au lieu de batch
- D) Pour accéder à des connecteurs disponibles uniquement dans les Pipelines

> **Réponse : B** — Les Pipelines permettent d'orchestrer des workflows : enchaîner plusieurs Dataflows, combiner avec Copy Activity et Notebook Activity, gérer les branches d'erreur (success/failure), et planifier l'exécution complète.

---

**Question 5** : Quel langage est utilisé sous-jacent par Power Query Online pour définir les transformations dans un Dataflow Gen2 ?

- A) Python (pandas)
- B) SQL (T-SQL)
- C) M (Power Query Formula Language)
- D) DAX (Data Analysis Expressions)

> **Réponse : C** — Power Query utilise le **langage M** (aussi appelé Power Query Formula Language). L'interface visuelle génère automatiquement le code M, mais vous pouvez aussi l'éditer directement via l'éditeur avancé.

## Résumé

*2 minutes*

Dans ce module, vous avez appris à utiliser les Dataflows Gen2 dans Microsoft Fabric :

- **Dataflows Gen2** sont des outils no-code/low-code basés sur Power Query Online
- Plus de **150 connecteurs** disponibles pour connecter des sources hétérogènes
- Les transformations sont définies visuellement dans l'éditeur **Power Query**
- Le code **M** est généré automatiquement et peut être inspecté/modifié
- Les destinations supportées incluent **Lakehouse**, **Warehouse**, **Azure SQL**, **KQL Database**
- Le mode **Append** ajoute des données, **Replace** recharge entièrement la table
- Les Dataflows peuvent être intégrés dans des **Pipelines** pour l'orchestration
- Les Pipelines permettent la **planification** et la gestion des erreurs

### Points clés pour l'examen DP-700

1. Dataflows Gen2 = Power Query Online + destinations multiples
2. Applied Steps = liste des transformations (inspectables, modifiables)
3. Mode Append = incrémental / Mode Replace = remplacement complet
4. Intégrer dans un Pipeline pour orchestrer et planifier
5. Aucun code requis — interface 100% visuelle
