# Utilisez Activator dans Microsoft Fabric

*1 h 1 min*
Module *(7 Unités)*
Intermédiaire
Ingénieur Data
Analyste de données
Microsoft Fabric

Fabric Activator est un moteur de détection d'événements qui déclenche automatiquement des actions lorsque des modèles ou des conditions spécifiques sont détectés dans des sources de données en temps réel. Il ferme la boucle entre l'analytique temps réel et l'action concrète.

---

## Objectifs d'apprentissage

Dans ce module, vous allez apprendre à :

- Décrire le rôle et l'architecture d'Activator dans Microsoft Fabric
- Créer et configurer un Activator depuis une source de données
- Définir des objets et des propriétés à partir d'un eventstream
- Créer des règles avec des conditions et des filtres de propriétés
- Configurer des actions (email, Teams, Power Automate)
- Démarrer, arrêter et monitorer des règles Activator
- Intégrer Activator avec des dashboards Real-Time et des rapports Power BI

## Présentation

*4 min*
Effectué — 100 XP

L'analytique en temps réel est utile. Savoir que la température d'un équipement industriel est en train de monter, c'est bien. Mais si personne ne regarde le dashboard à ce moment précis, cette information n'a aucun impact. Le problème fondamental de nombreux systèmes de monitoring est qu'ils supposent qu'un humain surveille les données en permanence.

**Activator** résout ce problème. C'est le composant de Microsoft Fabric qui transforme les observations passives en **réactions actives**. Au lieu de demander à quelqu'un de surveiller des données, Activator surveille automatiquement ces données 24h/24, 7j/7 et déclenche les bonnes actions — envoyer un email d'alerte, notifier une équipe sur Teams, démarrer un workflow Power Automate, exécuter un pipeline — au moment exact où une condition est remplie.

Activator s'appelle également "Reflex" dans certaines versions de la documentation Microsoft — les deux termes désignent le même composant. Il est le dernier maillon de la chaîne RTI : Eventstream collecte, l'Eventhouse stocke et analyse, le Real-Time Dashboard visualise, et **Activator agit**.

Dans ce module, vous allez apprendre à créer des règles Activator intelligentes pour automatiser les réponses aux événements dans vos données en temps réel, en passant par un scénario concret de monitoring de livraison de colis.

## Configurer l'Activator pour vos données

*7 min*
Effectué — 100 XP

### Architecture d'Activator

Activator est organisé autour de trois concepts fondamentaux : les **objets**, les **propriétés** et les **règles**.

```
┌──────────────────────────────────────────────────────────────────┐
│                           ACTIVATOR                              │
│                                                                  │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │                    OBJET (ex: Package)                  │    │
│  │  Représente une entité surveillée (package, appareil…)  │    │
│  │  Identifié par un champ unique (PackageId, DeviceId…)   │    │
│  │                                                         │    │
│  │  ┌───────────────────────────────────────────────┐     │    │
│  │  │          PROPRIÉTÉ (ex: Temperature)          │     │    │
│  │  │  Un attribut de l'objet à surveiller          │     │    │
│  │  │  Alimentée par une colonne de l'eventstream   │     │    │
│  │  │                                               │     │    │
│  │  │  ┌─────────────────────────────────────┐     │     │    │
│  │  │  │        RÈGLE (ex: Too hot)           │     │     │    │
│  │  │  │  Condition + Filtre + Action         │     │     │    │
│  │  │  │  • Condition: Temperature > 20       │     │     │    │
│  │  │  │  • Filtre: SpecialCare = "Medicine"  │     │     │    │
│  │  │  │  • Action: Envoyer email             │     │     │    │
│  │  │  └─────────────────────────────────────┘     │     │    │
│  │  └───────────────────────────────────────────────┘     │    │
│  └─────────────────────────────────────────────────────────┘    │
│                                                                  │
│  Source de données: Eventstream, KQL query, Power BI report      │
└──────────────────────────────────────────────────────────────────┘
```

### Sources de données supportées

Activator peut surveiller plusieurs types de sources :

1. **Eventstream** : surveillance directe d'un flux de données en temps réel (événement par événement)
2. **Résultats de requêtes KQL** : surveillance de métriques calculées dans un Eventhouse (via un KQL Queryset ou un Real-Time Dashboard)
3. **Rapports Power BI** : alerte quand une valeur dans un visuel Power BI dépasse un seuil
4. **Real-Time Hub** : surveillance de streams actifs dans l'organisation

### Créer un Activator

Deux façons de créer un Activator :

**Méthode 1 : Depuis le menu Create**
1. Dans le workspace, cliquez **+ New item**
2. Sous **Real-Time Intelligence**, sélectionnez **Activator**
3. Un Activator vide est créé avec un écran d'accueil proposant des options de démarrage

**Méthode 2 : Depuis un dashboard Real-Time (Set alert)**
1. Dans un Real-Time Dashboard, cliquez sur **Set alert** dans la toolbar
2. Configurez l'alerte (run query every, condition, action)
3. Cliquez **Create** — un Activator est créé automatiquement dans votre workspace

**Méthode 3 : Depuis un KQL Queryset (Set alert)**
1. Dans un KQL Queryset, sélectionnez une requête
2. Cliquez sur **Set alert** dans la toolbar
3. Configurez et créez — l'Activator est lié à la requête

### Interface de l'Activator

L'interface principale d'Activator comprend :

- **Panneau Explorer** (gauche) : liste hiérarchique des streams de données, objets, propriétés et règles
- **Panneau Event details** (centre-droite) : table en direct des événements arrivant dans le stream sélectionné
- **Panneau Definition** (droite) : configuration détaillée d'une règle sélectionnée (Monitor, Condition, Property filter, Action)

### Utiliser les données d'exemple

Pour explorer Activator sans données réelles, Microsoft fournit un jeu de données d'exemple :

1. Depuis l'écran d'accueil de l'Activator, cliquez sur **Try sample**
2. Un dataset simulant des livraisons de colis est chargé automatiquement :
   - **Package delivery events** : stream d'événements de livraison
   - **Package** : objet pré-créé avec des propriétés (City, Temperature, SpecialCare, ColdChainType)
   - Règles d'exemple pré-configurées (ex : "Too hot for medicine")

### Explorer les événements du sample

1. Dans le panneau **Explorer**, sélectionnez **Package delivery events**
2. Observez la table **Event details** : chaque ligne est un événement entrant avec des champs comme `PackageId`, `City`, `Temperature`, `SpecialCare`, `ColdChainType`
3. Cette table se met à jour en temps réel avec les nouveaux événements générés par le sample

## Créer des règles dans Activator

*6 min*
Effectué — 100 XP

### Comprendre les objets

Un **objet** dans Activator représente une **entité du monde réel** que vous souhaitez surveiller. Par exemple :
- Un **Package** (colis en livraison)
- Un **Appareil IoT** (capteur de température)
- Un **Symbole boursier** (action en bourse)
- Une **Station vélo** (vélos disponibles)

Chaque objet est identifié par un **Unique Identifier** — un champ de l'eventstream qui identifie de manière unique chaque instance de l'objet (ex : `PackageId`, `DeviceId`, `Symbol`, `StationId`).

Un objet a des **propriétés** : les attributs que vous voulez surveiller. Ce sont des colonnes de l'eventstream (ex : `Temperature`, `Price`, `No_Bikes`).

### Créer un objet

1. Dans le panneau **Explorer**, sélectionnez le stream de données source
2. Cliquez sur **New object** dans le ruban
3. Dans le panneau **Build object** :
   - **Object name** : nom descriptif de l'entité (ex : `Redmond Packages`)
   - **Unique Identifier** : champ identifiant unique (ex : `PackageId`)
   - **Properties** : liste des champs à surveiller (ex : `City`, `ColdChainType`, `SpecialCare`, `Temperature`)
4. Cliquez **Create**

L'objet apparaît dans le panneau Explorer avec ses propriétés listées en dessous.

### Structure d'une règle

Une **règle Activator** est composée de 4 éléments :

#### 1. Monitor (Surveillance)
Définit quelle propriété est surveillée et pour quel événement.

- **Event** : le stream d'événements source (ex : `Package delivery events-event`)
- **Property** : la propriété de l'objet à surveiller (ex : `Temperature`)

#### 2. Condition
Définit le critère de déclenchement. Les conditions disponibles varient selon le type de données :

**Conditions numériques :**
| Condition | Description |
|-----------|-------------|
| `Is greater than` | La valeur dépasse un seuil |
| `Is less than` | La valeur est inférieure à un seuil |
| `Is greater than or equal to` | Dépasse ou égale un seuil |
| `Is less than or equal to` | Inférieur ou égal à un seuil |
| `Increases by` | Augmentation d'un certain montant |
| `Decreases by` | Diminution d'un certain montant |
| `Increases by %` | Augmentation en pourcentage |
| `Decreases by %` | Diminution en pourcentage |
| `Becomes equal to` | Atteint exactement une valeur |
| `Becomes not equal to` | N'est plus égal à une valeur |

**Conditions textuelles :**
- `Is equal to`, `Is not equal to`
- `Contains`, `Does not contain`
- `Starts with`, `Ends with`

**Conditions d'occurrence :**
- `Every time the condition is met` : déclenche à chaque occurrence
- `At least once in a time period` : déclenche si la condition est vraie au moins une fois dans une fenêtre de temps

#### 3. Property filter (Filtre de propriété)
Limite le déclenchement de la règle à des instances spécifiques de l'objet. Vous pouvez ajouter plusieurs filtres combinés en AND.

Exemple : déclencher uniquement si `City == "Redmond"` ET `SpecialCare == "Medicine"` ET `ColdChainType == "Refrigerated"`.

Cela permet de créer des règles très ciblées sur des segments précis de vos données, sans créer un Activator séparé pour chaque cas.

#### 4. Action
Définit ce qui se passe quand la condition est remplie.

### Créer une règle

1. Sélectionnez la **propriété** à surveiller dans le panneau Explorer (ex : `Temperature` sous `Redmond Packages`)
2. Cliquez sur **New Rule** dans le ruban
3. Dans le panneau **Create rule** :
   - **Condition** : `Increases above`
   - **Value** : `20`
   - **Occurrence** : `Every time the condition is met`
   - **Action** : `Send me an email`
4. Cliquez **Create**
5. Renommez la règle en cliquant sur l'icône crayon (ex : `Medicine temp out of range`)

### Ajouter des filtres de propriété

Après création de la règle :

1. Dans le panneau **Definition**, développez la section **Property filter**
2. Ajoutez le **Filter 1** :
   - Attribut : `City`
   - Operation : `Is equal to`
   - Value : `Redmond`
3. Cliquez **Add filter**, ajoutez **Filter 2** :
   - Attribut : `SpecialCare`
   - Operation : `Is equal to`
   - Value : `Medicine`
4. Cliquez **Add filter**, ajoutez **Filter 3** :
   - Attribut : `ColdChainType`
   - Operation : `Is equal to`
   - Value : `Refrigerated`

La règle ne se déclenchera maintenant que pour des colis réfrigérés contenant des médicaments et destinés à Redmond.

## Configurer des actions dans Activator

*3 min*
Effectué — 100 XP

### Types d'actions disponibles

Activator supporte plusieurs types d'actions qui peuvent être configurées pour chaque règle :

#### Email
Envoie un email de notification à un ou plusieurs destinataires.

Configuration :
- **To** : destinataires (email ou groupe de distribution)
- **Subject** : sujet de l'email (texte fixe ou avec variables d'événement)
- **Headline** : titre affiché dans le corps de l'email
- **Message** : corps du message (texte fixe)
- **Context** : colonnes de données incluses dans l'email (sélectionnez les propriétés pertinentes, ex : `Temperature`, `PackageId`, `City`)

Exemple de configuration :
```
To: shipping@contoso.com
Subject: Redmond Medical Package outside acceptable temperature range
Headline: Temperature too high
Context: Temperature, PackageId, City
```

L'email reçu contient le sujet, le titre, et un tableau avec les valeurs des propriétés sélectionnées dans **Context** au moment du déclenchement.

#### Microsoft Teams
Envoie un message dans un canal Teams ou en message direct.

Configuration :
- **Team** : équipe Teams cible
- **Channel** : canal dans l'équipe
- **Message** : contenu du message

#### Power Automate (Workflow)
Déclenche un workflow Power Automate existant, permettant des intégrations complexes (ServiceNow, Jira, SAP, ERP...).

Configuration :
- **Power Automate flow URL** : URL du webhook Power Automate
- **Payload** : données transmises au workflow

#### Fabric items
Exécute des items Fabric directement :
- **Pipeline** : exécute un pipeline Data Factory
- **Spark job** : soumet un job Spark
- **Dataflow** : rafraîchit un Dataflow Gen2

Ces actions permettent d'orchestrer automatiquement des traitements de données en réponse à des événements (ex : retraining d'un modèle ML quand une anomalie est détectée, archivage de données quand un quota est atteint).

### Tester une action

Avant de démarrer une règle, vous pouvez tester l'action :

1. Dans la section **Action**, cliquez sur **Send me a test action**
2. L'action est exécutée immédiatement avec des données simulées
3. Vérifiez que vous avez reçu l'email/message Teams attendu

### Démarrer et arrêter une règle

Pour activer une règle :
1. Cliquez sur **Save and start** dans le panneau Definition
2. La règle est maintenant active et surveille les données en continu

Pour désactiver :
1. Cliquez sur **Stop** dans le ruban lorsque la règle est sélectionnée

### Monitorer les déclenchements

Chaque règle a un onglet **History** qui enregistre chaque instance de déclenchement :
- Date et heure du déclenchement
- Valeurs des propriétés au moment du déclenchement
- Statut de l'action (succès, échec)

L'onglet **Analytics** affiche des graphiques montrant la fréquence des déclenchements au fil du temps.

### Créer une alerte depuis un Real-Time Dashboard

Activator s'intègre directement dans les Real-Time Dashboards via le bouton **Set alert** :

1. Dans le dashboard, cliquez sur **Set alert** dans la toolbar
2. Configurez l'alerte :
   - **Run query every** : fréquence d'évaluation (5 min, 15 min...)
   - **Check** : `On each event grouped by`
   - **Grouping field** : champ de groupement (ex : `symbol`)
   - **When** : la métrique à surveiller (ex : `avgPrice`)
   - **Condition** : `Increases by` / `Decreases by` / etc.
   - **Value** : seuil
   - **Action** : `Send me an email`
   - **Save location** : workspace et nom de l'item Activator à créer

3. Cliquez **Create**

Un item Activator est créé dans votre workspace, lié à la requête KQL du dashboard. La règle s'exécute selon la fréquence définie et envoie des alertes quand la condition est remplie.

## Exercice — Utiliser Activator dans Fabric

*30 min*
Effectué — 100 XP

### Scénario du lab

Vous êtes analyste de données pour une entreprise de livraison. Vous souhaitez créer une alerte qui envoie un email à l'équipe logistique si la température d'un colis contenant des médicaments réfrigérés dépasse 20°C pendant le transport vers Redmond.

### Étape 1 : Créer un workspace et un Activator avec des données d'exemple

1. Créez un workspace Fabric
2. Depuis le menu **Create > Real-Time Intelligence**, sélectionnez **Activator**
3. Nommez-le `Contoso Shipping Activator` (renommez depuis la liste déroulante en haut à gauche)

### Étape 2 : Charger les données d'exemple

1. Sur l'écran d'accueil de l'Activator, cliquez sur **Try sample**
2. Les données d'exemple sont chargées (cela peut prendre 1-2 minutes)

### Étape 3 : Explorer les données du sample

1. Dans le panneau **Explorer**, sélectionnez **Package delivery events**
2. Observez les événements en temps réel dans la table **Event details** :
   - `PackageId` : identifiant unique du colis
   - `City` : ville de destination
   - `Temperature` : température actuelle du colis
   - `SpecialCare` : type de soin spécial (ex : Medicine)
   - `ColdChainType` : type de chaîne du froid (ex : Refrigerated)
3. Notez que les données changent en temps réel

### Étape 4 : Explorer une règle existante

1. Dans le panneau **Explorer**, sous l'objet **Package**, puis sous la propriété **Temperature**, sélectionnez la règle **Too hot for medicine**
2. Dans le panneau **Definition**, observez :
   - **Monitor** : propriété `Temperature` surveillée
   - **Condition** : `Is greater than 20`
   - **Property filter** : `SpecialCare` contains `Medicine`
   - **Action** : Teams message (ou email)
3. Cliquez sur **Send me a test action** pour tester le déclenchement

### Étape 5 : Créer un nouvel objet

Créez un objet spécifique pour les livraisons à Redmond :

1. Sélectionnez le stream **Package delivery events**
2. Cliquez sur **New object** dans le ruban
3. Configurez :
   - **Object name** : `Redmond Packages`
   - **Unique Identifier** : `PackageId`
   - **Properties** : `City`, `ColdChainType`, `SpecialCare`, `Temperature`
4. Cliquez **Create**

### Étape 6 : Créer la règle de température

1. Sélectionnez la propriété **Temperature** sous l'objet **Redmond Packages**
2. Cliquez sur **New Rule** dans le ruban
3. Configurez :
   - **Condition** : `Increases above`
   - **Value** : `20`
   - **Occurrence** : `Every time the condition is met`
   - **Action** : `Send me an email`
4. Cliquez **Create**
5. Renommez la règle en `Medicine temp out of range` (cliquez sur l'icône crayon)

### Étape 7 : Ajouter les filtres de propriété

1. Dans la section **Property filter**, ajoutez trois filtres :
   - **Filter 1** : `City` → `Is equal to` → `Redmond`
   - **Filter 2** : `SpecialCare` → `Is equal to` → `Medicine`
   - **Filter 3** : `ColdChainType` → `Is equal to` → `Refrigerated`
2. Vérifiez que les trois filtres sont bien combinés en AND

### Étape 8 : Configurer l'action email

Dans la section **Action** :
- **Type** : Email
- **To** : votre adresse email (sélectionnée par défaut)
- **Subject** : `Redmond Medical Package outside acceptable temperature range`
- **Headline** : `Temperature too high`
- **Context** : cochez `Temperature`

### Étape 9 : Tester et démarrer la règle

1. Cliquez sur **Send me a test action** pour vérifier que vous recevez l'email
2. Vérifiez l'email reçu : il contient le sujet, le titre et les données de contexte
3. Cliquez sur **Save and start** pour activer la règle
4. Observez l'onglet **Analytics** pour voir les déclenchements au fil du temps

### Étape 10 : Vérifier l'historique

Après quelques minutes (ou plusieurs heures selon la fréquence de déclenchement) :
1. Cliquez sur l'onglet **History** de la règle
2. Observez les déclenchements enregistrés avec leur timestamp et les valeurs associées
3. Cliquez sur **Stop** dans le ruban pour arrêter la règle

### Résultat attendu

Vous avez créé un Activator fonctionnel qui :
- Surveille en temps réel les livraisons de colis
- Filtre spécifiquement les colis médicaux réfrigérés à destination de Redmond
- Envoie un email d'alerte chaque fois que la température dépasse 20°C

**Question 2**
Vous configurez une règle Activator pour alerter quand la température d'un colis dépasse 20°C. Vous ne voulez déclencher cette alerte que pour les colis contenant des médicaments. Quelle fonctionnalité utilisez-vous pour cette restriction ?

- A) Créer un objet séparé pour les médicaments

## Résumé

*1 min*

Dans ce module, vous avez maîtrisé **Activator**, le composant de Microsoft Fabric qui transforme les insights temps réel en actions automatiques.

Points clés à retenir :

- **Activator** surveille des données en continu et déclenche des actions quand des conditions ou des patterns spécifiques sont détectés — il ferme la boucle entre analytique et action
- L'architecture d'Activator repose sur trois concepts : **objets** (entités surveillées), **propriétés** (attributs à observer) et **règles** (conditions + actions)
- Les règles comprennent : un **monitor** (quelle propriété), une **condition** (quel seuil), un **filtre de propriété** optionnel (pour quelles instances), et une **action** (quoi faire)
- Les **filtres de propriété** permettent de cibler très précisément les instances d'un objet qui déclenchent une règle (ex : uniquement les colis médicaux réfrigérés à Redmond)
- Les **actions disponibles** incluent : email, Microsoft Teams, Power Automate workflows, et l'exécution directe d'items Fabric (pipelines, Spark jobs, Dataflows)
- Activator s'intègre directement dans les **Real-Time Dashboards** via le bouton **Set alert**, et dans les **KQL Querysets** de la même manière
- L'onglet **History** enregistre tous les déclenchements, l'onglet **Analytics** affiche leur fréquence dans le temps
- Activator peut surveiller des **rapports Power BI** en plus des streams temps réel

Activator complète l'écosystème Real-Time Intelligence en permettant de passer de l'observation passive à la réponse automatisée, créant de véritables solutions **event-driven** dans Microsoft Fabric.
