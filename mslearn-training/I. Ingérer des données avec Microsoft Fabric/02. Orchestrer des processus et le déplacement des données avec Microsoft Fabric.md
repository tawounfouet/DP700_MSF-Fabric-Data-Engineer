# Orchestrer des processus et le déplacement des données avec Microsoft Fabric

*1 h 21 min* | Module *(8 Unités)* | Débutant | Analyste de données | Ingénieur Data | Microsoft Fabric

Microsoft Fabric inclut des fonctionnalités Data Factory, notamment la possibilité de créer des **pipelines** qui orchestrent les tâches d'ingestion et de transformation des données. Un pipeline est un flux de travail configurable permettant de combiner des activités de copie, de transformation, d'exécution de code et de notification dans un processus automatisé et surveillé.

- Combiner des activités Copy Data, Dataflow et Notebook dans un pipeline ETL complet

## Présentation
*1 min* | 100 XP

### Le problème de l'orchestration des données

Dans une architecture analytique moderne, l'ingestion de données n'est jamais un acte isolé. Elle implique généralement plusieurs étapes séquentielles :

1. **Extraire** des données depuis une ou plusieurs sources (base de données opérationnelle, fichiers, APIs)
2. **Stocker** les données brutes dans une zone de staging
3. **Transformer** les données (nettoyage, enrichissement, agrégation)
4. **Charger** les données dans leur destination finale (Lakehouse, Warehouse)
5. **Notifier** les équipes en cas de succès ou d'échec

Faire cela manuellement est laborieux, non reproductible et source d'erreurs. C'est là qu'interviennent les **pipelines Data Factory** dans Microsoft Fabric.

### Qu'est-ce qu'un pipeline ?

Un pipeline est un **flux de travail configuré graphiquement** qui enchaîne des activités dans un ordre défini, avec des conditions de branchement (si succès, si échec, si complétion). Il peut être :

- Déclenché manuellement à la demande
- Planifié automatiquement (quotidien, hebdomadaire, etc.)
- Déclenché par un événement (nouveau fichier dans un stockage, fin d'un autre pipeline)

**Analogie** : Pensez à un pipeline comme à une **recette de cuisine automatisée** — chaque activité est une étape de la recette, les conditions de branchement sont des "si le four est chaud, alors enfourner", et le déclencheur est l'alarme qui lance la préparation chaque matin.

## Comprendre les pipelines
*6 min* | 100 XP

### Structure d'un pipeline

Un pipeline dans Microsoft Fabric est composé de :

**Activités** : Les blocs de base d'un pipeline. Chaque activité effectue une tâche spécifique. Il existe de nombreux types d'activités.

**Flux de contrôle (Control Flow)** : Les connexions entre activités. Chaque activité peut avoir trois types de sorties :
- **On Success** (vert) : L'activité suivante s'exécute si cette activité réussit
- **On Failure** (rouge) : L'activité suivante s'exécute si cette activité échoue
- **On Completion** (bleu) : L'activité suivante s'exécute quelle que soit la issue

**Paramètres** : Variables que vous pouvez définir au niveau du pipeline et passer à toutes les activités. Permettent de rendre un pipeline réutilisable avec différentes configurations.

**Variables** : Valeurs calculées dynamiquement pendant l'exécution du pipeline.

**Déclencheurs** : Mécanismes qui démarrent l'exécution d'un pipeline.

### Types d'activités disponibles

**Activités de déplacement de données :**
- **Copy Data** : Copie des données d'une source vers une destination
- **Delete Data** : Supprime des fichiers dans un stockage

**Activités de transformation :**
- **Dataflow** : Exécute un flux de données Gen2
- **Notebook** : Exécute un notebook Apache Spark
- **Stored Procedure** : Exécute une procédure stockée SQL
- **Script** : Exécute un script SQL personnalisé

**Activités de contrôle de flux :**
- **If Condition** : Branchement conditionnel (if/else)
- **Switch** : Branchement multiple (switch/case)
- **ForEach** : Itération sur une collection de valeurs
- **Until** : Boucle jusqu'à ce qu'une condition soit vraie
- **Wait** : Attendre un nombre de secondes avant de continuer
- **Set Variable** : Assigner une valeur à une variable

**Activités de notification et monitoring :**
- **Web Activity** : Appel HTTP vers une API externe (ex. Teams Webhook, Slack)
- **Fail** : Forcer l'échec du pipeline avec un message d'erreur personnalisé

### Architecture visuelle d'un pipeline

```
┌─────────────────────────────────────────────────────────────────────┐
│                        Pipeline Canvas                              │
│                                                                     │
│  [Déclencheur]  ──▶  [Delete old files]  ──✓──▶  [Copy Data]       │
│                                                        │            │
│                                                   ──✓──▼            │
│                                              [Notebook Transform]   │
│                                                        │            │
│                                      ┌────✓────────────┘            │
│                                      │                              │
│                              [Email Success]                        │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## Utiliser l'activité Copier des données
*3 min* | 100 XP

### Rôle de l'activité Copy Data

L'activité **Copy Data** est l'activité la plus fondamentale d'un pipeline. Elle permet de copier des données d'une source vers une destination, en gérant automatiquement :

- La connexion aux sources et destinations
- La conversion de formats (CSV vers Parquet, JSON vers Delta, etc.)
- La gestion des colonnes (mappage, renommage)
- La compression/décompression
- Le traitement des erreurs de données

**Différence avec un Dataflow** : L'activité Copy Data est optimisée pour le **mouvement de données brutes** à grande vitesse. Elle ne fait pas de transformations complexes. Les dataflows Gen2 et les notebooks sont préférés pour les transformations. Une bonne pratique ETL est :

```
[Copy Data] ──▶ [Zone staging / brute] ──▶ [Notebook/Dataflow] ──▶ [Table finale]
```

> **Note** : Une *Copy Job* (Job de copie) est un outil distinct et simplifié pour le déplacement de données. L'activité *Copy Data* dans un pipeline supporte l'orchestration complète avec d'autres activités. Dans un contexte DP-700, vous travaillez avec l'activité Copy Data dans les pipelines.

### Configurer la Source

La source peut être n'importe quel connecteur supporté (HTTP, Azure Blob, Azure SQL, SharePoint, etc.).

**Exemple de configuration pour une source HTTP (fichier CSV) :**

| Propriété | Valeur |
|---|---|
| URL | `https://raw.githubusercontent.com/.../sales.csv` |
| Méthode | GET |
| Format de fichier | DelimitedText (CSV) |
| Délimiteur de colonne | Virgule (,) |
| Délimiteur de ligne | Saut de ligne (\n) |
| Première ligne en en-tête | Oui |

### Configurer la Destination

La destination indique où copier les données.

**Exemple de configuration pour une destination Lakehouse :**

| Propriété | Valeur |
|---|---|
| Connexion | Sélectionner le Lakehouse via OneLake Catalog |
| Dossier racine | Files |
| Chemin du fichier | `new_data/sales.csv` |

### Paramètres de formatage

L'onglet "File format settings" permet de configurer précisément le comportement :

```
Compression : Aucune / Gzip / Deflate / ZipDeflate
Délimiteur de colonne : , / ; / Tab / Pipe (|)
Délimiteur de ligne : \n / \r\n
Encoding : UTF-8 / UTF-16 / ASCII
Caractère d'échappement : " / '
```

### Débogage rapide

Avant d'exécuter le pipeline complet, utilisez les boutons :
- **Test connection** : Vérifie que la connexion à la source/destination est valide
- **Preview data** : Affiche un aperçu des données source (max 100 lignes)

## Utiliser des modèles de pipeline
*3 min* | 100 XP

### Pourquoi utiliser des modèles ?

Créer un pipeline from scratch peut être long. Microsoft Fabric propose une galerie de **modèles de pipeline prédéfinis** qui couvrent les scénarios d'ingestion les plus courants. Ces modèles sont :

- Préconfigurés avec les activités typiques du scénario
- Documentés avec des commentaires explicatifs
- Personnalisables selon vos besoins spécifiques

### Comment accéder aux modèles

Dans l'éditeur de pipeline, cliquez sur **Copy data** dans la barre d'outils, puis sélectionnez "Use copy assistant" — cela ouvre un assistant pas-à-pas pour configurer une activité Copy Data guidée.

Alternativement, lors de la création d'un nouveau pipeline, la page de démarrage propose des templates :
- Ingest data from Azure Blob to Lakehouse
- Ingest data from REST API to Delta Table
- Ingest data from SQL Server to Lakehouse

### Catégories de modèles disponibles

**Ingestion depuis des bases de données** :
- SQL Server vers Lakehouse
- PostgreSQL vers Lakehouse
- Oracle vers Lakehouse

**Ingestion depuis des fichiers** :
- Azure Blob Storage vers Lakehouse
- ADLS Gen2 vers Lakehouse
- SharePoint vers Lakehouse

**Transformations** :
- Lakehouse vers Warehouse (via notebook)
- Données brutes vers données curated

## Exécuter et superviser des pipelines
*5 min* | 100 XP

### Modes d'exécution

Un pipeline peut être exécuté de trois façons :

**1. Exécution manuelle (Debug / Run)**
- **Debug** : Exécute le pipeline en mode débogage. Vous pouvez voir l'état de chaque activité en temps réel. Utile pour tester et valider.
- **Run** : Exécution standard. Crée une nouvelle entrée dans l'historique des exécutions.

**2. Déclencheurs planifiés (Schedule Triggers)**
Permettent d'exécuter le pipeline à intervalles réguliers :

```
Fréquence : Minute / Heure / Jour / Semaine / Mois
Heure de début : 2026-05-27 08:00:00 UTC
Fuseau horaire : Europe/Paris
Récurrence : Toutes les 24 heures
```

**3. Déclencheurs d'événements (Event Triggers)**
- **Storage event trigger** : Déclenche le pipeline quand un fichier est créé ou supprimé dans Azure Blob Storage ou ADLS Gen2
- **Custom event trigger** : Déclenche via un événement Azure Event Grid

### Surveiller l'exécution

**Panneau Output** : Lors d'une exécution manuelle, le panneau "Output" sous le canevas affiche en temps réel :
- Le statut de chaque activité (In Progress / Succeeded / Failed / Skipped)
- La durée d'exécution de chaque activité
- L'icône de loupe pour voir les détails de sortie de chaque activité

**Monitoring Hub** : Dans la barre de navigation gauche de Fabric, le **Monitoring Hub** centralise toutes les exécutions de pipelines de votre espace de travail. Il affiche :
- L'historique de toutes les exécutions
- Le statut global (Succeeded / Failed / In Progress)
- La durée et l'heure de début/fin
- Les liens vers les détails d'exécution

### Interpréter les statuts

| Statut | Signification | Action recommandée |
|---|---|---|
| **Succeeded** | Toutes les activités ont réussi | Aucune |
| **Failed** | Au moins une activité a échoué et a bloqué le flux | Consulter les logs d'erreur |
| **In Progress** | Le pipeline est en cours d'exécution | Attendre ou annuler |
| **Cancelled** | Le pipeline a été annulé manuellement | — |
| **Queued** | Le pipeline attend des ressources disponibles | Attendre |

### Logs d'activité et débogage

En cliquant sur l'icône de loupe à côté d'une activité en échec, vous accédez aux **détails d'exécution** qui incluent :
- Le message d'erreur complet
- L'identifiant de la requête (pour le support Microsoft)
- Les métriques de performance (lignes lues/écrites, débit en Mo/s)

**Exemple de log d'une activité Copy Data réussie :**
```json
{
  "dataRead": 45231,
  "dataWritten": 45231,
  "filesRead": 1,
  "filesWritten": 1,
  "rowsRead": 1234,
  "rowsCopied": 1234,
  "throughput": "0.04 MB/s",
  "duration": "00:00:05"
}
```

## Exercice – Ingérer des données avec un pipeline
*60 min* | 100 XP

### Vue d'ensemble du lab

Dans cet exercice pratique, vous allez construire un pipeline ETL complet dans Microsoft Fabric qui :

1. Supprime les anciens fichiers CSV (nettoyage)
2. Copie un nouveau fichier CSV depuis GitHub vers le Lakehouse
3. Exécute un notebook Spark pour transformer et charger les données dans une table Delta

### Étape 1 : Créer le workspace et le Lakehouse

Connectez-vous à [Microsoft Fabric](https://app.fabric.microsoft.com/home?experience=fabric-developer) et créez un espace de travail avec capacité Fabric.

Créez un **Lakehouse** avec un nom unique. Dans l'Explorateur, créez un sous-dossier **new_data** sous **Files** via le menu `…` du nœud Files > New subfolder.

### Étape 2 : Créer le pipeline initial avec Copy Data

Dans l'espace de travail, créez un nouveau **Pipeline** nommé `Ingest Sales Data`.

Dans l'éditeur, sélectionnez **Copy data > Add copy data activity** dans la barre d'outils.

**Configurer la Source :**
- Connexion : Browse all > Créer une connexion HTTP
- URL : `https://raw.githubusercontent.com/MicrosoftLearning/dp-data/main/sales.csv`
- Format de fichier : DelimitedText
- Première ligne en en-tête : Oui
- Délimiteur : Virgule

**Configurer la Destination :**
- Connection : Browse all > Sélectionner votre Lakehouse dans OneLake Catalog
- Dossier racine : Files
- Chemin : `new_data/sales.csv`

Testez la connexion, puis exécutez le pipeline. Vérifiez que le fichier `sales.csv` apparaît dans `Files/new_data/`.

### Étape 3 : Créer le notebook de transformation

Depuis la page d'accueil du Lakehouse, créez un **Nouveau notebook**.

Dans la première cellule, ajoutez une **cellule de paramètres** :

```python
table_name = "dbo.sales"
```

> Pour marquer une cellule comme cellule de paramètres : cliquez sur le menu `…` en haut à droite de la cellule > **Toggle parameter cell**. Cela permet au pipeline de surcharger cette variable.

Ajoutez une deuxième cellule avec le code de transformation :

```python
from pyspark.sql.functions import *

# Lire les nouvelles données de vente depuis le dossier new_data
df = spark.read.format("csv").option("header","true").load("Files/new_data/*.csv")

# Ajouter les colonnes Year et Month depuis OrderDate
df = df.withColumn("Year", year(col("OrderDate"))).withColumn("Month", month(col("OrderDate")))

# Extraire FirstName et LastName depuis CustomerName
df = df.withColumn("FirstName", split(col("CustomerName"), " ").getItem(0)) \
       .withColumn("LastName", split(col("CustomerName"), " ").getItem(1))

# Filtrer et réordonner les colonnes
df = df["SalesOrderNumber", "SalesOrderLineNumber", "OrderDate", "Year", "Month",
        "FirstName", "LastName", "EmailAddress", "Item", "Quantity", "UnitPrice", "TaxAmount"]

# Charger dans la table Delta (append si elle existe déjà)
df.write.format("delta").mode("append").saveAsTable(table_name)
```

Renommez le notebook **Load Sales** via les paramètres du notebook (icône engrenage).

Exécutez le notebook manuellement pour vérifier qu'il crée bien la table `sales` dans le Lakehouse.

### Étape 4 : Modifier le pipeline pour ajouter Delete et Notebook

Retournez dans le pipeline **Ingest Sales Data**.

**Ajouter l'activité Delete Data :**
Dans l'onglet Activités > All activities, ajoutez **Delete data**. Positionnez-la à gauche de l'activité Copy Data. Connectez sa sortie **On Completion** vers Copy Data.

Configurez l'activité Delete :
- Nom : `Delete old files`
- Source : Votre Lakehouse (Browse all)
- File path type : Wildcard file path
- Folder path : Files / new_data
- Wildcard file name : `*.csv`
- Recursively : Oui
- Enable logging : Non

**Ajouter l'activité Notebook :**
Ajoutez une activité **Notebook** à droite du Copy Data. Connectez la sortie **On Completion** de Copy Data vers Notebook.

Configurez l'activité Notebook :
- Nom : `Load Sales notebook`
- Notebook : Sélectionnez "Load Sales"
- Base parameters : Ajoutez `table_name` (String) = `dbo.new_sales`

### Étape 5 : Exécuter le pipeline complet

Sauvegardez et exécutez le pipeline avec **Run**. Attendez que les 3 activités (Delete → Copy → Notebook) se terminent avec succès.

Dans le panneau Output, vérifiez que chaque activité affiche un statut "Succeeded" avec une icône verte.

Retournez dans le Lakehouse et vérifiez que la table **new_sales** a été créée avec les données transformées.

**Architecture finale du pipeline :**

```
[Delete old files] ──On Completion──▶ [Copy Data] ──On Completion──▶ [Load Sales notebook]
  (supprimer *.csv)                    (copier CSV)                    (transformer, charger table)
```

### Question 1

Quelle est la différence principale entre une activité Copy Data et un Dataflow Gen2 ?

A) Copy Data est plus rapide pour les grandes quantités de données brutes ; Dataflow est optimisé pour les transformations complexes  
B) Copy Data supporte uniquement les sources Azure ; Dataflow supporte toutes les sources  
C) Un Dataflow peut uniquement charger dans un Lakehouse ; Copy Data supporte toutes les destinations  
D) Il n'y a pas de différence fonctionnelle entre les deux  

**Réponse correcte : A** — Copy Data est conçu pour le déplacement efficace de données brutes sans transformation. Pour les transformations complexes (colonnes calculées, jointures, nettoyage), on utilise Dataflow Gen2 ou des notebooks.

---

### Question 2

Vous souhaitez que votre pipeline s'exécute chaque lundi matin à 6h00. Quelle fonctionnalité utilisez-vous ?

A) Un déclencheur d'événement (Event Trigger)  
B) Un déclencheur planifié (Schedule Trigger)  
C) Une activité Wait au début du pipeline  
D) Le mode Debug avec planification  

**Réponse correcte : B** — Un déclencheur planifié (Schedule Trigger) permet de définir une récurrence (quotidienne, hebdomadaire, etc.) avec une heure et un fuseau horaire précis.

---

### Question 3

Dans un pipeline, quelle connexion entre activités dois-je utiliser pour exécuter une activité de notification UNIQUEMENT si l'activité précédente a échoué ?

A) On Completion (bleu)  
B) On Success (vert)  
C) On Failure (rouge)  
D) On Skip (orange)  

**Réponse correcte : C** — La connexion "On Failure" (rouge) déclenche l'activité suivante uniquement en cas d'échec de l'activité précédente. C'est le bon choix pour des activités de notification d'erreur.

---

### Question 4

Vous passez un paramètre `table_name` à un notebook depuis un pipeline. Dans le notebook, comment cette cellule doit-elle être marquée pour recevoir ce paramètre ?

A) En ajoutant le commentaire `# PARAMETER` au début de la cellule  
B) En activant l'option "Toggle parameter cell" sur cette cellule  
C) En nommant la variable avec le préfixe `$`  
D) Les paramètres de pipeline sont automatiquement disponibles dans tous les notebooks  

**Réponse correcte : B** — La cellule contenant les variables à surcharger doit être marquée comme "cellule de paramètres" via le menu `…` > "Toggle parameter cell". Le pipeline peut alors passer des valeurs qui surchargent les valeurs par défaut.

## Résumé
*1 min*

Dans ce module, vous avez découvert les **pipelines Data Factory** dans Microsoft Fabric, un outil d'orchestration puissant pour automatiser vos processus d'ingestion et de transformation de données.

**Points clés :**

- Un pipeline orchestre des **activités** (Copy Data, Notebook, Dataflow, Delete, etc.) avec des **conditions de flux** (On Success, On Failure, On Completion).

- L'activité **Copy Data** est optimisée pour le déplacement rapide de données brutes entre sources et destinations, sans transformations complexes.

- Les **modèles de pipeline** offrent des points de départ préconfigurés pour les scénarios d'ingestion courants.

- Les pipelines peuvent être exécutés **manuellement**, via des **déclencheurs planifiés** ou via des **déclencheurs d'événements** (ex. nouveau fichier dans un stockage).

- Le **Monitoring Hub** et le panneau **Output** permettent de surveiller et déboguer les exécutions de pipelines.

- Un pattern ETL typique combine : **Delete Data** (nettoyage) → **Copy Data** (ingestion brute) → **Notebook** (transformation) → table Delta finale.
