## Présentation
*1 min* | 100 XP

### Pourquoi Apache Spark ?

Dans le monde de l'analytique des données, les approches traditionnelles de traitement séquentiel (une ligne après l'autre) atteignent rapidement leurs limites lorsque les volumes de données dépassent ce qu'un seul serveur peut traiter. Apache Spark résout ce problème en distribuant les calculs sur un **cluster de machines** qui travaillent en parallèle.

**Analogie** : Imaginez que vous devez compter les grains de sable d'une plage. Seul, cela prendrait des années. Avec Spark, c'est comme avoir des milliers de bénévoles qui comptent chacun une section de la plage simultanément, puis vous remettent leurs résultats.

Apache Spark est un **moteur d'analyse unifié** pour le traitement des données à grande échelle qui supporte :
- Le traitement par lots (batch processing)
- Le streaming de données en quasi-temps réel
- L'apprentissage automatique (via MLlib)
- Le traitement de graphes (via GraphX)
- Les requêtes SQL (via Spark SQL)

### Spark dans Microsoft Fabric

Microsoft Fabric intègre Apache Spark dans son **expérience Data Engineering et Data Science**. La différence majeure avec un Spark autonome ou sur Azure HDInsight : **Fabric gère toute l'infrastructure à votre place**. Vous n'avez pas besoin de :
- Créer et gérer un cluster Spark
- Configurer des connexions au stockage
- Gérer les versions et mises à jour

Fabric crée automatiquement un Spark **Starter Pool** dans chaque espace de travail avec capacité. Ce pool démarre un cluster Spark à la demande quand vous exécutez du code dans un notebook.

### Architecture Spark dans Microsoft Fabric

Quand vous exécutez du code Spark dans Fabric, voici ce qui se passe en coulisses :

```
Votre Notebook / Spark Job
        │
        ▼
┌───────────────────────────────────────────┐
│           Cluster Spark Fabric            │
│  ┌──────────────────┐                     │
│  │   Driver Node    │  ── Coordonne       │
│  │  (Spark Context) │     l'exécution     │
│  └────────┬─────────┘                     │
│           │                               │
│    ┌──────┼──────┐                        │
│    ▼      ▼      ▼                        │
│  [W1]   [W2]   [W3]  ← Worker Nodes      │
│  [E1]   [E2]   [E3]  ← Executors JVM     │
└───────────────────────────────────────────┘
        │
        ▼
   OneLake (Fabric Storage)
```

**Composants clés :**

- **Driver Node** : Coordonne l'exécution du programme Spark. Maintient le SparkContext, distribue les tâches aux workers, collecte les résultats.
- **Worker Nodes** : Nœuds de calcul qui exécutent les tâches assignées par le driver.
- **Executors** : Processus JVM sur chaque worker. Chaque executor reçoit une partition de données et exécute les transformations dessus.
- **SparkContext / SparkSession** : L'objet `spark` disponible par défaut dans les notebooks Fabric. Point d'entrée pour toutes les opérations Spark.

### Types d'environnements Spark dans Fabric

**Starter Pool** : Pool par défaut dans chaque workspace. Démarre rapidement, configuration standard. Idéal pour le développement et les petits volumes.

**Spark Pools personnalisés** : Vous pouvez créer des pools avec des configurations spécifiques :
- Taille de nœud (Small, Medium, Large, X-Large)
- Nombre minimum et maximum de nœuds (auto-scaling)
- Runtime Spark (version 3.3, 3.4, etc.)
- Bibliothèques Python personnalisées

**Environnements (Environments)** : Permettent de définir les bibliothèques Python/R et les configurations Spark spécifiques à un projet. Un Environment est attaché à un notebook ou un Spark Job.

### Notebooks vs Spark Jobs

| Critère | Notebook | Spark Job Definition |
|---|---|---|
| Interface | Interactive, cellule par cellule | Script Python/Scala soumis en batch |
| Cas d'usage | Exploration, développement, debug | Production, automatisation, pipelines |
| Résultats | Affichés en temps réel dans le notebook | Logs dans Monitoring Hub |
| Déclenchement | Manuel ou depuis un pipeline | Pipeline, Schedule, API |
| État de la session | Persiste entre les cellules | Nouvelle session à chaque exécution |

### Créer un notebook dans un Lakehouse

Dans Microsoft Fabric, les notebooks sont créés dans le contexte d'un Lakehouse pour bénéficier de l'accès direct aux fichiers et tables.

Depuis la page d'accueil d'un Lakehouse : **Ouvrir un notebook > Nouveau notebook**

### Anatomie d'un notebook Fabric

Un notebook Fabric est composé de **cellules** de deux types :

**Cellules de code** : Contiennent du code Python (PySpark), Scala, R ou SQL.
```python
# Exemple de cellule code PySpark
df = spark.read.format("csv").option("header","true").load("Files/orders/2019.csv")
display(df.limit(10))
```

**Cellules Markdown** : Contiennent du texte formaté (titres, listes, explications).
```markdown
## Analyse des données de vente
Ce notebook explore les données de commandes 2019-2021.
```

### Langages disponibles dans un notebook Fabric

Le langage par défaut est **PySpark** (Python pour Spark), mais vous pouvez utiliser :
- `%%sql` : magic pour écrire des requêtes Spark SQL
- `%%scala` : magic pour écrire du code Scala Spark
- `%%r` : magic pour écrire du code R (si activé)
- `%%sh` : magic pour des commandes shell bash

### La session Spark et le SparkSession

Lors de la première exécution d'une cellule de code Spark, Fabric démarre une **session Spark**. Cela peut prendre 30 secondes à 2 minutes selon la disponibilité des ressources. Les exécutions suivantes dans la même session sont instantanées.

L'objet `spark` (de type `SparkSession`) est **disponible automatiquement** dans tous les notebooks Fabric, sans import :

```python
# L'objet spark est disponible sans import
print(spark.version)  # Affiche la version de Spark
print(spark.conf.get("spark.app.name"))  # Nom de l'application
```

## Utiliser des données dans un DataFrame Spark
*5 min* | 100 XP

### Qu'est-ce qu'un DataFrame Spark ?

Un **DataFrame Spark** est une collection distribuée de données organisées en colonnes nommées, similaire à une table SQL ou un DataFrame Pandas. La différence clé : un DataFrame Spark est **distribué sur le cluster** et traité en parallèle.

**Caractéristiques importantes :**
- **Immutable** : Vous ne modifiez pas un DataFrame existant, vous créez un nouveau DataFrame à partir du précédent.
- **Lazy evaluation** : Les transformations ne sont pas exécutées immédiatement. Elles sont accumulées et optimisées, puis exécutées seulement quand une **action** est appelée (ex. `display()`, `count()`, `write()`).
- **Distributed** : Les données sont partitionnées et traitées en parallèle sur les workers.

### Lire des données dans un DataFrame

**Depuis un fichier CSV :**

```python
# Lecture simple avec en-tête automatique
df = spark.read.format("csv").option("header","true").load("Files/orders/2019.csv")
display(df.limit(100))
```

```python
# Lecture avec schéma explicite (recommandé pour la production)
from pyspark.sql.types import *

orderSchema = StructType([
    StructField("SalesOrderNumber", StringType()),
    StructField("SalesOrderLineNumber", IntegerType()),
    StructField("OrderDate", DateType()),
    StructField("CustomerName", StringType()),
    StructField("Email", StringType()),
    StructField("Item", StringType()),
    StructField("Quantity", IntegerType()),
    StructField("UnitPrice", FloatType()),
    StructField("Tax", FloatType())
])

df = spark.read.format("csv").schema(orderSchema).load("Files/orders/*.csv")
display(df)
```

> **Bonne pratique** : Toujours définir un schéma explicite en production plutôt que de laisser Spark inférer le schéma (`inferSchema`). L'inférence de schéma est lente car elle requiert un scan des données, et peut inférer incorrectement les types.

**Depuis des fichiers Parquet :**

```python
df_parquet = spark.read.format("parquet").load("Files/transformed_data/orders")
display(df_parquet)
```

**Depuis une table Delta (Lakehouse) :**

```python
df_table = spark.sql("SELECT * FROM salesorders LIMIT 1000")
display(df_table)
```

### Transformations de DataFrame

Les transformations créent un nouveau DataFrame à partir d'un existant. Elles sont **lazy** (exécutées seulement au moment d'une action).

**Sélectionner des colonnes :**

```python
# select() - choisir des colonnes spécifiques
customers = df.select("CustomerName", "Email")

# Alternative avec accès par index de colonnes
customers = df["CustomerName", "Email"]
```

**Filtrer des lignes :**

```python
# where() - équivalent de filter()
high_value_orders = df.where(df["UnitPrice"] > 100)

# Avec une condition sur le texte
bike_orders = df.select("CustomerName", "Email").where(df["Item"] == "Road-250 Red, 52")
```

**Ajouter des colonnes calculées :**

```python
from pyspark.sql.functions import *

# Ajouter des colonnes Year et Month depuis OrderDate
transformed_df = df.withColumn("Year", year(col("OrderDate"))) \
                   .withColumn("Month", month(col("OrderDate")))

# Diviser CustomerName en FirstName et LastName
transformed_df = transformed_df \
    .withColumn("FirstName", split(col("CustomerName"), " ").getItem(0)) \
    .withColumn("LastName", split(col("CustomerName"), " ").getItem(1))
```

**Grouper et agréger :**

```python
# Somme des quantités par produit
productSales = df.select("Item", "Quantity").groupBy("Item").sum()
display(productSales)

# Nombre de commandes par année
yearlySales = df.select(year(col("OrderDate")).alias("Year")) \
                .groupBy("Year") \
                .count() \
                .orderBy("Year")
display(yearlySales)
```

**Transformation complète — exemple production :**

```python
from pyspark.sql.functions import *

# Transformation complète d'un DataFrame de commandes
transformed_df = df \
    .withColumn("Year", year(col("OrderDate"))) \
    .withColumn("Month", month(col("OrderDate"))) \
    .withColumn("FirstName", split(col("CustomerName"), " ").getItem(0)) \
    .withColumn("LastName", split(col("CustomerName"), " ").getItem(1)) \
    ["SalesOrderNumber", "SalesOrderLineNumber", "OrderDate", "Year", "Month",
     "FirstName", "LastName", "Email", "Item", "Quantity", "UnitPrice", "Tax"]

display(transformed_df.limit(5))
```

### Actions de DataFrame

Contrairement aux transformations, les **actions** déclenchent réellement l'exécution du calcul :

```python
# count() - compte le nombre de lignes
print(df.count())               # Déclenche l'exécution

# distinct() - déduplique
print(df.distinct().count())

# show() - affiche les premières lignes dans les logs
df.show(5, truncate=False)

# display() - affiche interactivement dans le notebook (spécifique Fabric)
display(df)

# toPandas() - convertit en Pandas DataFrame (charge tout en mémoire driver!)
pdf = df.toPandas()             # Attention aux grands DataFrames!
```

### Enregistrer des données transformées

**En format Parquet :**

```python
# Sauvegarder en Parquet (format columaire performant)
transformed_df.write.mode("overwrite").parquet("Files/transformed_data/orders")
print("Données transformées sauvegardées!")
```

**En format Parquet partitionné :**

```python
# Partitionner par Year et Month pour des requêtes plus performantes
orders_df.write.partitionBy("Year","Month").mode("overwrite").parquet("Files/partitioned_data")
print("Données partitionnées sauvegardées!")
```

Le partitionnement crée une structure de dossiers hiérarchique :
```
Files/partitioned_data/
├── Year=2019/
│   ├── Month=1/  ── part-00000.parquet
│   ├── Month=2/  ── part-00000.parquet
│   └── ...
├── Year=2020/
│   └── ...
└── Year=2021/
    └── ...
```

Lire uniquement les données d'une partition spécifique :
```python
# Lire seulement les données 2021 (ne lit que Year=2021/)
orders_2021 = spark.read.format("parquet").load("Files/partitioned_data/Year=2021/Month=*")
display(orders_2021)
```

## Utiliser des données à l'aide de Spark SQL
*7 min* | 100 XP

### Tables et vues Delta dans un Lakehouse

Les **tables Delta** d'un Lakehouse Fabric sont des abstractions relationnelles sur des fichiers Delta Lake dans OneLake. Elles combinent la flexibilité d'un Data Lake avec les capacités relationnelles d'un Data Warehouse.

**Créer une table Delta depuis un DataFrame :**

```python
# Sauvegarder le DataFrame comme table Delta managée
df.write.format("delta").saveAsTable("salesorders")

# Vérifier la définition de la table
spark.sql("DESCRIBE EXTENDED salesorders").show(truncate=False)
```

Les tables créées avec `saveAsTable` sont **managed tables** : leurs fichiers sont stockés dans le dossier `Tables/` du Lakehouse et visibles dans l'explorateur Lakehouse.

**Modes d'écriture :**

```python
# Créer/remplacer la table complètement
df.write.format("delta").mode("overwrite").saveAsTable("salesorders")

# Ajouter des données à une table existante
df.write.format("delta").mode("append").saveAsTable("salesorders")

# Insérer/mettre à jour (upsert) - nécessite une clé de merge
from delta.tables import DeltaTable
deltaTable = DeltaTable.forName(spark, "salesorders")
deltaTable.alias("target").merge(
    df.alias("source"),
    "target.SalesOrderNumber = source.SalesOrderNumber"
).whenMatchedUpdateAll().whenNotMatchedInsertAll().execute()
```

### Interroger des données avec PySpark + SQL

Depuis un notebook, vous pouvez embarquer des requêtes SQL dans du code PySpark :

```python
# spark.sql() retourne un DataFrame PySpark
df_result = spark.sql("SELECT * FROM salesorders WHERE UnitPrice > 100 LIMIT 1000")
display(df_result)
```

### Utiliser directement SQL avec la magic %%sql

La magic `%%sql` au début d'une cellule permet d'écrire directement du Spark SQL :

```sql
%%sql
SELECT YEAR(OrderDate) AS OrderYear,
       SUM((UnitPrice * Quantity) + Tax) AS GrossRevenue
FROM salesorders
GROUP BY YEAR(OrderDate)
ORDER BY OrderYear;
```

Résultat affiché automatiquement en tableau dans le notebook.

**Exemples de requêtes Spark SQL :**

```sql
%%sql
-- Top 10 produits par chiffre d'affaires
SELECT Item,
       COUNT(*) AS NbCommandes,
       SUM(Quantity) AS TotalQuantite,
       SUM(UnitPrice * Quantity) AS ChiffreAffaires
FROM salesorders
GROUP BY Item
ORDER BY ChiffreAffaires DESC
LIMIT 10;
```

```sql
%%sql
-- Évolution mensuelle du CA
SELECT YEAR(OrderDate) AS Annee,
       MONTH(OrderDate) AS Mois,
       SUM((UnitPrice * Quantity) + Tax) AS RevenuBrut
FROM salesorders
GROUP BY YEAR(OrderDate), MONTH(OrderDate)
ORDER BY Annee, Mois;
```

### Créer des vues temporaires

Les **vues temporaires** sont des alias de requêtes SQL accessibles dans la session courante (non persistées) :

```python
# Créer une vue temporaire depuis un DataFrame
transformed_df.createOrReplaceTempView("orders_clean")

# Utiliser la vue dans une requête SQL
df_result = spark.sql("SELECT Year, Month, COUNT(*) as Orders FROM orders_clean GROUP BY Year, Month")
display(df_result)
```

## Visualiser des données dans un notebook Spark
*5 min* | 100 XP

### Vue graphique intégrée de Fabric

Dans un notebook Fabric, les résultats d'une cellule (affichés via `display()` ou `%%sql`) peuvent être basculés en vue graphique via le bouton **+ New chart** dans la barre de résultats.

Options de personnalisation :
- Type de graphique : Barres, Lignes, Aire, Secteurs (Pie), Dispersion
- Axe X : Choisir la colonne
- Axe Y : Choisir la colonne avec agrégation (Sum, Count, Average, etc.)
- Séries : Grouper par une colonne
- Empilé : Oui/Non

Limitation : La vue graphique intégrée est pratique pour une exploration rapide, mais offre peu de personnalisation pour des graphiques de qualité production.

### Visualiser avec matplotlib

**matplotlib** est la bibliothèque de visualisation Python de référence. Elle est disponible par défaut dans les notebooks Fabric.

**Graphique en barres basique :**

```python
from matplotlib import pyplot as plt

# Préparer les données — convertir le DataFrame Spark en Pandas
sqlQuery = """
    SELECT CAST(YEAR(OrderDate) AS STRING) AS OrderYear,
           SUM((UnitPrice * Quantity) + Tax) AS GrossRevenue
    FROM salesorders
    GROUP BY YEAR(OrderDate)
    ORDER BY OrderYear
"""
df_spark = spark.sql(sqlQuery)
df_sales = df_spark.toPandas()  # matplotlib nécessite un DataFrame Pandas

# Créer le graphique
plt.bar(x=df_sales['OrderYear'], height=df_sales['GrossRevenue'], color='steelblue')
plt.title('Chiffre d\'affaires par année')
plt.xlabel('Année')
plt.ylabel('Revenu (€)')
plt.grid(color='#95a5a6', linestyle='--', linewidth=1, axis='y', alpha=0.7)
plt.show()
```

**Graphique avec sous-graphiques (subplots) :**

```python
from matplotlib import pyplot as plt

# Préparer les données
sqlQuery = """
    SELECT CAST(YEAR(OrderDate) AS STRING) AS OrderYear,
           SUM((UnitPrice * Quantity) + Tax) AS GrossRevenue,
           COUNT(DISTINCT SalesOrderNumber) AS YearlyCounts
    FROM salesorders
    GROUP BY YEAR(OrderDate)
    ORDER BY OrderYear
"""
df_sales = spark.sql(sqlQuery).toPandas()

# Créer une figure avec 2 sous-graphiques côte à côte
plt.clf()
fig, ax = plt.subplots(1, 2, figsize=(12, 4))

# Graphique 1 : Barres (revenu par année)
ax[0].bar(x=df_sales['OrderYear'], height=df_sales['GrossRevenue'], color='orange')
ax[0].set_title('Revenu par Année')
ax[0].set_xlabel('Année')
ax[0].set_ylabel('Revenu (€)')

# Graphique 2 : Camembert (répartition des commandes)
ax[1].pie(df_sales['YearlyCounts'], labels=df_sales['OrderYear'], autopct='%1.1f%%')
ax[1].set_title('Répartition des commandes par année')

fig.suptitle('Analyse des ventes 2019-2021', fontsize=14, fontweight='bold')
plt.tight_layout()
plt.show()
```

### Visualiser avec seaborn

**seaborn** est construite sur matplotlib et offre une API plus simple avec des thèmes visuels plus attractifs :

```python
import seaborn as sns
from matplotlib import pyplot as plt
import warnings

# Supprimer les warnings FutureWarning de seaborn
warnings.filterwarnings('ignore', category=FutureWarning)

# Préparer les données
df_sales = spark.sql("""
    SELECT CAST(YEAR(OrderDate) AS STRING) AS OrderYear,
           SUM((UnitPrice * Quantity) + Tax) AS GrossRevenue
    FROM salesorders
    GROUP BY YEAR(OrderDate)
    ORDER BY OrderYear
""").toPandas()

plt.clf()

# Appliquer un thème seaborn
sns.set_theme(style="whitegrid", palette="Set2")

# Graphique en barres avec seaborn
ax = sns.barplot(x="OrderYear", y="GrossRevenue", data=df_sales)
ax.set_title("Revenu brut par année")
ax.set_xlabel("Année")
ax.set_ylabel("Revenu (€)")

plt.show()
```

```python
# Graphique en ligne avec seaborn
import seaborn as sns
from matplotlib import pyplot as plt

plt.clf()
ax = sns.lineplot(x="OrderYear", y="GrossRevenue", data=df_sales, marker="o", linewidth=2.5)
ax.set_title("Évolution du revenu brut")
plt.show()
```

-- Analyser le revenu annuel

### Question 1

Quelle est la différence principale entre une **transformation** et une **action** dans Spark ?

A) Les transformations modifient les données en place ; les actions créent de nouveaux DataFrames  
B) Les transformations sont lazy (différées) et créent un plan d'exécution ; les actions déclenchent l'exécution réelle  
C) Les transformations sont plus rapides que les actions  
D) Les actions sont appliquées sur les workers ; les transformations sont appliquées sur le driver  

**Réponse correcte : B** — Les transformations (select, filter, withColumn, groupBy) sont lazy : elles accumulent un plan d'exécution logique sans traiter les données. Les actions (count, display, write, toPandas) déclenchent l'exécution réelle de ce plan.

### Question 2

Vous voulez lire uniquement les données de l'année 2021 depuis des fichiers Parquet partitionnés stockés dans `Files/partitioned_data/Year=2021/`. Quelle est la commande correcte ?

A) `spark.read.format("parquet").filter("Year=2021").load("Files/partitioned_data")`  
B) `spark.read.format("parquet").load("Files/partitioned_data/Year=2021/Month=*")`  
C) `spark.read.format("parquet").where("Year == 2021").load("Files/partitioned_data")`  
D) `spark.sql("SELECT * FROM partitioned_data WHERE Year = 2021")`  

**Réponse correcte : B** — Spark utilise le **partition pruning** : en spécifiant le chemin `Year=2021/Month=*`, Spark ne lit que les fichiers dans ce dossier, ignorant toutes les autres années. C'est beaucoup plus performant que de charger toutes les données et filtrer ensuite.

### Question 4

Pourquoi est-il recommandé de définir un schéma explicite (`StructType`) lors de la lecture de fichiers CSV en Spark plutôt que de laisser Spark inférer le schéma ?

A) L'inférence de schéma ne fonctionne qu'avec des fichiers Parquet, pas CSV  
B) L'inférence de schéma nécessite un scan complet des données (lent) et peut déduire des types incorrects  
C) Spark SQL ne peut pas utiliser des DataFrames sans schéma explicite  
D) La définition explicite du schéma permet d'utiliser des colonnes partitionnées  

**Réponse correcte : B** — L'inférence de schéma (`inferSchema=true`) scanne toutes les données pour deviner les types, ce qui double le temps de lecture. De plus, elle peut déduire `StringType` pour une colonne numérique contenant des valeurs nulles, ou `DoubleType` au lieu de `FloatType`. En production, un schéma explicite est toujours préféré.

## Résumé
*1 min*

Dans ce module, vous avez exploré **Apache Spark dans Microsoft Fabric** pour analyser et transformer des données à grande échelle.

**Points clés :**

- Fabric gère l'infrastructure Spark automatiquement via les **Starter Pools** et les **Spark Pools personnalisés**. Vous n'avez pas besoin de configurer des clusters.

- L'objet `spark` (SparkSession) est disponible automatiquement dans tous les notebooks Fabric, sans import.

- Les **DataFrames Spark** sont immutables et utilisent l'**évaluation lazy** : les transformations sont différées jusqu'à une action (`count()`, `display()`, `write()`).

- **PySpark** offre une API riche pour les transformations : `select()`, `filter()`, `withColumn()`, `groupBy()`, `orderBy()`, et des fonctions SQL comme `year()`, `month()`, `split()`.

- **Spark SQL** (magic `%%sql`) permet d'écrire des requêtes SQL familières sur des tables Delta du Lakehouse.

- Le **partitionnement** des fichiers Parquet (`partitionBy("Year","Month")`) améliore significativement les performances des requêtes filtrées par partition.

- Pour la visualisation, **matplotlib** et **seaborn** nécessitent un DataFrame Pandas (`toPandas()`). Pour de grands volumes, préférez des outils qui opèrent directement sur Spark.
