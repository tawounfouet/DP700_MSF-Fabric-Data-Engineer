# Ingérer des données avec des flux de données Gen2 dans Microsoft Fabric

*1 heure* | Module *(7 Unités)* | Débutant | Analyste de données | Ingénieur Data | Microsoft Fabric

L'ingestion de données est cruciale dans toute architecture analytique moderne. Data Factory de Microsoft Fabric offre les flux de données Gen2 (Dataflows Gen2) pour créer visuellement une ingestion et une transformation des données en plusieurs étapes, grâce à l'expérience Power Query Online — sans écrire une seule ligne de code.

## Présentation
*2 min* | 100 XP

### Qu'est-ce qu'un Dataflow Gen2 ?

Un flux de données (dataflow) est un outil cloud conçu pour préparer et transformer des données sans écrire de code. Il fournit une interface à faible code (low-code) pour l'ingestion de données à partir de centaines de sources, la transformation de vos données via 300+ opérations disponibles, et le chargement des données résultantes vers plusieurs destinations.

Imaginez un flux de données comme un **assistant de préparation des données personnel** : il peut se connecter à des centaines de sources différentes (bases de données, fichiers CSV, APIs REST, SharePoint, etc.), nettoyer et restructurer les données désordonnées, puis les livrer exactement là où vous en avez besoin — que ce soit un Lakehouse, un Data Warehouse ou une base de données Azure SQL.

**Dataflow Gen2** est la version plus récente et plus puissante des dataflows dans Microsoft Fabric. Elle fonctionne en parallèle avec les dataflows Power BI d'origine (maintenant appelés Gen1) mais apporte des améliorations majeures :

- Enregistrement automatique du travail en cours
- Destinations de sortie multiples (pas seulement le stockage interne)
- Meilleure surveillance et suivi des actualisations
- Intégration native avec les pipelines Data Factory
- Moteurs de calcul haute performance basés sur Fabric
- Intégration avec Copilot pour les transformations en langage naturel

> **Important** : À compter d'avril 2026, tous les nouveaux éléments Dataflow Gen2 sont créés avec la prise en charge de l'intégration CI/CD et Git par défaut. L'ancienne version "Dataflow Gen2 Classic" (sans support CI/CD) n'est plus disponible pour les nouvelles créations.

### Positionnement dans Microsoft Fabric

Dans l'écosystème Fabric, les flux de données Gen2 s'inscrivent dans l'expérience **Data Factory**, qui est la composante d'intégration de données de la plateforme. Ils se distinguent d'autres approches d'ingestion de données :

| Outil | Cas d'usage | Niveau technique |
|---|---|---|
| **Dataflow Gen2** | Transformations visuelles, préparation de données, ETL sans code | Faible (Power Query) |
| **Pipeline Data Factory** | Orchestration de flux, automatisation, combinaison d'activités | Moyen |
| **Notebook Spark** | Transformations complexes, traitement à grande échelle, logique personnalisée | Élevé (Python/Scala) |
| **Raccourcis (Shortcuts)** | Accès direct à des données externes sans copie | Très faible |

## Comprendre les flux de données Gen2
*7 min* | 100 XP

### Architecture et composants

Un flux de données Gen2 repose sur **Power Query Online**, la même technologie qui équipe Power BI Desktop, Excel, Power Apps et Dynamics 365. Cette cohérence de l'expérience facilite la montée en compétences pour les utilisateurs déjà familiers avec ces outils.

**Architecture interne d'un Dataflow Gen2 :**

```
Source de données                   Power Query Online                 Destination
┌──────────────┐                   ┌──────────────────────────────┐   ┌─────────────────┐
│ CSV / Excel  │                   │                              │   │ Lakehouse Table │
│ Azure SQL    │  ──── Connexion ──▶│  Éditeur de requêtes        │──▶│ Warehouse       │
│ REST API     │                   │  ├─ Étapes appliquées        │   │ Azure SQL DB    │
│ SharePoint   │                   │  ├─ Transformations visuelles│   │ Azure ADLS Gen2 │
│ 300+ sources │                   │  └─ Prévisualisation des data│   │ Snowflake       │
└──────────────┘                   └──────────────────────────────┘   └─────────────────┘
```

**Composants clés :**

1. **Connecteurs de données** : Plus de 300 connecteurs permettent d'accéder à des sources variées — bases de données relationnelles, fichiers plats, APIs, services cloud, plateformes SaaS.

2. **Éditeur Power Query** : Interface graphique qui affiche les données en tableau et permet d'appliquer des transformations de manière visuelle. Chaque transformation est enregistrée comme une "étape appliquée" et est réversible.

3. **Moteur M (Power Query Formula Language)** : Langage fonctionnel sous-jacent à chaque transformation. L'interface graphique génère automatiquement du code M, mais les utilisateurs avancés peuvent l'éditer directement.

4. **Staging Lakehouse/Warehouse** : Pour les performances, Dataflow Gen2 utilise des éléments intermédiaires (`DataflowsStagingLakehouse`, `DataflowsStagingWarehouse`) créés automatiquement dans votre espace de travail. Ces éléments sont internes et ne doivent pas être modifiés manuellement.

5. **Destinations de données** : Configuration indiquant où les données transformées doivent être chargées. Plusieurs destinations peuvent être définies pour une même requête.

### Comparaison Gen1 vs Gen2

| Fonctionnalité | Dataflow Gen2 | Dataflow Gen1 |
|---|---|---|
| Interface Power Query | ✓ | ✓ |
| Processus de création simplifié | ✓ | — |
| Enregistrement automatique | ✓ | — |
| Destinations multiples | ✓ | — |
| Surveillance améliorée | ✓ | — |
| Intégration avec pipelines | ✓ | — |
| Calcul haute performance (Fabric) | ✓ | — |
| Connecteur Dataflow dans Power BI | ✓ | ✓ |
| Requête directe via connecteur | — | ✓ |
| Actualisation incrémentielle | ✓ | ✓ |
| Copilot AI | ✓ | — |

### Sources de données supportées

Les flux de données Gen2 se connectent à une très large variété de sources :

**Fichiers** : CSV, Excel, JSON, XML, Parquet, PDF, texte délimité

**Bases de données** : Azure SQL Database, SQL Server, PostgreSQL, MySQL, Oracle, SAP HANA, Teradata

**Services cloud** : Azure Data Lake Storage Gen2, Azure Blob Storage, Amazon S3, Google BigQuery, Snowflake

**Services Microsoft** : SharePoint, OneDrive, Dynamics 365, Power BI Datasets, Dataverse, Fabric Lakehouse, Fabric Warehouse

**APIs et web** : REST API, OData, Web scraping, XML de flux

## Explorer un flux de données Gen2 dans Microsoft Fabric
*7 min* | 100 XP

### L'éditeur Power Query Online

Une fois un flux de données Gen2 créé dans votre espace de travail ou depuis un Lakehouse, l'**éditeur Power Query Online** s'ouvre. C'est le cœur de l'expérience de création.

**Zones de l'interface :**

```
┌─────────────────────────────────────────────────────────────────┐
│  Ruban (Home, Transform, Add column, View...)                   │
├────────────────────┬──────────────────────────────┬─────────────┤
│                    │                              │  Paramètres │
│  Requêtes          │   Prévisualisation des       │  de la      │
│  (panneau gauche)  │   données (zone centrale)    │  requête    │
│                    │                              │  (droite)   │
│  ─ Ma_Requête      │   Col1 | Col2 | Col3 | ...   │             │
│    Requête2        │   val1 | val2 | val3 | ...   │  Étapes     │
│                    │   val4 | val5 | val6 | ...   │  appliquées │
│                    │                              │  ─ Source   │
│                    │                              │  ─ Type modifié│
│                    │                              │  ─ Col ajoutée│
├────────────────────┴──────────────────────────────┴─────────────┤
│  Barre de formule M (optionnelle)                               │
└─────────────────────────────────────────────────────────────────┘
```

### Onglets du ruban

**Onglet Accueil (Home)** :
- Obtenir des données / Nouvelle source
- Actualiser l'aperçu
- Choisir des colonnes / Supprimer des colonnes
- Conserver / Supprimer des lignes
- Regrouper par
- Fusionner des requêtes / Ajouter des requêtes
- Ajouter une destination de données
- Enregistrer et exécuter (Save & run)

**Onglet Transformer** :
- Modifier le type de données
- Remplacer les valeurs / Supprimer les doublons
- Fractionner / Combiner des colonnes
- Pivoter / Dépivoter
- Transposer

**Onglet Ajouter une colonne** :
- Colonne personnalisée (formule M)
- Colonne conditionnelle (if/then/else visuel)
- Colonne d'index
- Dupliquer une colonne
- Colonne à partir d'exemples (suggestion automatique basée sur l'IA)

### Les étapes appliquées (Applied Steps)

C'est l'une des fonctionnalités les plus puissantes de Power Query. Chaque action dans l'éditeur est enregistrée comme une étape nommée dans le panneau "Étapes appliquées" à droite. Ces étapes :

- Sont exécutées séquentiellement de haut en bas
- Peuvent être réordonnées par glisser-déposer
- Peuvent être supprimées individuellement
- Peuvent être éditées en cliquant sur l'icône d'engrenage
- Génèrent automatiquement le code M correspondant

**Exemple de séquence d'étapes pour un fichier CSV :**

```
Source                    → Connexion à la source de données
Navigation                → Sélection du fichier/table spécifique
Promoted Headers          → Utilisation de la 1ère ligne comme en-tête
Changed Type              → Détection et modification des types de données
Removed Columns           → Suppression des colonnes inutiles
Filtered Rows             → Filtrage des lignes nulles ou invalides
Added Custom Column       → Ajout d'une colonne calculée
```

### Créer une colonne personnalisée

L'onglet "Ajouter une colonne" > "Colonne personnalisée" ouvre un dialogue permettant d'écrire une formule M :

**Exemples de formules M courantes :**

```m
// Extraire le mois d'une date
Date.Month([OrderDate])

// Concaténer deux colonnes avec un espace
[FirstName] & " " & [LastName]

// Créer une colonne conditionnelle
if [Amount] > 1000 then "High" else if [Amount] > 500 then "Medium" else "Low"

// Extraire l'année d'une date
Date.Year([OrderDate])

// Calculer le nombre de jours entre deux dates
Duration.Days([EndDate] - [StartDate])

// Transformer du texte en majuscules
Text.Upper([ProductName])
```

### Vue Diagramme de flux

Le bouton "Diagram flow" (dans l'onglet View) affiche une représentation visuelle du flux de données sous forme de diagramme orienté, montrant les connexions entre les sources, les transformations et les destinations. C'est particulièrement utile pour :

- Comprendre des flux de données complexes à plusieurs requêtes
- Identifier les dépendances entre les requêtes
- Documenter l'architecture du flux de données

## Intégrer des flux de données Gen2 et des pipelines
*2 min* | 100 XP

### Pourquoi intégrer dataflows et pipelines ?

Un flux de données Gen2 seul peut extraire, transformer et charger des données. Mais dans un contexte d'entreprise, vous avez souvent besoin :

- D'**orchestrer** plusieurs flux de données dans un ordre précis
- De **conditionner** l'exécution d'un dataflow en fonction du succès d'une étape précédente
- De **combiner** des activités (copie de fichiers, exécution de notebooks, envoi d'emails) avec l'exécution d'un dataflow
- De **planifier** automatiquement l'ensemble du processus via des déclencheurs

C'est là qu'intervient l'intégration avec les **pipelines Data Factory**.

### Comment ajouter un dataflow à un pipeline

1. Dans votre espace de travail, créez ou ouvrez un pipeline Data Factory
2. Dans l'onglet **Activités**, faites glisser une activité **Dataflow** sur le canevas
3. Dans les **Paramètres** de l'activité, sélectionnez le flux de données Gen2 à exécuter
4. Connectez cette activité aux autres activités du pipeline via les connecteurs de flux (On success, On failure, On completion)

**Architecture typique d'un pipeline avec dataflow :**

```
[Déclencheur planifié]
        │
        ▼
[Copier des données]  ──On Success──▶  [Flux de données Gen2]  ──On Success──▶  [Notebook]
(ingestion brute)                       (transformations)                         (enrichissement)
        │                                       │
        └──On Failure──▶  [Activité Web]        └──On Failure──▶  [Email d'alerte]
                          (notifier équipe)
```

### Destinations de données supportées par Dataflow Gen2

Dataflow Gen2 prend en charge les destinations suivantes pour le chargement des données transformées :

| Destination | Description | Cas d'usage |
|---|---|---|
| **Fabric Lakehouse (Tables)** | Tables Delta dans un Lakehouse Fabric | Analytique Fabric, Spark, SQL |
| **Fabric Lakehouse (Fichiers)** | Fichiers dans la zone Files d'un Lakehouse | Ingestion brute, format flexible |
| **Fabric Warehouse** | Tables dans un Data Warehouse Fabric | SQL analytique, reporting |
| **Azure SQL Database** | Base de données transactionnelle Azure | Applications opérationnelles |
| **Azure Data Lake Gen2** | Stockage objet Azure | Data Lake enterprise |
| **Azure Data Explorer** | Base de données analytique temps réel | Analyse de séries temporelles |
| **Fabric KQL Database** | Base de données KQL dans un Eventhouse | Real-Time Intelligence |
| **Fabric SQL Database** | Base de données SQL dans Fabric | SQL transactionnel Fabric |
| **Snowflake** | Data Warehouse cloud | Multi-cloud |
| **SharePoint** | Listes SharePoint | Collaboration, partage métier |

### Modes d'écriture des données

Lors de la configuration d'une destination, vous choisissez le comportement d'écriture :

- **Ajouter (Append)** : Les nouvelles données sont ajoutées à la table existante. Les données précédentes sont conservées. Idéal pour les chargements incrémentaux.
- **Remplacer (Replace)** : La table est vidée puis rechargée avec les nouvelles données. Idéal pour les chargements complets.
- **Fusionner (Merge/Upsert)** : Les données existantes sont mises à jour et les nouvelles données sont insérées. Nécessite une clé primaire.

## Exercice – Créer et utiliser un flux de données Gen2
*30 min* | 100 XP

### Vue d'ensemble du lab

Dans cet exercice, vous allez :
1. Créer un espace de travail et un Lakehouse dans Microsoft Fabric
2. Créer un flux de données Gen2 qui lit un fichier CSV depuis GitHub
3. Appliquer des transformations avec Power Query Online
4. Configurer une destination Lakehouse pour charger les données
5. Intégrer le dataflow dans un pipeline

### Étape 1 : Créer l'espace de travail et le Lakehouse

Connectez-vous à [Microsoft Fabric](https://app.fabric.microsoft.com/home?experience=fabric) et créez un nouvel espace de travail avec une licence incluant la capacité Fabric (Trial, Premium ou Fabric).

Depuis l'espace de travail, créez un nouveau **Lakehouse** via **Créer > Data Engineering > Lakehouse**. Donnez-lui un nom unique.

### Étape 2 : Créer un Dataflow Gen2

Depuis la page d'accueil du Lakehouse, sélectionnez **Obtenir des données > Nouveau flux de données Gen2**. L'éditeur Power Query Online s'ouvre.

Sélectionnez **Importer depuis un fichier Texte/CSV** et configurez la connexion :

- **Lien vers le fichier** : Sélectionné
- **URL** : `https://raw.githubusercontent.com/MicrosoftLearning/dp-data/main/orders.csv`
- **Connexion** : Créer une nouvelle connexion
- **Passerelle de données** : (aucune)
- **Type d'authentification** : Anonyme

Après avoir cliqué sur **Suivant** pour prévisualiser les données, puis **Créer**, l'éditeur affiche les données avec les étapes appliquées automatiquement (Source, Promoted Headers, Changed Type).

### Étape 3 : Ajouter une colonne calculée

Dans l'onglet **Ajouter une colonne**, sélectionnez **Colonne personnalisée** et configurez :

- **Nom de la nouvelle colonne** : `MonthNo`
- **Type de données** : Nombre entier
- **Formule** : `Date.Month([OrderDate])`

Cliquez **OK**. La nouvelle colonne apparaît dans l'aperçu des données, et l'étape "Added Custom" est ajoutée dans la liste des étapes appliquées.

Vérifiez que :
- La colonne `OrderDate` est de type **Date**
- La colonne `MonthNo` est de type **Nombre entier**

### Étape 4 : Configurer la destination Lakehouse

Dans l'onglet **Accueil**, sélectionnez **Ajouter une destination de données > Lakehouse**.

Dans la boîte de dialogue, connectez-vous avec votre compte Power BI organisationnel, puis sélectionnez votre espace de travail et votre Lakehouse. Nommez la table cible **orders**.

Choisissez le mode **Ajouter (Append)** et désactivez les "Paramètres automatiques" pour avoir le contrôle complet.

Sauvegardez et exécutez le dataflow via **Enregistrer et exécuter**. Attendez que l'actualisation se termine.

### Étape 5 : Vérifier les données dans le Lakehouse

Retournez à votre Lakehouse. Dans le panneau Explorateur, actualisez **Tables** — la table **orders** devrait apparaître avec les données chargées par le dataflow, incluant la colonne `MonthNo`.

### Étape 6 : Intégrer dans un pipeline

Depuis l'espace de travail, créez un nouveau **Pipeline de données** nommé **Load data**.

Ajoutez une activité **Dataflow** sur le canevas. Dans l'onglet **Paramètres** de l'activité, sélectionnez **Dataflow 1** dans la liste déroulante.

Sauvegardez et exécutez le pipeline. Après complétion, vérifiez que les données ont bien été rechargées dans la table `orders` du Lakehouse.

### Question 1

Quelle fonctionnalité de Dataflow Gen2 n'est PAS disponible dans Dataflow Gen1 ?

A) Créer des dataflows avec Power Query  
B) Connecter via le connecteur de flux de données  
C) Destinations de sortie multiples  
D) Actualiser uniquement les données modifiées  

**Réponse correcte : C** — Dataflow Gen2 introduit la prise en charge de destinations multiples (Lakehouse, Warehouse, Azure SQL, etc.), contrairement à Gen1 qui stocke les données dans son propre espace interne.

---

### Question 2

Dans l'éditeur Power Query, où sont enregistrées les transformations appliquées ?

A) Dans un fichier JSON séparé  
B) Dans la liste "Étapes appliquées" du panneau des paramètres de requête  
C) Uniquement dans le code M visible dans la barre de formule  
D) Dans les métadonnées de la destination de données  

**Réponse correcte : B** — Chaque transformation est enregistrée comme une étape nommée dans la liste "Étapes appliquées", visible dans le panneau droit de l'éditeur Power Query.

---

### Question 3

Vous souhaitez charger des données transformées dans un Lakehouse tout en conservant l'historique des données précédentes. Quel mode de chargement choisissez-vous ?

A) Remplacer (Replace)  
B) Fusionner (Merge)  
C) Ajouter (Append)  
D) Supprimer et recréer  

**Réponse correcte : C** — Le mode "Ajouter (Append)" conserve les données existantes et ajoute les nouvelles données à la suite. "Remplacer" efface la table avant de la recharger.

---

### Question 4

Quelle est la formule M correcte pour extraire le mois d'une colonne de date `[OrderDate]` ?

A) `Month([OrderDate])`  
B) `Date.Month([OrderDate])`  
C) `MONTH([OrderDate])`  
D) `Extract.Month([OrderDate])`  

**Réponse correcte : B** — La syntaxe correcte en langage M (Power Query Formula Language) est `Date.Month([OrderDate])`. Les autres syntaxes correspondent à T-SQL ou à des fonctions inexistantes.

---

### Question 5

Pourquoi intégrer un flux de données Gen2 dans un pipeline Data Factory plutôt que de l'exécuter directement ?

A) Les pipelines sont obligatoires pour les dataflows Gen2  
B) Un dataflow seul ne peut pas se connecter à des fichiers CSV  
C) Les pipelines permettent d'orchestrer le dataflow avec d'autres activités et de définir des déclencheurs planifiés  
D) Les pipelines améliorent les performances des transformations Power Query  

**Réponse correcte : C** — Les pipelines permettent l'orchestration (ordre d'exécution, conditions), la combinaison avec d'autres activités (copie, notebooks, procédures stockées) et la planification automatique via des déclencheurs.

## Résumé
*2 min*

Dans ce module, vous avez exploré les **flux de données Gen2 (Dataflows Gen2)** de Microsoft Fabric, un outil puissant pour l'ingestion et la transformation de données sans écrire de code.

**Points clés à retenir :**

- Les dataflows Gen2 utilisent **Power Query Online** pour offrir une expérience visuelle de transformation de données, cohérente avec Power BI Desktop, Excel et d'autres produits Microsoft.

- Par rapport à Gen1, Dataflow Gen2 apporte : l'enregistrement automatique, les **destinations multiples** (Lakehouse, Warehouse, Azure SQL, etc.), la surveillance améliorée et l'intégration native avec les pipelines.

- L'éditeur Power Query enregistre chaque transformation comme une **étape appliquée**, ce qui rend les flux de données faciles à comprendre, déboguer et modifier.

- Les **colonnes personnalisées** permettent d'ajouter de la logique métier via des formules M, comme `Date.Month([OrderDate])` pour extraire le mois d'une date.

- Les dataflows peuvent être intégrés dans des **pipelines Data Factory** comme activités, permettant d'orchestrer l'ingestion de données dans des processus ETL plus complexes.

- Le **mode de chargement** (Append vs Replace) est crucial : Append conserve l'historique, Replace recharge complètement la table.
