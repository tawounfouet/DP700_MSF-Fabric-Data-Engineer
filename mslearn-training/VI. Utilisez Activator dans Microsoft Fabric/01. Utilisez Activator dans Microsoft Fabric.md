*Effectué — 100 XP — 4 minutes*

Dans le monde moderne des données, le problème n'est plus l'accès aux données — c'est la capacité à **agir sur ces données au bon moment**. Imaginez les scénarios suivants :

- Un capteur de température dans un entrepôt frigorifique dépasse le seuil critique à 3h du matin

Dans ce module, vous allez découvrir comment configurer Activator pour surveiller des flux de données, définir des règles de détection, et orchestrer des actions automatisées comme l'envoi d'emails, de notifications Teams, ou le déclenchement de workflows Power Automate.

## Qu'est-ce qu'Activator ?

*Effectué — 100 XP — 7 minutes*

Activator est le composant d'**intelligence automatisée** de Microsoft Fabric. Il fait partie du workload **Real-Time Intelligence** et complète le pipeline temps réel de Fabric :

```
Sources de données → Eventstream → Eventhouse (KQL) → Real-Time Dashboard
                                                    ↓
                                               ACTIVATOR
                                                    ↓
                              Email / Teams / Power Automate / Azure Functions
```

### Architecture d'Activator

Un projet Activator est composé de plusieurs éléments fondamentaux :

#### 1. Sources de données

Activator peut se connecter à plusieurs types de sources :

| Source | Description | Cas d'usage |
|--------|-------------|-------------|
| **Eventstream** | Flux d'événements Fabric | IoT, logs applicatifs, clickstream |
| **KQL Database** | Données de l'Eventhouse | Métriques agrégées, séries temporelles |
| **Real-Time Hub** | Sources de streaming tierces | Event Hubs, IoT Hub, Kafka |
| **Power BI** | Rapports et datasets | KPIs métier, alertes sur mesures |

#### 2. Objets (Objects)

Un **objet** représente une entité métier que vous surveillez — par exemple, un `Paquet`, un `Capteur`, un `Compte bancaire`, ou un `Équipement`. Chaque objet est associé à :
- Un **identifiant unique** (l'ID du paquet, l'ID du capteur...)
- Un ensemble de **propriétés** (température, statut, montant...)

Les objets permettent à Activator de suivre l'état de chaque entité individuellement. Ainsi, si votre règle détecte une température anormale, Activator sait exactement **quel capteur** est concerné.

#### 3. Propriétés (Properties)

Les **propriétés** sont les valeurs que vous surveillez sur vos objets. Elles correspondent à des colonnes dans votre flux de données :

- `Température` → valeur numérique du capteur thermique
- `Statut` → état du paquet ("En livraison", "Livré", "Retardé")
- `Montant` → valeur de la transaction

Chaque propriété peut être configurée pour capturer :
- La valeur brute de chaque événement
- La valeur agrégée (moyenne, max, min sur une fenêtre temporelle)
- Le changement de valeur par rapport à l'événement précédent

#### 4. Règles (Rules)

Les **règles** définissent les conditions qui déclenchent une action. Une règle comprend :

- **Propriété surveillée** : quelle valeur observer
- **Condition** : le seuil ou pattern à détecter
- **Fréquence** : à quelle fréquence évaluer (chaque événement, chaque fois que la condition est vraie...)
- **Filtres** : restreindre l'application de la règle à un sous-ensemble de données
- **Action** : que faire quand la condition est satisfaite

#### 5. Actions (Actions)

Lorsqu'une règle est déclenchée, Activator peut exécuter les actions suivantes :

| Action | Description |
|--------|-------------|
| **Email** | Envoyer un email avec des informations contextuelles |
| **Teams** | Poster un message dans un canal Teams |
| **Power Automate** | Déclencher un workflow d'automatisation |
| **Webhook** | Appeler une URL HTTP externe |
| **Azure Functions** | Exécuter une fonction serverless |

### Positionnement dans l'écosystème Fabric

Activator n'est pas un outil de remplacement pour des alertes simples — c'est un moteur d'intelligence automatisée qui :

- Comprend le **contexte** de chaque événement (quel objet, quelle propriété, quel état précédent)
- Évite les **alertes en doublons** (une règle ne se déclenche qu'une fois par occurrence, pas en boucle)
- Supporte des **conditions complexes** avec filtres combinés (ET/OU)
- Permet un **suivi d'état** entre événements (détecter un passage au-dessus d'un seuil, pas juste une valeur ponctuelle)

## Configurer Activator pour vos données

*Effectué — 100 XP — 7 minutes*

### Créer un Activator

Pour créer un projet Activator dans Fabric :

1. Naviguez vers [Microsoft Fabric](https://app.fabric.microsoft.com)
2. Dans la barre de navigation gauche, sélectionnez **Créer**
3. Dans la section **Real-Time Intelligence**, sélectionnez **Activator**
4. Donnez un nom descriptif à votre Activator (ex: `Surveillance_Temperature_Entrepôt`)

> **Conseil** : Nommez votre Activator en fonction du domaine métier surveillé, pas de la technologie. Cela facilite la maintenance à long terme.

### Connecter une source de données

Une fois l'Activator créé, vous devez lui connecter une source de données. La méthode la plus courante est via un **Eventstream**.

**Depuis un Eventstream existant :**

1. Dans votre Eventstream, ajoutez une destination de type **Activator**
2. Configurez le mappage des colonnes vers les propriétés de l'objet
3. Définissez la colonne qui servira d'identifiant unique de l'objet

**En utilisant les données d'exemple :**

Pour l'exploration, Activator propose un jeu de données d'exemple intégré — **Package delivery events** — qui simule un système de livraison de colis avec des données de température, de localisation et de statut.

1. Sur l'écran d'accueil de l'Activator, sélectionnez **Try sample**
2. Un eventstream d'exemple est automatiquement créé avec des données aléatoires

### Définir un objet

Après avoir connecté la source, créez un objet :

1. Dans l'**Explorer pane**, sélectionnez votre eventstream
2. Cliquez sur **New object** dans le ruban
3. Dans le panneau **Build object**, configurez :

```
Nom de l'objet : Redmond_Packages
Identifiant unique : PackageId
Propriétés à inclure :
  ✓ City
  ✓ ColdChainType  
  ✓ SpecialCare
  ✓ Temperature
```

4. Cliquez sur **Create**

> **Bonne pratique** : Choisissez un identifiant unique qui reste **stable dans le temps** pour un objet donné. Pour un colis, c'est le `PackageId`. Pour un équipement, c'est le numéro de série.

### Comprendre le schéma de données

Après avoir créé un objet, Activator analyse automatiquement les propriétés de l'eventstream et vous permet de voir :

- **Event details** : table en live avec tous les événements entrants
- **Properties** : valeurs actuelles pour chaque propriété de chaque objet
- **Rules** : règles définies pour cet objet

![Écran détail événements Activator](https://learn.microsoft.com/fr-fr/fabric/real-time-intelligence/media/data-activator-introduction/activator-event-details.png)

## Créer des règles dans Activator

*Effectué — 100 XP — 6 minutes*

### Anatomie d'une règle

Une règle dans Activator suit cette structure logique :

```
SI [Propriété] [Condition] [Valeur]
ET [Filtre 1] ET [Filtre 2]
ALORS [Action]
RÉPÉTER [Fréquence]
```

### Types de conditions disponibles

| Condition | Description | Exemple |
|-----------|-------------|---------|
| **Is greater than** | Dépasse un seuil | Température > 41°C |
| **Is less than** | Passe sous un seuil | Stock < 10 unités |
| **Increases above** | Monte au-dessus (transition) | Charge CPU passe au-dessus de 90% |
| **Decreases below** | Descend en dessous (transition) | Score de crédit passe sous 500 |
| **Is equal to** | Valeur exacte | Statut = "Échoué" |
| **Changes to** | Changement de valeur | Statut change vers "Livré" |
| **Is in range** | Dans un intervalle | Température entre 2°C et 8°C |
| **Is outside range** | Hors d'un intervalle | pH hors de [6.5, 7.5] |

> **La différence entre "Is greater than" et "Increases above"** est cruciale : "Is greater than" se déclenche à **chaque événement** où la valeur est supérieure au seuil, tandis que "Increases above" se déclenche **une seule fois** au moment du passage du seuil. Utilisez "Increases above" pour éviter les alertes répétitives.

### Fréquence de déclenchement

Choisissez quand la règle se déclenche :

- **Every time the condition is met** : à chaque événement satisfaisant la condition (utile pour les logs)
- **When the condition changes** : uniquement lors des transitions (évite les doublons)
- **Once** : une seule fois, même si la condition persiste
- **After a delay** : si la condition persiste pendant X minutes/heures

### Créer une règle en pratique

Voici comment créer une règle de surveillance de température :

1. Dans l'Explorer pane, sélectionnez la propriété **Temperature** de l'objet `Redmond_Packages`
2. Cliquez sur **New Rule** dans le ruban
3. Configurez la règle :

**Section Monitor :**
```
Propriété : Temperature
```

**Section Condition :**
```
Condition : Increases above
Valeur : 20
Occurrence : Every time the condition is met
```

**Section Property filter :**
```
Filtre 1 : City = "Redmond"
Filtre 2 : SpecialCare = "Medicine"
Filtre 3 : ColdChainType = "Refrigerated"
```

4. Renommez la règle en `Medicine_temp_out_of_range`

![Configuration d'une règle Activator avec filtres](https://learn.microsoft.com/fr-fr/fabric/real-time-intelligence/media/data-activator-introduction/activator-rule-filters.png)

### Utiliser des filtres combinés

Les filtres permettent de cibler précisément quels objets sont concernés par la règle. Sans filtres, **tous les objets** de ce type seraient surveillés.

Dans l'exemple ci-dessus, les 3 filtres combinés signifient :
> "Déclenche l'alerte UNIQUEMENT si le colis va à Redmond ET contient de la médecine ET est dans une chaîne du froid réfrigérée."

Cette précision évite les fausses alertes pour des colis qui peuvent légitimement avoir des températures différentes (colis standards non réfrigérés).

## Configurer des actions dans Activator

*Effectué — 100 XP — 3 minutes*

### Types d'actions

#### Email

L'action la plus simple et la plus directe :

```
Type : Email
Destinataire : shipping@contoso.com (ou votre email)
Objet : Redmond Medical Package - Température hors plage
Titre : Température trop élevée
Contexte : ☑ Temperature (inclure la valeur actuelle)
           ☑ PackageId
           ☑ City
```

Activator enrichit automatiquement l'email avec :
- L'heure exacte du déclenchement
- Les valeurs des propriétés sélectionnées dans "Contexte"
- Un lien vers l'Activator pour investigation

#### Teams

Idéal pour les équipes qui collaborent dans Microsoft Teams :

```
Type : Teams
Canal : Equipe_Logistique / Alertes_Critiques
Message : "⚠️ ALERTE TEMPÉRATURE — Colis {PackageId} à {Temperature}°C"
```

#### Power Automate

Pour des actions complexes (créer un ticket de support, mettre à jour une base de données, envoyer des notifications multi-canal) :

```
Type : Power Automate
Flow : Alerte_Temperature_Handler (déclenché par HTTP)
Paramètres : {PackageId, Temperature, Timestamp, City}
```

#### Webhook / HTTP

Pour intégrer avec n'importe quel système externe :

```
Type : Webhook
URL : https://api.contoso.com/alerts/temperature
Method : POST
Body : {"packageId": "{PackageId}", "temp": {Temperature}, "time": "{EventTime}"}
```

### Configurer le message d'action

Pour l'email et Teams, vous pouvez utiliser des **propriétés dynamiques** dans le message :

| Placeholder | Description |
|-------------|-------------|
| `{Temperature}` | Valeur actuelle de la propriété Temperature |
| `{PackageId}` | ID de l'objet concerné |
| `{EventTime}` | Horodatage de l'événement |
| `{RuleName}` | Nom de la règle déclenchée |

### Tester une action avant activation

Avant de démarrer une règle, testez-la avec **Send me a test action** :

1. Dans la section **Action**, configurez vos paramètres
2. Cliquez sur **Send me a test action**
3. Vérifiez que vous recevez l'email/Teams avec le bon contenu
4. Ajustez le message si nécessaire
5. Cliquez sur **Save and start** pour activer la règle

> **Important** : Une fois activée, la règle commence à surveiller les données en temps réel. Si la condition est déjà vraie pour certains objets, l'action sera déclenchée immédiatement.

## Exercice — Utiliser Activator dans Fabric

*30 minutes*

Dans cet exercice pratique, vous allez :
1. Créer un espace de travail Fabric
2. Créer un Activator avec les données d'exemple
3. Explorer l'eventstream **Package delivery events**
4. Créer un objet `Redmond Packages`
5. Définir une règle de température avec filtres multi-conditions
6. Configurer une action email
7. Tester et valider la règle

**Accéder au lab :** [Lab — Utiliser Activator dans Fabric](https://microsoftlearning.github.io/mslearn-fabric/Instructions/Labs/11-data-activator.html)

### Scénario du lab

Vous êtes analyste de données pour une entreprise de livraison. Vous gérez les données de livraisons à destination de **Redmond**. Parmi les produits expédiés, des **médicaments réfrigérés** doivent rester entre 33°F et 41°F pendant le transport.

Vous devez créer une alerte qui notifie le service logistique dès que la température d'un colis de médicaments sort de cette plage.

### Étapes principales

```
1. Workspace → Nouveau Activator
2. Try sample → Charger les données d'exemple
3. Package delivery events → Explorer les données
4. New object → Redmond Packages (ID: PackageId)
5. Temperature property → New Rule
6. Condition: Increases above 20°C
7. Filters: City=Redmond AND SpecialCare=Medicine AND ColdChainType=Refrigerated
8. Action: Email → Sujet: "Redmond Medical Package outside acceptable temperature"
9. Save and start → Valider le déclenchement
```

## Résumé

*1 minute*

Dans ce module, vous avez découvert **Activator**, le composant de détection et d'action automatisée de Microsoft Fabric.

Vous avez appris à :
- **Comprendre l'architecture** d'Activator : sources → objets → propriétés → règles → actions
- **Créer des objets** pour représenter des entités métier (colis, capteurs, comptes)
- **Définir des propriétés** pour suivre les valeurs importantes sur chaque objet
- **Configurer des règles** avec des conditions précises et des filtres multi-critères
- **Orchestrer des actions** automatisées (email, Teams, Power Automate) lors du déclenchement

Activator complète le pipeline Real-Time Intelligence de Microsoft Fabric en ajoutant la couche d'**intelligence automatisée** : vos données ne sont plus seulement visibles — elles agissent.

### Cas d'usage métier typiques

| Secteur | Scénario | Règle Activator |
|---------|----------|-----------------|
| **Logistique** | Colis en mauvais état thermique | Température hors plage → Email logistique |
| **Finance** | Transaction frauduleuse | Montant > seuil ET pays inhabituel → Bloquer + alerte |
| **Industrie** | Équipement proche de la panne | Vibration > seuil 3 fois/heure → Ticket maintenance |
| **E-commerce** | Stock épuisé imminente | Niveau stock < 10 → Déclenchement réapprovisionnement |
| **Santé** | Patient hors paramètres normaux | Fréquence cardiaque < 40 → Alerte soignant |
